# code-explorer

## `FileTree` takes a `storageKey`

`FileTree` renders on two surfaces — the Explorer pane (a whole worktree) and
`plugin-meta/plugin-view/file-tree` (one plugin's subtree) — so it takes an
optional `storageKey: DataViewId` (default `FILE_TREE_VIEW`) and the second
surface passes its own. One id means one config file, one filter, and one expand
map; two surfaces sharing it would share that map over overlapping paths, so a
folder collapsed in a plugin's Files section would come back collapsed in the
Explorer.

Folder rows toggle on a body click via the tree view's `expandOnActivate`
(`(r) => r.isDir`); file rows navigate. The selected file's ancestors open by
themselves through the tree primitive's reveal-on-select — the tree carries no
ancestor-union of its own. Expand state is device-local and shared across
worktrees, which is deliberate: repo paths coincide.
