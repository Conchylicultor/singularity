# hooktheory

The Hooktheory (TheoryTab / Hookpad) account, as an auth provider of kind
`password`. The user signs in once from Settings → Accounts with their
Hooktheory username and password. Central posts them to
`https://api.hooktheory.com/v1/users/auth` and gets back `{ username, activkey }`.
It stores only the `activkey`, a long-lived bearer token, and drops the password.
Every later call reads the token with `getTokenFromCentral({ providerId: "hooktheory" })`
and sends it as `Authorization: Bearer <activkey>`.

- A wrong username or password shows Hooktheory's own message in the sign-in
  dialog (for example "There are no accounts with this username.").
- Nothing marks the token stale. If Hooktheory revokes it, the account still
  reads Connected until a call fails; the user then signs in again.
- The Hooktheory API calls themselves (trends, TheoryTab sections) live in
  `integrations/hooktheory`, so a consumer never imports `@plugins/auth`.
