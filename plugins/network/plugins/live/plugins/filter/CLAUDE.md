# filter

The ONE filter language shared by live collections and DataView — design in
`research/2026-09-25-global-unified-filter-language.md`. A leaf: it imports
nothing from `fields`, `primitives/data-view` or `network/live`, and `core/` does
not import drizzle (browser-safe).

## Usage

```ts
// core/ — declare the filterable columns by DOMAIN, never by field type
const filterable = {
  status: liveText(StatusSchema),   // narrows `value` / `list` operands in tsc only
  count: liveNumber(),
  pinned: liveBoolean(),
  createdAt: liveInstant(),         // rows: Date or ISO-Z; operands: ISO-Z (ms)
  labels: liveStringArray(),        // a jsonb string array
};

const f: Filter<typeof filterable> = or(
  clause("status", "in", ["open", "held"]),
  and(clause("createdAt", "gte", "2026-09-01T00:00:00.000Z"), clause("labels", "hasAny", ["urgent"])),
);

encodeFilter(f, filterable);           // canonical JSON, or undefined for the absent filter
decodeFilter(json, filterable);        // STRICT: throws FilterError unless exactly canonical
canonicalizeFilter(f, filterable);     // validate + canonical tree, any spelling
matchesFilter(row, f, filterable);     // in memory; no clock; throws on a missing field

// server/
filterSql(f, { status: sql`${t.status}`, … }, filterable);  // SQL | undefined
renderOpSql("contains", "text", sql`${t.title}`, "abc");    // one op
```

## The language

- **Domains** (closed set, `core/internal/domains.ts`): `text`, `number`,
  `boolean`, `instant`, `stringArray`. Each owns the row-value normalizer (strict:
  a value of the wrong type throws), emptiness (text: NULL or ASCII-whitespace
  only; stringArray: NULL, not an array, or `[]`; the rest: NULL), the operand's
  wire schema over the DOMAIN (never the column's value schema — a stale enum
  option decodes and matches nothing), its canonical spelling, and the SQL type
  operands bind as.
- **Ops** (`core/internal/ops.ts`): ONE table; each entry holds its `domains`,
  operand kind (`value` / `pattern` / `list` / `none`), in-memory `test`, and a
  dialect-free SQL template (`tpl` with holes `T` target, `P` operand, `L` list,
  `orEach(…X…)` per element) — one template, or one per domain where the SQL
  differs. Which ops a domain takes is derived from the table (`OpsFor<D>`).
- **Negatives are complements, only.** `ne notIn neCi notContains hasNone
  isNotEmpty` are built by `complementOf(<positive>)`: `test = !pos.test`, SQL
  `(<pos>) IS NOT TRUE`. So a negative returns exactly the rows its positive does
  not — NULL included — by construction. Range ops are positive and fail on NULL.
- **The cluster decides string semantics**: it is `C`-collated, so ordering is
  code-point order, and `lower()` / `ILIKE` fold ASCII only — as `eqCi` /
  `contains` do in memory (`asciiLower`). Emptiness spells the C locale's
  `[[:space:]]` set out literally on both sides.
- **Instants are ms-precise.** The driver truncates a µs `timestamptz` to ms, so
  memory compares floor_ms(value) with an ms operand; the SQL states the same
  comparison sargably (`lte` → `T < P + 1ms`, `gt` → `T >= P + 1ms`).
- **Operands bind cast to the domain's type** (`$1::float8`, `$1::text[]` …): a
  `number` op over an `integer` column compares exactly (at the cost of a btree
  index on that column), and a `text` op over a `uuid` column fails loudly until
  its target is rendered `col::text`.
- **Expression** (`core/internal/expr.ts`, `codec.ts`): `Filter = clause |
  { and } | { or }`, no `not` node. Canonical form: same-kind groups flattened,
  singletons unwrapped, children sorted + deduped by canonical JSON, list operands
  sorted + deduped, instants as `toISOString()`. `and: []` is the absent filter
  (`undefined`) and `or: []` matches nothing (encoded `{"or":[]}`). Bounds on the
  canonical tree: depth ≤ 4, clauses ≤ 50, lists ≤ 100 (`LIST_MAX`).

## Tests

- `core/internal/codec.test.ts` / `matches.test.ts` — canonicalization, strict
  decode, bounds, the type-level contract, in-memory semantics.
- `server/internal/parity.test.ts` — every op × every domain against a real
  Postgres (rows read through the raw `pg` client, as a typed read hands them
  over), complement pairs disjoint + covering, and 400 seeded random and/or
  trees. A divergence is fixed in the op's entry, never in the test.
