# chip

`<ConversationChip conv={…}/>` — a conversation, as a clickable chip that opens
its run beside the surface naming it.

The sibling `item` plugin states its contract as "pure presentation — no click
handler, no router awareness, no chrome; surfaces wrap their own button/link
around it". **This plugin is that wrapper for the chip case, written once**, so
that two surfaces showing the same thing cannot end up showing it two ways.

What it wraps `ConversationItem` in:

- a ghost `ToggleChip`, whose `active` is whether this conversation is the one
  currently open — read off `conversationPane.useRouteEntries().at(-1)`. Pages
  mount Miller columns, so a conversation pane anywhere in the chain is by
  definition one opened from a page; the last (rightmost) one is the open run.
- a click that pushes the conversation column
  (`openPane(conversationPane, { convId }, { mode: "push" })`).
- a `title` of `"Starting…"` while the conversation has no title yet — a
  conversation exists before its title is generated, and a momentarily blank
  chip is worse than a word.

`conv` is structural, the same type `ConversationItem` accepts
(`ConversationItemConv`): a full `Conversation` row and the narrower
`ConversationSummary` carried by `attemptsResource` both fit.

## Who hand-rolls this, and who deliberately still does

Six places in the repo built "a `ConversationItem` inside something clickable
that calls `openPane(conversationPane, …)`" by hand. Only one of them was this
*chip* — the `/prompt` block's launched-run chips — and it now imports this
plugin instead; the TODO card's foot, which needed the same pill, was what made
a seventh copy worth replacing with a shared one.

The remaining five are left alone on purpose, because they are not the same
widget:

- `tasks/task-events`, `active-data/task`'s task card,
  `page/annotations/agent-notes/authorship` and
  `page/annotations/todo/task-link`'s dispatch panel are all `Row`s — a full-width
  list line with its own trailing content, not a pill.
- `active-data/conv`'s inline `conv-<id>` token is a `LinkChip` in running prose,
  and carries an unknown-id fallback (a bare mono id with a gone dot) that a chip
  built from a conversation it already has cannot express.

Turning a `Row` into a chip would change what those surfaces look like, which is
a separate decision from removing a duplicate.
