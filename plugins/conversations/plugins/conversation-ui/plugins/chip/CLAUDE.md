# chip

`<ConversationChip conv={…}/>` — a conversation, as a clickable chip that opens
its run beside the surface naming it.

The sibling `item` plugin states its contract as "pure presentation — no click
handler, no router awareness, no chrome; surfaces wrap their own button/link
around it". **This plugin is that wrapper for the chip case, written once**, so
that two surfaces showing the same thing cannot end up showing it two ways. The
sibling `row` plugin is the same wrapper for the full-width row case.

What it wraps `ConversationItem` in:

- a ghost `ToggleChip`, whose `active` is whether this conversation is the column
  **this surface** opened — `useConversationOpener()`, which reads
  `conversationPane.useOpenedHere()`.
- a click that opens that column, and closes it again when it is already open.
- a `title` of `"Starting…"` while the conversation has no title yet
  (`conversationTitle`, the same word `item` paints as the visible label) — a
  conversation exists before its title is generated, and a momentarily blank chip
  is worse than a word.

`conv` is structural, the same type `ConversationItem` accepts
(`ConversationItemConv`): a full `Conversation` row and the narrower
`ConversationSummary` carried by `attemptsResource` both fit.

## Chip or row?

Six places in the repo built "a `ConversationItem` inside something clickable
that opens its run". They are now two widgets and one navigation:

- the **chip** — this plugin — for a pill in a cluster: the `/prompt` block's
  launched runs, the TODO card's foot.
- the **row** — `../row` — for a full-width list line: task detail's attempts,
  the launched-attempts card in a transcript, an agent-note card's authors, a
  TODO card's latest run.
- `active-data/conv`'s inline `conv-<id>` token stays a `LinkChip` in running
  prose. It carries an unknown-id fallback (a bare mono id with a gone dot) that
  a chip built from a conversation it already has cannot express, so only its
  navigation is shared — `useConversationOpener()`, like everything else here.

Picking between them is a look decision, and it belongs at the call site. What
must not vary — the pane mode, which conversation counts as "the open one", and
what an untitled conversation is called — is below both.
