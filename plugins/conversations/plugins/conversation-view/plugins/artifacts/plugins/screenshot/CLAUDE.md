# screenshot

The pictures a conversation looked at, as a thumbnail grid in the Artifacts
popover.

A `Read` on an image path counts, and counts as `created`: agents read a picture
after making it (a screenshot of the app they just changed, a compare sheet).
The key is the path exactly as the tool got it — screenshots usually land in a
temp directory, outside any worktree, and the image endpoint serves an absolute
path fine.

## Why the popover stays open over the viewer

`ViewerThumbnail` renders the full-window viewer inside THIS section's React
tree on purpose, so the popover around it reads the viewer's clicks as its own
instead of as an outside press. Dismissing the popover would therefore unmount
the viewer the click just opened — so this section does not call
`useCloseArtifacts()`, unlike a kind that navigates to a pane.

## The image-extension set is duplicated

`IMAGE_EXTS` here is a third copy of the set the image endpoint serves (the
others: `EXT_TO_MIME` in `code-explorer/server/internal/image-handler.ts`, and
`IMAGE_EXTS` inside the Read tool row's component). It belongs beside
`codeImageUrl` in `code-explorer/plugins/code-api/core`, which already owns the
address of a worktree image; nothing here can reach the other two.
