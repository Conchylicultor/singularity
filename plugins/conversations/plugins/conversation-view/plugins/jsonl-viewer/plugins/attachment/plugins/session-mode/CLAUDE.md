# session-mode

Four attachments (`auto_mode`, `plan_mode`, `plan_mode_exit`,
`ultra_effort_enter`) that say the same kind of thing: **from here on the agent
is working under a different set of rules.** They are one fact family, so they
are one plugin and one component — the reading differs only in label, icon, and
which value is worth naming. Splitting them would let two announcements of "the
contract changed" drift into two different-looking rows.

All four are `EventLine`s, not cards. Nothing here has content to inspect: auto
mode is a handful of switches, plan mode is a path, ultracode is a stance. A
card whose body only restated its own label is noise in a timeline the reader is
scrolling past, and the full payload is one click away in the row's raw-JSON
action either way.

What each row leaves the reader with:

- **Auto mode** — which switches are on, in words (`bash first · steer only ·
  bypass permissions`). Auto mode injects no prose of its own, so the switches
  *are* the fact. They are read off the payload's own keys rather than a
  hardcoded list, so a switch the harness adds upstream shows up here without
  this plugin changing; a non-boolean setting (`bashFirstSteer: "strict"`) is a
  value a reader needs, so it renders as `bash first steer: strict`. When every
  switch is off the row says so rather than trailing off blank.
- **Plan mode** / **Plan mode exited** — the plan file as a clickable `FilePath`
  (the one thing a reader can act on), plus `no plan written yet` when the file
  does not exist and `subagent` when the announcement is aimed at a sub-agent.
- **Ultracode on** — a short gloss (`exhaustive over fast`) standing in for the
  paragraph the harness injects. The paragraph itself is boilerplate; what a
  reader needs is that the stance changed.
