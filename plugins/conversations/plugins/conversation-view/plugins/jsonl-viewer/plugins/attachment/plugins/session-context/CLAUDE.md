# session-context

The harness's opening briefing — the `<system-reminder>` carrying a `# key`
block per ambient fact (who the user is, what the repo looked like at launch).

**A card, collapsed.** The blocks are long (a git status runs to a dozen lines)
and a reader scrolling the transcript wants what the agent _did_, not the
standing context it was handed. The collapsed row states the block count; the
body waits behind the chevron, capped at `max-h-64`.

**Headings are derived, never listed.** `context` is an open string→string map
the harness owns and adds to. The heading is computed from the key (`gitStatus`
→ `Git status`), so a block introduced tomorrow renders readably instead of
falling out of a hardcoded table.
