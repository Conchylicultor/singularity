# tool-output-notice

`read_truncation_notice` and `bash_output_audience_note` are the harness talking
*about* a tool result, not announcing an event of their own. Both name the call
they annotate with a `toolUseID`. That id is never rendered — it is opaque, a
reader cannot follow it anywhere, and printing it would put a 30-character
token on a row whose whole job is to be glanceable. The row states the meaning
instead.

Both are `EventLine`s. Neither has anything to expand.

- **Read truncated** — the banner the harness wrote, with its wrapping
  `[Truncated: …]` brackets removed: the label already says the read was
  truncated, so the brackets repeat it in punctuation. What is inside is left
  exactly as written. The line and token counts and the suggested follow-up call
  are the harness's phrasing to change, and re-parsing numbers out of that string
  here would break the day it is reworded.
- **Output not shown to the user** — this attachment carries no text of its own;
  the fact *is* the attachment's existence. So the row states it in the label and
  glosses it once (`only the agent saw that command's output`), rather than
  rendering an empty line the reader has to open raw JSON to understand.
