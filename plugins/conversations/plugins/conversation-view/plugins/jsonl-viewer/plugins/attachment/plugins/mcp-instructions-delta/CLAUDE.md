# mcp-instructions-delta

`mcp_instructions_delta` says that an MCP server's standing instructions — the
prose the server injects into the agent's context, telling it how to use itself
— were added or removed mid-session.

This is the sibling of the deferred-tools delta one layer up: that row says
which of a server's *tools* appeared, this one says which server's *instructions*
did. So it deliberately borrows that plugin's grammar wholesale — the same
`(+n −n)` note, the same `+ name` in success green over `− name` struck through
in destructive red, the same monospace list. Two rows about the same kind of
mid-session context change should look like each other; inventing a second
visual language for it would make a reader work out twice that nothing
important happened.

The added instruction blocks are their own section under the names, not paired
with them. `addedBlocks` lines up positionally with `addedNames` in the samples
we have, but nothing in the payload promises it does, and a block shown under
the wrong server's name would be a quiet lie — worse than a block shown on its
own. They are capped in a `max-h-64` scroller because a server's instructions
run to hundreds of lines.
