# environment

Where the agent is running — working directory, worktree/repo flags, platform,
shell, scratchpad.

**One component, two readings.** The payload is the same `snapshot` either way;
what differs is whether the harness also sent `changes`. Without it the row is
routine chrome (`Environment`, working directory on the collapsed line). With
it, the agent MOVED — that is the fact a reader wants — so the label names what
changed and the body leads with the from → to lines before the rest of the
snapshot. Splitting this into two renderers would let the two readings of one
payload drift.

**The snapshot renders over its own keys.** A hand-written field list would drop
a new harness field silently; iterating the keys shows it instead. Labels are
derived (`osVersion` → `OS version`), booleans read `yes`/`no`, and an empty
list reads `none` rather than blank — a blank cell would look like a field that
failed to arrive.
