# directory-listing

The harness handing the agent the contents of a directory — the attachment
behind a `Read` on a folder.

The collapsed line is the whole point of this row:

```
Directory   plugins/primitives/plugins/announce/web   · 4 entries
```

The directory says which listing this is; the count says whether the names are
worth reading. Nothing else fits on one line, and the names themselves are bulk
content, so they go in the body — a plain monospace column, one entry per line,
capped at `max-h-64` so a large folder cannot push the rest of the transcript
off the screen.

The path is rendered through `FilePath`, which shortens an absolute path to its
worktree-relative form (`/Users/…/worktrees/att-x/plugins/…` → `plugins/…`) and
carries its own copy button. **Caveat:** clicking it opens the file-peek pane,
which has no directory view — the pane will report an error rather than list the
folder. The shortening and the copy affordance are worth the broken click for
now; a directory-aware peek target would be the real fix.

An empty listing is a real answer, not a missing one: the card says `· empty`
and the body says so in words. A payload carrying no `content` at all is a
different thing — the row exists to show entries — so that throws onto its own
row rather than rendering an empty card.
