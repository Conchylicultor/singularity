# team-context

`team_context` is the harness telling the agent it is a teammate rather than the
session lead. Two things in it matter to someone reading the transcript: **who
this session is** (`plan-render`) and **which team it belongs to**
(`session-29d6d8de`). That pair reframes every message after it — messages
arriving from a lead, work scoped to one member — so the agent's own name is the
row's one emphasized value, and the team follows muted.

An `EventLine`, not a card. There is exactly one sentence here and nothing to
inspect: the config path, the task-list directory, the composite `agentId` and
`hasTaskListTools` are plumbing the agent needs and a reader does not. They stay
one click away in the row's raw-JSON action rather than filling a card body that
would otherwise only restate the label.

The row throws when `agentName` is absent — the row exists to name the teammate,
and a `Team` line naming nobody would be worse than the loud failure the
renderer's own error boundary shows in its place.
