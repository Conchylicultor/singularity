# outline

The transcript's outline, pinned to the right edge of the conversation: one dash
per user turn, the one you are reading highlighted; hover opens the list of
turns, click jumps, and the chevron at its foot scrolls to the bottom.

None of that chrome lives here — the dashes, the panel, the current-entry
tracking and the scroll-to-on-click belong to `OutlineRail`
(`@plugins/primitives/plugins/outline/plugins/rail/web`). This plugin is the
adapter, and answers only **which turns exist** and **how a turn maps to its
row**. It is a `JsonlViewer.Overlay` contribution, so it sits beside the
transcript scroller in the pane frame and never scrolls with it.

## Three things here that look incidental and are not

**The entries come from `useVisibleEvents(events)`, never the raw resource.** A
`JsonlViewer.EventFilter` contributor can hide a `user-text` event —
`ask-user-question` does exactly that — and an outline built from the unfiltered
array then lists a turn the transcript never rendered. Every surface that
enumerates the transcript has to agree with the transcript about which events
exist.

**An entry's id is `eventKey(ev)`, the event's content identity — never its
position.** The id used to be an index, counted over the unfiltered array while
the DOM stamped its positional attribute over the filtered one, so every entry
pointed at the wrong row in any conversation where a filter had hidden something
earlier. `eventKey` is stamped on the row itself as `data-event-key`, so an entry
and its row cannot drift apart. `e2e/toc-lands-on-right-message.ts` is the guard
against that regression coming back.

**`resolve` looks inside this pane's own scroller, via `usePaneScrollElement()`
— never `document`.** Two panes can be open on the same conversation, and a row's
key (`user-text:<timestamp>`) carries no conversation id, so the other pane's rows
answer to the identical selector; the pane publishes the element it already holds,
so nothing walks the DOM to rediscover it. The same element is the footer
chevron's `scrollToBottom` target.

Invisible from the call site, so worth stating: the rail derives its
current-position tracking root from the first element `resolve` returns. A
`resolve` that can reach another pane breaks the highlight, not just the jump.
