# tool-search

Renderer for `ToolSearch` tool calls in the JSONL viewer.

ToolSearch loads deferred tool schemas, so the row answers "which tools became
available?". Two query shapes:

- `select:a,b` — the collapsed line reads `Loaded a, b`; names asked for that did
  not come back get a `· N not found` note and warning chips (the model's next
  call to them will fail). A bare name (`read_page`) is served by its full MCP id.
- anything else is a keyword search — the line shows the query and
  `· N matches` / `· no matches`; the body lists the ranked matches.

The loaded names come from the result's `tool_reference` blocks, which carry no
text: the transcript parser keeps them as `result.toolReferences`
(`conversations/transcript-watcher`). `result.content` is empty on success.
MCP ids render as their tool name with the server dimmed; the full id is the
chip's tooltip.
