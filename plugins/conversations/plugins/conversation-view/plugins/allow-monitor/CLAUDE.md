# allow-monitor

Monitors the conversation's worktree for guard-bypass files. When any exists, a pulsing red "BYPASS ACTIVE" chip appears in the conversation toolbar header, and it disappears as soon as the file is removed.

The set of files is every guard's `bypassToken` (`BYPASS_TOKENS` from `framework/tooling/guards/core`), so a new guard's bypass file shows up here with no edit.

The value is the `allowFiles` live value (`allow-files`, params `{ id }` — the conversation id), served external. The files are written by the agent's own shell (the guard's denial message tells it to), so no app event marks them; a file watcher on the worktree root, run by `whileSubscribed` while the conversation has a subscriber, pushes each change through `notify`. Its start stays synchronous (the stop chains on the watcher's promise): an async start is awaited on the subscribe path and would hold the first value behind the watch opening.
