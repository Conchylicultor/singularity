# dmda

Guided visits from [desmotsetdesarts.com](https://www.desmotsetdesarts.com/visites-guidees),
read from the site's own JSON API. The site renders its listing client-side, so
the generic `url` type is handed an empty shell and truthfully extracts nothing.

`GET /api/front/visits?city=all&kind=<kind>&page=<n>&query=` — the call the page
itself makes, paginated with its own `done` flag. Found by rendering the page
headlessly once and watching its XHRs; that's the general recipe for the next
site like this.

## The first source type whose `extract` costs no model call

The model is for **ambiguity** — in HTML, which title goes with which date is a
judgement. Structured upstream data has none, so the mapping is a rename.

The one judgement left is the year, which the site publishes nowhere (the detail
page's Schema.org `Event` has an *empty* `startDate`). It is decided
deterministically: `Dimanche 09 Août` is 2026, not 2027, because 2027-08-09 is a
Monday. **The weekday is the year.**

## Three guards that keep this type from emptying itself

`extract` returns the source's FULL set and every absent identity gets
`disappearedAt` stamped, so these are data-loss guards, not defensiveness:

- **Running out of pages without the site's `done` throws** — never the rows we
  happen to hold.
- **An unreadable date string throws; a row with no `date` key is omitted.**
  These look alike and are opposites — one live row (id 1394) genuinely has no
  date, while a format we stopped understanding would drain the source one row
  at a time.
- **The fingerprint covers identity fields only.** `picture` is a signed
  ActiveStorage blob URL; per-request churn in the cache key defeats it.

## Two things that look wrong and aren't

- **`externalId` is the upstream `id`**, not the engine's title+day hash. The
  site models a walk as one product with a next occurrence, so its id keeps one
  row per walk as the date rolls forward instead of minting one per date.
- **`10h00` is Paris wall-clock, `startsAt` is UTC.** Aug is +2, Nov is +1;
  reading it as UTC puts every summer walk two hours early. No tz database here
  (see `event-date/CLAUDE.md`), so the offset comes from `Intl` at the candidate
  instant. Any source type reading local times off a foreign page needs this.
