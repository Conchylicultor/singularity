# manual

The hand-entry source type: **the user is the extractor.** Nothing is fetched,
nothing is configured, no model is called.

## Why `extract` echoes instead of returning `[]`

The engine's contract is *"`extract` returns the full current set, and every
identity absent from it gets `disappearedAt` stamped"*. Right for a fetching
type, lethal here: `extract: () => []` hands the engine an empty seen-set, which
`markEventsDisappeared` reads as "the source listed nothing" and turns into one
UPDATE burying every event the user typed.

Two belts, covering **different runs** — neither is redundant:

1. `extract` returns the source's own *live* rows (`disappeared_at IS NULL`),
   stored identity included, so the seen-set is every live row and the
   disappearance predicate matches nothing. The upsert is a no-op.
2. `probe` reports a **constant** fingerprint, so from a source's *second* run on
   the engine returns `unchanged` without reaching `extract` at all.

Belt 2 alone fails on the run that matters most — a first refresh runs with
`lastFingerprint = null`, so a user who hand-adds events before clicking "Refresh
now" loses all of them. Belt 1 alone leaves the disappearance path reachable
forever, one future `LIMIT` in the echo away from erasing a list.

**Constant, not `null`.** A fingerprint keys the *upstream material*; this type
has none (its material is the destination table), so a value that never moves is
the literal truth. `null` means "cannot fingerprint, always extract" — false
here, and it costs belt 2. Versioned (`manual:v1`) only because bumping it is the
way to force one re-run if the echo changes.

**The echo is lossless by proof.** `planEventWrites` writes unreceived optionals
as explicit `null`, so a column the echo cannot carry is *erased* on the round
trip. `EchoIsLossless` (`server/internal/echo.ts`) fails `tsc` naming any such
column, so adding an `events` column forces a decision here. A column counts as
carried by EITHER route: its own `ExtractedEvent` field, or derivation by the
engine from one (`keyof EventDateProjection` — the five `date` projections, which
is why the echo must NOT restate them). `echo.ts` is pure (type-only imports) and
unit-tested; the query is in `live-events.ts`.

## Zero config, deliberately

`manualSourceConfigFields` is `{}` — nothing to point this type at, and the
list's label is already `event_sources.name`. This is the registry's zero-config
case: the `+` menu must render an empty `configFields` as "nothing to configure".

The "add an event by hand" **form** is the events UI's, not this plugin's.

## Known gap in the `events-core` contract

`EventSourceType` cannot express *"does not participate in refresh"* —
`probe`/`extract` are both required, and the alternatives to the echo are throwing
(parking a blameless source in `status: "error"`) or returning `[]` (data loss).
A `refreshable: false`, or an `extract` that may return `{ kind: "unchanged" }`,
would let this plugin drop both belts. Reported, not patched: `events-core` is
frozen.
