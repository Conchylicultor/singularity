# model-call

The prompt a run sent to the model and what it said back, as one section of the
run pane.

## Why it lives here and not in `runs`

The run ledger is **generic over source types**, and only *some* source types pay
for a model call — a hand-entry source never makes one, and a future feed parser
would not either. A "Model call" region in `runs` would put an LLM in the one
plugin whose whole job is to describe runs without knowing what produced them.

So it is a contribution into `runs`' own `EventSourceRunDetail` slot, and this
plugin names **no source type either**: it reaches the calls through
`infra/claude-cli`'s generic correlation API (`useClaudeCliCalls({ correlationId:
runId, occurredAt })`), which knows only that some record made some calls. A
future non-LLM source type simply produces runs whose section reports that no
call was made. Nothing here changes when a source type is added or removed.

## All three arms, always

`useClaudeCliCalls` answers with a discriminated result, and each arm is a
different fact about *this* run:

- **`calls`** — one `<ClaudeCliCallDetail>` each. The rendering belongs to the
  plugin that owns the record, so every surface showing a prompt shows it
  identically; this section supplies only the surrounding chrome.
- **`none`** — the run never made a model call. For a cheap `unchanged` run this
  is **correct and expected**: the probe fingerprint matched, so extraction was
  deliberately skipped. The copy says so, because "no model call" read as a gap
  is the single most likely misreading of this app (see `runs`' CLAUDE.md).
- **`not-retained`** — it *did* make one, but the call log is a global ring of
  the most recent calls and has since trimmed it.

Collapsing `none` and `not-retained` would render "no model call" over a run
whose prompt merely aged out — a confident wrong explanation, which is exactly
what the discriminated result exists to prevent.

The run is fetched for its `startedAt`, which is the only thing that lets the
call log tell those last two apart; both fetches gate the answer, so the section
never reports `none` merely because the timestamp had not landed yet.

Terminology: **model call**, never "conversation". `runClaudePrint` is a
one-shot, tool-less, non-persisted `claude --print` — there is no session to
resume and no turn history to go looking for.
