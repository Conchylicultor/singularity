# source-detail

Umbrella for the **source side-pane's regions**. An umbrella only: no barrel, no
code. The pane and its slot live in the parent (`sources/web`); each child
contributes one `EventSourceDetail.Section` and owns its own data.

One region per sub-plugin because the regions answer independent questions —
*what is this source called and pointed at* (settings), *when does it run*
(schedule), *is it healthy* (status), *what has it actually done* (runs) — and
the detail-sections host already gives each one uniform card chrome plus
user-reorderable order. A source type that needs its own region contributes a
fifth section; nothing here aggregates them.

The row's `name` lives in `settings` alongside the type's `configFields`, not in
a card of its own: they are one form to the user, however differently the two
halves travel in the PATCH. That is also why `settings` no longer declares
`useAvailable` — a card that always carries the name can never open onto
emptiness.

Every child takes `{ sourceId }` and reads the row through the parent's
`useEventSource`, so they share one live subscription and each owns its own
loading / missing / errored rendering. A section that can have nothing to show
declares `useAvailable` (returning `true` while pending — loading is not empty)
rather than returning `null`, which would leave a titled bar over emptiness.

Design: [`research/2026-08-03-apps-events-event-tracking-app.md`](../../../../../../../research/2026-08-03-apps-events-event-tracking-app.md).

## Plugin reference

- Description: Umbrella for the source side-pane's sections — one sub-plugin per region of a configured source (settings, schedule, status, runs).
- Sub-plugins:
  - **`runs`** — Runs section of the Events source side-pane: the run ledger as a DataView (outcome, event counts, duration, error), including the cheap `unchanged` runs — the record that makes 'why did nothing happen' answerable. A row drills into the run's own pane, whose regions are contributions.
  - **`schedule`** — Schedule section of the Events source side-pane: the refresh cadence picker, the scheduling on/off switch, and Refresh now — whose discriminated RefreshSourceResult (enqueued / already-running / skipped) is rendered arm by arm rather than collapsed into 'done'.
  - **`settings`** — Settings section of the Events source side-pane: the source's own name plus the type's configFields, rendered generically through the fields FieldRenderer as one form with per-field autosave. Names no source type.
  - **`status`** — Status section of the Events source side-pane: the source's current state (also shown as a collapsed-card chip), its run watermarks and probe fingerprint, and the classified terminal error verbatim when it is parked.
