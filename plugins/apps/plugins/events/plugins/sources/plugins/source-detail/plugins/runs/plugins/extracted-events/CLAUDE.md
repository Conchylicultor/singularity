# extracted-events

The run pane's **Extracted events** region: which events this run touched, and
what it did to each. The summary above it says *"Found 12, New 3, Updated 9"* —
this is the list those numbers count.

## Why a junction table, not a stamp on the event

The link is `event_source_run_events` (run, event, action), written by the engine
inside the **same transaction as the run row**. The obvious cheaper designs are
both wrong in the same way:

- a `lastRunId` column on `events` is overwritten by the next run, so every run
  but the newest would show an empty list under counts claiming it touched
  twelve events;
- recovering the set from `last_seen_at` between the run's start and finish has
  the identical flaw — the next extraction re-stamps it.

A ledger whose rows contradict their own summary is worse than no list at all,
and the whole point of this ledger is that it can be trusted about the past. One
row per (run, event) is the only shape where a run keeps its own answer for as
long as the run row exists. Growth is bounded by the run's 30-day retention
through the FK cascade — checked at boot by `markCascadeBounded`, not merely
asserted here.

`disappeared` is a member of the same action vocabulary as `created`/`updated`
because it is something the extraction *did*: it listed the source in full, and
this event was not in it. There is no `unchanged` member — an extraction
re-upserts everything it lists, so "seen again, identical" is an `updated`.

## The section renders `event-list`'s row, not its own

`EventRow` and `useOpenEvent` come from `event-list` — the same row body and the
same destination as the main events surface, so an event reads and behaves
identically wherever it appears. Only the action chip in front is this plugin's.

The empty states are worded apart on purpose — the cache hit, the failed run, an
extraction that genuinely read a page with no events, and (counts > 0 but no
links) a run predating the per-event record, whose list cannot be reconstructed.
Collapsing them into "No events" would have the card contradict the counts an
inch above it.
