# settings

The Settings card of the source side-pane: the source type's `configFields`
rendered through `config_v2`'s `FieldRenderer` dispatch.

**This plugin names no source type, and adding one must not change this file.**
That is the whole payoff of putting per-type config in a `core/` `FieldsRecord`:
a new type ships a field record + an extractor and gets a working form.

- Autosave is per field, not per form. Each field renderer owns its own commit
  granularity (text commits on blur), so one PATCH lands per edit. The PATCH
  carries the FULL config because `UpdateEventSourceBody.config` replaces and
  revalidates the whole blob — a partial write can never leave a row whose
  config fails its type's schema. Two fields edited within one round trip would
  race (each sends its own snapshot); blur-granularity makes that practically
  unreachable, and the server revalidates either way.
- A stored blob that no longer fits its type's schema is *reported*
  (`readConfigValues` returns a result), never half-rendered — a partial form
  would silently drop the offending key on the next autosave.
- `useAvailable` hides the card for a zero-config type, and returns `true` while
  the lookup is pending so the card cannot pop in a frame late.
