# salsanueva

The weekly dance planning of [salsanueva.fr](https://salsanueva.fr/danses-adultes/planning-adultes/),
read from the school's own JSON API. The page ships an empty container and fills
it client-side, so the generic `url` type finds a venue with no events.

`GET /wp-json/v1/blb/courses?from_date=&to_date=&club_id=13958&booking_type=bs&v=2`
— the call the page itself makes. One request covers the whole published term;
`club_id` demonstrably changes nothing today but stays the page's value.

## One vocabulary, three uses

The config keys are the school's own spelling — `type`, `activity`,
`sub_activity`, `course_level`, `location_name`, `coach`, `days` — because those
same names are its **JSON fields**, its **query parameters**, and this source's
**filters**. That is what lets `originUrl` build a link to the school's own page
showing this source's exact subset, and each event link to the one course, with
no per-filter code. Rename a key and both links break.

Filters are applied here, not upstream: the API takes a date range and nothing
else, which is why the school's page filters client-side too. Empty selection =
no filter, exactly as an untouched dropdown on that page.

## 800 occurrences in, 75 courses out

The API serves one object per DATED OCCURRENCE. `event-date`'s contract is one
row per series carrying a rule, so `series.ts` groups them back:

- **Identity is the key, never a date** — style, level, studio, room, weekday,
  time. Supplied to the engine rather than left to its title+rule fallback,
  because the same course runs at both studios at the same hour and the fallback
  would collapse them onto one row.
- **All day arithmetic runs on `course_date`**, the school's own local day, and
  gaps are counted in whole days. A millisecond comparison reads the 169-hour
  week across the October DST change as "not weekly" and downgrades every autumn
  course to a one-off.
- **No `until`.** The window ends where the school stops *publishing*, not where
  the course stops running — and `until` is part of a series' identity, so one
  read off the window edge would mint a new row every week.
- **Holiday gaps stay weekly**, reported through `flags` aggregated by date. A
  rhythm that is not weekly at all falls back to the next occurrence as a `once`
  plus a flag, which is `event-date`'s own prescription, not an invention here.

## Two things that look wrong and aren't

- **The fingerprint excludes the dates and includes the WEEK.** Excluding: the
  window slides daily, so hashing occurrence dates reports "changed" every tick
  for a schedule nobody touched. Including the week: a recurring row's anchor is
  re-derived from the clock at *write* time, so a fingerprint blind to the week
  would freeze every course's "When" on the day the source was first read.
- **`category: "sport"`, not `art`.** A dance class is a thing you go and do
  weekly; `art` in this app already means going to look at art (`dmda`). The
  dance travels in `tags`, which is filterable.

## The catalogue is a snapshot

`core/internal/catalog.ts` copies the school's vocabulary verbatim — including
`Hip Hop` *and* `Hip-Hop`, and `Classique -Initiation` with the space missing.
Do not tidy them; the filters compare with `===`.

A season can retire a value. The fields accept any string (`tags/config`) so a
saved selection survives, and `extract` reports a selection that matched nothing
in the run's caveats — so a stale entry is loud, and refreshing the lists is a
one-file edit.
