# reanchor

Keeps `events.starts_at` / `ends_at` / `all_day` telling the truth for a
recurring row.

`events.date` (the rule + the extractor's anchor) is the authority and never
decays; those three columns are its answer for ONE instant — the one the
extraction ran at — and expire when that occurrence passes. Nothing else
recomputes them, so without this plugin a still-running weekly series keeps
claiming an August date and drops out of every `starts_at >= today` view. A
source on manual refresh never gets re-extracted, so it stays wrong forever.

Two triggers, and both are needed:

- **hourly cron** — the change signal is the passage of time, so there is
  nothing to subscribe to (the sanctioned no-polling exception, same as
  `events.refresh-tick`). Hourly rather than daily because cron here is UTC and
  graphile does not backfill a tick missed while the process was down: a laptop
  asleep at the one nightly slot would be wrong all the next day. The SWEEP
  reads the *local* day, so the cron line carries no timezone.
- **`onReady`** — covers a backend starting after a long sleep, and the worktree
  case (the schedule is main-only).

The decision is pure and lives in `events-core`'s `plan-reanchor.ts`, next to
the funnel that writes it.

The sweep resolves from the start of the local **day**, never from the wall
clock — the filters it feeds are day-granular, so an occurrence that started
earlier today is still today's. Resolving at `now` skips it and hides a weekly
event from the day it is actually running on (an all-day series, which "starts"
at midnight, would be pushed a week out by any daytime sweep).

## Plugin reference

- Description: Keeps a recurring event's occurrence columns (starts_at / ends_at / all_day) current as time passes: the hourly re-anchor tick plus the boot pass, so an 'upcoming' filter never drops a series that is still running just because its source has not been re-extracted since the last occurrence.
- Server:
  - Uses:
    - `apps/events/events-core.reanchorRecurringEvents`
    - `infra/jobs.defineJob`
  - Register: `defineJob('events.reanchor')`
