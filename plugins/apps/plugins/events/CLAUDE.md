# events

One events database — *"what is happening, and when"* — fed by pluggable
**sources**, delivered as a top-level Singularity app at `/events`.

This top-level plugin is an empty namespace only (no slots, no logic, per the
`create-app` skill). All content lives in sub-plugins:

- `events-core` — the contract layer everything else depends on: the three
  entities (`event_sources`, `events`, `event_source_runs`), the
  `defineEventSourceType` registry, the `EventSources.Type` web slot, the closed
  vocabularies, the source-CRUD endpoints, and the live resources.

Naming discipline — **one name per concept**:

- **source** — a *configured instance*, a row in `event_sources` ("the Fitzroy
  page").
- **source type** — the *plugin* that knows how to read that kind of thing
  (`url`, `manual`, `shotgun`). Never call this a "source".

The web-side slot namespace is `EventSources` (plural) because `EventSource` is
a DOM global and must not be shadowed.

Design: [`research/2026-08-03-apps-events-event-tracking-app.md`](../../../../research/2026-08-03-apps-events-event-tracking-app.md).
