# prompt-origin

The task-side half of the `/prompt` block: a task detail section that says
*"this came from page X"* and links back to it.

## Why it lives in the pages **app** tree, not under `page/`

The backlink's whole job is to navigate — it opens `pageDetailPane`, and that
pane is owned by `apps/pages/page-tree`. A plugin under `page/` that opened it
would need to import from `apps/`, creating a `page → apps` dependency edge for
a tree that is otherwise a self-contained document engine, reusable by any app
that wants to host pages. Pointing the edge the other way (`apps → page`) is the
direction that already exists: the pages app is the consumer, `page/` is the
library.

The domain half — the task↔block link rows, the resources, the creation
endpoint — stays under `page/plugins/prompt/plugins/link`, which this plugin
reads through its `web` barrel. So the pane knowledge lives here and the data
knowledge lives there, and neither has to know the other's internals.

## Why it can render nothing

`tasks_ext_prompt_block.pageId` / `.blockId` are plain text columns with no FK,
deliberately: a task is real work and must survive the block (and the page) it
was launched from. A dangling id is therefore a designed state, not a fault —
the section resolves the page against the live `pagesResource` and, finding
nothing, renders no header and no empty state rather than a broken link or an
error. Same for the far more common case of a task that never came from a page
at all.
