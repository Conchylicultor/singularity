# page-author

The page-kind control in the page-detail header, between version history and
"Copy block ID". Its icon says what the open page is to agents, and clicking it
opens a small panel to change that.

- **Page** (`MdDescription`, plain ghost icon) — an ordinary page: agents may
  read it and never write it.
- **Agent page** (`MdAutoAwesome`, blue) — agents may write all of it. Its row
  carries `author: "agent"` (the `<agent-page>` of
  `page/annotations/agent-notes/agent-page`).
- **Instructions** (`MdMenuBook`, `primary` tint) — the human's standing
  instructions to every agent working under the parent page (the
  `<instructions-page>` of `page/annotations/instructions/instructions-page`).
  A **Global** switch appears under the three choices on such a page: a global
  instructions page is pointed at in every conversation's opening instructions.

A choice calls `setPageKind` with the new kind. That is the one way a page's kind
changes after the page is created — an ordinary data write cannot change it. The
control waits for the server rather than flipping at once. The icon changes when
the live pages list updates, which is also what re-tints the page's row in its
parent page and in the sidebar.

While the pages list is still loading, the button's place shows a same-sized
placeholder, never the button. A button would claim a kind before that is known.

**This button is the only sign on the open page of its kind.** That is the user's
choice: no banner, no chip. From outside the page, the tinted row in the parent
page and in the sidebar still say so.

## Why it lives here

- **Under `apps/pages`, not in a `page/**` plugin.** The header strip
  (`PageDetail.HeaderActions`) belongs to the Pages app's page pane, which is app
  chrome. The `plugins/page/**` plugins are the editor the app is built on, and
  none of them imports an `apps/**` web barrel, so the control cannot be
  contributed from there without inverting that layering.
- **Still named `page-author`, and its contribution id is still `page-author`.**
  It shipped as a two-way agent-page toggle. A plugin's id is derived from its
  folder, and reorder's persisted header-strip directives are keyed by
  `<pluginId>:<id>` (`config/apps/pages/page-tree/header-actions.jsonc`), so a
  rename would silently drop the control's place in the strip. The kind still
  answers the question the name asks — whose words the page holds and who may
  write it. ("Agent pages" is taken anyway: `apps/pages/agent-origin` marks pages
  an automated browser session created.)
