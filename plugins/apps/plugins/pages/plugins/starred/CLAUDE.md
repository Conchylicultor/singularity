# starred

Favorites/starred pages, as a **presence-only marker** — not a bespoke sidebar.

- `page_blocks_ext_starred` is a pure presence side-table (one row per starred
  page, no columns of its own beyond the synthesized `blockId` key/timestamps).
  Presence = starred; there is no rank/order column.
- The plugin contributes a single `starred` bool `FieldDef<PageRow>` into the
  page-tree's `PageTree.Fields` field-extension seam (`StarredField` closes the
  field's `value` over the starred id set). That makes `starred` a filter
  dimension of the one `pages-sidebar` DataView.
- **One read serves everything.** `useStarredPageIds()`
  (`web/internal/use-starred-ids.ts`) is the only reader of the `starredPages`
  collection (`useLive(starredPages)`, the default window); the field and both
  toggles go through it, so they cannot disagree and every mount shares one
  subscription tuple. It returns a read (`ResourceResult<ReadonlySet<string>>`):
  not known yet and failed are their own arms, and each caller decides: the toggles render a disabled loading button (a hollow
  star would claim "not a favorite", and a click would star an already-starred
  page), while `StarredField` projects an empty set, so Favorites stays empty
  until the window lands.
- **Favorites is a filtered `list` view instance** of the `pages-sidebar`
  DataView (authored in `page-tree`'s config, filtering on `starred = true`) —
  not a separate `Pages.Sidebar` contribution. The DataView's view switcher is
  the sidebar chrome.
- The Favorites **row order belongs to the view** (`data-view/view-order`, keyed
  by `(dataViewId, viewId)`), not to this table. Consequently there is no rank
  column and no reorder endpoint.
- `starredPages` (`shared/resources.ts`) is a `liveCollection` read as its
  **bounded default window** (desc `createdAt`, default 500 / max 1000,
  `filterable: {}`), not by id: `StarredField` needs `starred` for every row the
  DataView filters over, so an id set would have to name every page id —
  O(pages), which bounds nothing. What is bounded is the favorites set. It is
  served by `serveCollection(starredPages, { from: pageBlocksStarred })` — the
  extension handle's wire columns — and `...starredPagesServed.declare` is
  spread into the server contributions. Star and unstar are membership
  entry/exit and ship incremental deltas. The boundary is real: past `maxLimit`
  favorites the oldest-starred page reads as unstarred. Same shape as the
  sibling `agent-origin` plugin.
- The two star toggles stay: `PageTree.RowActions` (row hover) and
  `pageDetailPane.Actions` (page header), both flipping `PUT /api/pages/:pageId/starred`.
