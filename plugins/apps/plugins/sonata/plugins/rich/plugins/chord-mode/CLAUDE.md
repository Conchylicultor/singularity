# chord-mode

Per-song **chord mode** for Sonata. A chord-grid song has no notes of its own:
the shell voices its authored chord annotations into the Chords / Bass tracks.
A MIDI song is the opposite — literal notes, and the chord *analyzer* only
labels them. Chord mode lets a MIDI song be played and drawn **as its detected
chords**, through the very same voicing config + rhythm groove a chord grid
uses, while its original tracks stay individually selectable.

## Design

- **The pipeline only *adds* tracks.** When the mode is on, the shell's
  `baseScore` runs `reVoiceChords(…, { include: "all" })` a second time, AFTER
  chord analysis (detection needs the original notes, which stay in the score),
  voicing authored + derived chords in one pass so voice-leading is continuous.
  The new notes land on the chords' existing beats — a view transform, so it can
  never rewind the transport. The pass also re-targets each voiced annotation at
  the notes it generated (a derived chord otherwise keeps pointing at the
  original notes it was detected from).
- **Turning the originals off is ordinary track-mixer state.** The toggle
  writes hidden + muted for every score track that is not `chords` /
  `chords-bass` through the mixer's `setTracksActive` (one transaction, one
  push) and clears them on the way out. Every display and the audio engine
  already filter by the mixer's rollup, so nothing here filters notes. Which
  original tracks play in chord mode is then an ordinary Tracks-card edit and
  persists like any other. **Trade-off, chosen deliberately:** the toggle
  overwrites any prior hide/mute state on entry and exit — "the toggle
  activates/deactivates the original notes".
- **Ordered so the listener never hears both layers.** The shell store flips
  synchronously; the mixer write lands a live-state round-trip later. So: on
  entry the originals are turned off first (awaited), then the mode flips; on
  exit the mode flips first, then the originals come back. A beat of silence,
  never a doubling. The chip is disabled while the awaited write is in flight.
- **State is DB-persisted per song** in `sonata_songs_ext_chord_mode` (an
  `entity-extensions` 1:1 side-table; an absent row reads as off). A push
  live-state rollup (`chordModeResource`) serves all rows; the headless
  `ChordModeObserver` (a `Sonata.Effect`) does the per-song lookup and writes the
  shell's per-surface `chord-mode-store` — the sole owner of "which song's mode
  is in force" (writes `false` when no song is open). Dependency arrow stays
  feature → shell; this plugin also imports `track-mixer/web`, which never
  imports it back.
- **The card is a static row.** `Sonata.Section` with no body `component`: the
  "Chords" title plus the On/Off chip in `actions` is the whole card. Available
  when the song has an analyzer-derived chord (something to voice) or the mode is
  already on (so it can always be switched off).
- **Voicing and Rhythm follow.** Those cards gate on the shell's
  `useHasVoicedChords` (authored chord, or chord mode on with any chord), so
  flipping the mode on a MIDI song brings them in unchanged.

Follow-ups worth knowing: detected chords are as dense as detection makes them
(one window per beat, coalesced while the symbol holds) — a snap-to-bar knob
would live on this card; snapshot/restore of the pre-toggle track state would
remove the overwrite trade-off.

## Plugin reference

- Description: Sonata Section: per-song chord mode. One On/Off chip in the 'Chords' card header: on, the shell voices the song's detected chords onto the Chords / Bass tracks (same voicing + rhythm options as a chord grid) and the original tracks are turned off in the Tracks card, where any of them can be re-enabled. Persists per song and syncs into the shell's score pipeline via a headless Sonata.Effect observer. Owns the sonata_songs_ext_chord_mode side-table: per-song toggle to play a song's detected chords (voiced onto the Chords / Bass tracks) instead of its notes. Serves the reactive rollup.
