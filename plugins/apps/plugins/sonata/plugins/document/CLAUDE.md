# document

The song document: which song a surface holds, its content (every source's raw
input) and its per-song settings, as ONE per-surface state, and the score
composed from them. `SongDocumentProvider` provides it; `useSongDocument()` reads
`{ identity, content, sourceRaw, setSourceRaw }`; `useLoadDocument()` returns
the one way to load: `load(identity, rawById)`.

## Identity

`SongIdentity` is a union — `{ kind: "library"; songId }` or
`{ kind: "file"; key }` — so a file opened for preview can never be mistaken for
a library song:

- A **library** song's settings are persisted by their feature plugins and
  settled by the registered observers (`SongSettingsMount`, mounted by the
  player scope).
- A **file** document mounts no observer, and every setting reads its
  `absent` value (`defineSongSetting(name, absent)` requires one) at once. No
  setting can be written for it.

`useLibrarySong()` answers `{ kind: "library", songId } | { kind: "none" }` for
the LOADED document. Every setting writer (transpose stepper, track mixer, chord
mode, key auto-detect, rhythm groove) takes its song id from it — the song whose
settings it reads — and renders nothing for `none`.

## Content

`content` is `empty | pending | failed{failure} | ready{score}`, each arm
carrying `contentKey` (the compiled, merged sources before any view transform).
The pipeline: compile every `SonataDocument.Source` that has raw input →
`mergeScores` → transpose → `reVoiceChords` → `inferKeys` → `spellScore` →
every `SonataDocument.Analyzer` → chord mode. The score is untempo-scaled; the
playback session folds the tempo in.

## Per-song settings — pending is a state

Per-song settings transform or accompany the loaded song: transpose, key
auto-detect, chord mode, groove (rhythm) and track view (the mixer's per-track
color / instrument / mute / hide / volume). A setting is a
`defineSongSetting(name, absent)` key (`song-setting.ts`) defined by the plugin
that reads its value — the document for the four its pipeline transforms with
(`score-settings.ts`), the track-mixer for the track view. A read is
`SongSetting<T>` = `pending | failed | settled{value}`.

- **One loaded document: identity, content and settings in one state.** A
  different document replaces all three in one write, its settings empty
  (pending); the same document keeps its settings. So no render can pair one
  song's content with another song's settings.
- **The composition registers the settings.** A feature plugin contributes
  `SonataDocument.SongSetting({ id, setting, component })`: the setting and the
  headless observer that settles it. `SongSettingsMount` mounts every observer
  for the loaded library song, keyed on the load's generation, so an observer
  reads the non-null `useMountedSongId()` and mounts afresh whenever a different
  song is loaded — even A → B → A in one tick. A write for a song that is not
  the loaded library song is dropped.
- **Nothing renders or plays until every registered setting settles.** While
  content is loaded and a registered setting is pending, `content` is `pending`
  (displays show a loading state; the session defers its reset); a failed read
  makes it `failed` (displays show the failure with Retry). A setting nobody
  registers is not waited on and reads as its `absent` value.

`useHasChords` / `useHasDerivedChord` / `useHasVoicedChords` are the section
availability gates over the composed score.
