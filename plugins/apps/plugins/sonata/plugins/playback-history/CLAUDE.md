# playback-history

Play stats reach the library as `Library.Fields` only — one projection, so the
card, the table column, the Sort pill and the Filter pill can't disagree.
`playCount`'s `cell` says "3 plays" / "Not played yet"; that sentence therefore
shows in the TABLE's Plays column too, which is deliberate.

`playbackHistory` (`shared/resources.ts`, key `"sonata-playback-history"`) is a
`liveValue` of the whole `sonata_songs_ext_playback` table, served by
`playbackHistoryServed` (`serveValue({ source: "db", unbounded: { reason } })`)
and read with `useLive(playbackHistory)` inside `usePlaybackHistoryMap`. It is
whole-table only until Resources item 7: the library sorts by plays over every
song client-side, and a bounded read needs joined side-table sort/filter columns
on the songs collection, the host rows in data-view's `FieldExtensionProps`, and
live-window paging in DataView — item 7's joined columns then replace this
value. Until then `usePlaybackHistoryMap` keeps its documented pending →
empty-map collapse (a missing entry sorts as "never played").

## Plugin reference

- Description: Per-song play count + last-played: records a play on playback start (Sonata.Effect), and contributes Plays / Last-played fields (Library.Fields) so they appear on the library card, in the DataView's sort and filter pills, and as table columns.
