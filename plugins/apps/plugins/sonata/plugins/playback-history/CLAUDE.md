# playback-history

Play stats reach the library as `Library.Fields` only — one projection, so the
card, the table column, the Sort pill and the Filter pill can't disagree.
`playCount`'s `cell` says "3 plays" / "Not played yet"; that sentence therefore
shows in the TABLE's Plays column too, which is deliberate.

The stats are columns of the song library, not a side read: `playbackColumns`
(`core/columns.ts`) is a `liveColumns` handle on `songLibrary` (`playCount`
filterable and sortable, `lastPlayedAt` filterable and sortable), served by this
plugin's server over the `sonata_songs_ext_playback` extension
(`LiveColumns.Serve(serveColumns(playbackColumns, { join:
songPlayback.join("playback") }))`, `server/internal/columns.ts`). Every library
row carries them under `$columns.playback`; `PlaybackFields` reads them with
`playbackColumns.read(song)` and binds `playbackColumns.column(…)`, so the
library sorts and filters by them on the server. `playCount` reads the
extension's default (0) for a song never played (the join `COALESCE`s it), so
"Unplayed" (`playCount = 0`) and "Most played" keep their meaning;
`lastPlayedAt` is null until the first play and sorts last. A recorded play
(`POST /api/sonata/songs/:id/play`) refills exactly that song in the library
tuples that read the join. The extension shape is `shared/shape.ts` (the server
table is built from it).
