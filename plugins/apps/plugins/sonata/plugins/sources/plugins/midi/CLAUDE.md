# midi

The track count reaches the library as a `Library.Fields` contribution
(`MidiFields`), not a per-card widget: `value` is `null` and `cell` renders
nothing for a song with no MIDI row, so the shared card stays source-agnostic
while the column/sort/filter come free.

Both MIDI facts the library lists are columns of the song library:
`midiColumns` (`core/columns.ts`) is a `liveColumns` handle on `songLibrary` —
`trackCount` (filterable, sortable; `null` for a non-MIDI song) and
`sourceMissing` (filterable; the extension's default `false` for a song with no
MIDI row) — served over the `sonata_songs_ext_midi` extension
(`LiveColumns.Serve(serveColumns(midiColumns, { join: songMidi.join("midi")
}))`, `server/internal/columns.ts`; the server-only `contentHash` is no wire
column, so it cannot be bound). Every library row carries them under
`$columns.midi`; `MidiFields` and the `folders` sub-plugin's "File" field read
them with `midiColumns.read(song)` — the handle is this plugin's public core.
One song's MIDI for playback is the `getSongMidi` endpoint. The extension shape
is `shared/shape.ts`.

## Plugin reference

- Description: MIDI file input source for Sonata. Dropzone accepts .mid/.midi files; compile() parses them into a Score via @tonejs/midi. Persists per-song MIDI (attachment + track count) and contributes the library Import affordance, hydration, and the Tracks field. Owns the sonata_songs_ext_midi side-table: per-song MIDI attachment + track count. Creates MIDI-backed songs, serves the song library's `midi` columns (track count, file-missing), and seeds the bundled public-domain MIDI starters at boot.
