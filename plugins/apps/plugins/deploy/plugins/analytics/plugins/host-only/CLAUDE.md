# host-only

Routes that answer only requests made on the deployed box itself. The deploy
app's dashboard reaches them over SSH (`curl http://127.0.0.1:<port>/api/host-only/…`);
the public internet never does.

Two independent guards:

1. **Caddy** — `caddySite()` (`framework/cli/deploy`) emits
   `respond /api/host-only/* 404` from `HOST_ONLY_PREFIX`, so no deployment can
   forget it.
2. **`hostOnly(handler)`** — 404 unless `X-Forwarded-For` holds exactly one hop.

Why one hop means "from the box": Caddy replaces any client-supplied
`X-Forwarded-For` with the address it saw, and the gateway's
`httputil.ReverseProxy` (Director mode, `gateway/worktree.go`) appends its own
peer. A public request therefore arrives as `<visitor>, 127.0.0.1`; an on-box
request straight to the gateway as `127.0.0.1`. `requestClientIp(req)` reads the
same chain (second-to-last entry) and is the only code that should know it.

A request made straight to the backend's unix socket carries no header at all,
so it is refused too — go through the gateway (`http://<ns>.localhost:9000`
locally, the loopback port on a box).
