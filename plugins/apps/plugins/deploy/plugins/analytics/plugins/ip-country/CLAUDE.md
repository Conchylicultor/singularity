# ip-country

Which country is this IP address in? Answered from a local copy of
[DB-IP IP-to-Country Lite](https://db-ip.com) (CC BY 4.0), held in memory. The
address is never sent anywhere: the only network traffic is a plain weekly GET
of DB-IP's public file. Generic — it knows nothing about analytics; deployed-site
analytics (`apps/deploy/analytics/collect`) is its first user.

## API

```ts
import { lookupCountry } from "@plugins/apps/plugins/deploy/plugins/analytics/plugins/ip-country/server";

const r = lookupCountry(ip);
// { kind: "found", country: "FR" }  — ISO 3166-1 alpha-2, as DB-IP spells it
// { kind: "unlisted" }              — ZZ (private/reserved), no range, or not an address
// { kind: "unavailable" }           — no snapshot downloaded on this machine yet
```

`unavailable` is its own arm on purpose: "we do not know yet" must never pass as
"this IP has no country".

Any surface that shows a looked-up country credits the source from
`IP_COUNTRY_SOURCE` (`core`) — the license requires attribution.

For tests, `createIpCountryLookup(() => path)` builds a lookup over any snapshot
file, and `buildSnapshot(csv, yyyymm)` makes one from a small CSV fixture.

## How it works

- **Snapshot.** `server/internal/snapshot.ts` turns DB-IP's `start,end,CC` CSV
  (IPv4 rows, then IPv6; ~717k rows) into a compact binary file: a header
  (magic, format version, source month, counts), the country-code table, and
  per family start/end/code-index typed arrays. The builder asserts each family
  ascends without overlap (a binary search answers wrong silently on unordered
  input) and yields to the event loop between chunks. A load is zero-copy
  typed-array views; a wrong magic, version or length throws.
- **Lookup.** `lookup.ts` reads `~/.singularity/cache/ip-country/ip-country.bin`
  lazily on the FIRST lookup (one synchronous ~16 MB read), so a backend that
  never looks anything up never pays for it. `reloadIpCountry()` drops the held
  copy; the refresh job calls it in-process after writing — no watcher, no
  polling. IPv4-mapped IPv6 (`::ffff:1.2.3.4`) is looked up as IPv4.
- **Refresh.** `ip-country.refresh` (`hold: "seconds"`, 60 s download timeout,
  weekly cron `perWorktree: true` because a deployed release is never main) skips
  when the file is under 7 days old and of the current format. Otherwise it
  downloads this month's file, falls back to the previous month on a 404 (a new
  month's file appears some days in), gunzips, builds, and writes via temp file +
  rename. `onReady` enqueues it when the snapshot is missing or stale, so a fresh
  install has data about a minute after boot. Visits before that get
  `unavailable`.
- **Format changes.** Bump `SNAPSHOT_FORMAT_VERSION`. An old file then counts as
  needing a refresh, so the next boot replaces it.

## Plugin reference

- Description: IP-to-country lookup from a local copy of DB-IP IP-to-Country Lite: lookupCountry(ip) answers found / unlisted / unavailable by binary search over an in-memory snapshot read lazily from the machine-wide cache, and the weekly ip-country.refresh job (also enqueued at boot when the snapshot is missing or stale) downloads the CSV, builds the compact binary snapshot and swaps it in. The IP never leaves the process.
