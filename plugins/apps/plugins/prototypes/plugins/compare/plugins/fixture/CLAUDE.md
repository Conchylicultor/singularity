# fixture

The **`fixture:`** kind of counterpart for the prototype Compare stage: the real
app component a prototype mocks, as a **layout-harness fixture** rendered live
at the stage's shared width.

It is a separate plugin because it is the only thing in the Prototypes app that
reaches into app internals — the layout-harness fixture catalog. The compare
plugin's kind set is a slot precisely so that weight lives in one folder.

## The pairing is declarative, and only the prototype declares it

```html
<meta name="mocks" content="fixture:control-panel/setting-rail" />
```

The ref is a **layout-harness fixture id** (the ids in Debug → Layout Lab).
Nothing here offers a picker: the prototype is always the source of the pairing.

**The lookup can only be a runtime one.** Prototypes are host-global and shared
by every worktree; fixtures are per-worktree code on a branch. A prototype
naming a fixture that does not exist here is *ordinary* — it may exist on
another branch — so the resolution says which id it asked for rather than
treating it as a fault.

## What it resolves to

`FixtureCounterpart` loads the catalog once (`loadFixtures()`, in an effect, no
polling — the generated registry's entries are dynamic imports, so the fixtures
are code-split off the pane's own wave) and answers:

- **loading** while the catalog is not in yet — never "no such fixture", which
  would be a claim about the user's file that then reverses itself.
- **unresolved** when nothing here has that id, *or* it is a **region fixture**
  (`control-panel/region`, `section-card/region`, …). A region fixture takes
  the children the harness supplies and has no rendering of its own to put
  beside a mock; those children come from `expandRegionFixtures`, harness
  internals we do not widen the barrel for. Making regions comparable is a
  deliberate follow-up.
- **found**, with the fixture's own `widths` (fallback `360 / 640 / 960`) — the
  component's own statement of where it changes shape — and
  `render: () => fixture.render()`.

The chrome, the width control and the error boundary around `render()` belong
to the parent `compare` plugin; see its `CLAUDE.md`.
