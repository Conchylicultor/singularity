# checkpoints

At the end of every agent turn, records a version of each prototype that turn
touched. The version store itself (one private git repo per prototype, beside
the folder) belongs to `files`; this plugin only decides **which** prototypes a
turn touched and **what** to write in the version's message, then calls
`checkpointPrototype`.

```
conversationTurnCompleted { conversationId, messageId, text }
  → prototypes.checkpoint-turn: read the transcript, take this turn's window
  → prototype ids named in the window's tool-call inputs
  → checkpointPrototype(id, { kind: "turn", subject, body, conversationId, messageId })
```

Design: `research/2026-09-11-apps-prototype-version-history.md`.

## Decisions that look wrong until you know why

**A separate plugin, not part of `files`.** The job needs `conversations` (the
event and the transcript). `files` is the low-level owner of the tree, imported
by the CLI; keeping the turn job here means `files` never depends on
`conversations`.

**Attribution comes from the transcript, not from what is dirty.** Several
agents can be iterating on different prototypes at once. Snapshotting every dirty
folder at the end of one agent's turn would record another agent's half-written
file under this turn's request. So a turn records only the ids its own tool calls
named — an `Edit`/`Write` path, a `Bash` command, and an `Agent` call's prompt
(a subagent's tool calls live in its own transcript, so the delegating prompt is
the only trace here). A change no turn claims is not lost: it waits in the folder,
shows as "Live · unsaved changes", and goes into the next version.

**The window starts at the previous `end_turn`, not the previous user message.**
A turn the user interrupted never reached `end_turn`, so nothing recorded it;
starting at the previous `end_turn` folds its changes into the next turn.

**An unknown `messageId` records nothing.** It means the message is not on the
live branch (a rewind abandoned it). Picking some other window would file one
turn's changes under another turn's request. A `null` `messageId` (allowed by the
payload type, never sent by the emitter) takes the last `end_turn` and uses that
message's id.

**No dedup of its own.** The event is at-least-once, and several backends may
emit it for one turn. `checkpointPrototype` answers `unchanged` when a version
already carries this turn's `messageId`, so running twice is harmless. A busy
history lock throws, and the job's retry picks it up.

The window, id and message rules are pure functions over the transcript's events
(`server/internal/turn.ts`), pinned by `turn.test.ts`.

- Description: Records a version of every prototype an agent turn touched, at the end of that turn: reads the turn's window out of the conversation transcript, finds the prototype ids its tool calls named (Edit/Write paths, Bash commands, an Agent call's prompt), and checkpoints each through the files plugin's version store with the turn's request and summary.
