# present

The **Present** control in the prototype detail pane's header — the three ways
to see a prototype with none of the app around it:

- **In this tab** — a viewport-filling overlay: the same live iframe the pane
  shows, scaled UP to fill the tab (the pane's stage never upscales; a
  presentation should). Escape or the × closes it.
- **Fullscreen** — the same overlay, additionally handed to the browser's
  Fullscreen API, so it covers the screen rather than the tab. The close button
  lives *inside* the element that goes fullscreen — a sibling of it would be
  invisible there. Escape exits fullscreen (browser-handled) and the resulting
  `fullscreenchange` closes the overlay, so one key still leaves.
- **New tab** — `window.open` on the raw prototype document, at its native size,
  carrying the same `?v=` cache-bust the in-app iframes use so a new tab never
  opens a copy an agent has already edited past.

The whole feature is one contribution — `prototypeDetailPane.Actions({
component: PresentMenu })` — so the detail pane knows nothing about it. Adding
another way to view a prototype is a sibling plugin, not an edit here.
