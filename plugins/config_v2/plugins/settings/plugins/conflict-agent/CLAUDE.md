# conflict-agent

The **Ask an agent** button inside a config detail's conflict banner: opens the
standard `LaunchAgentPopover` — the same surface as the crash **Fix** button and
the build-failure investigate button — with the conflict already written out as
the agent's first turn: which fields both sides changed, which only upstream
moved, or (for an invalid document) which schema issues it fails on.

**Why the launch popover and not the task-draft one.** `TaskDraftPopover` drafts
a task for someone to pick up later; this button's job is to put an agent on the
conflict now, with the user choosing the model and adding context. That is what
every other "launch an agent about this thing" surface in the app does, so it
uses the same one. The launch is fire-and-forget — the toast is what carries the
user to the conversation.

**Why a separate plugin.** The config editor is generic; launching agents would
drag conversations and the launch stack into every composition that ships
Settings. So `config_v2/settings` owns the `ConfigDetailSlots.ConflictAction`
render slot and hands contributions a plain `ConfigConflictContext` (descriptor,
scope, kind, per-field classification, pre-joined issues, the banner's button
tint). The editor names neither this plugin nor conversations.

**The prompt** (`web/internal/build-prompt.ts`, pure + unit-tested) lists only
fields carrying a decision, clips any serialized value past 200 chars, and asks
for the `defineConfig` descriptor's recent history and a source-level fix. It
also states that the user's config layer is forked per worktree
(`~/.singularity/state/config/<worktree>/…`, spelled via `paths/display`) —
without that, an agent "fixes" the conflict in its own fork and reports success
on a change the user never receives.

`describeConflict()` in the same module is the popover's one-line summary. It
counts the fields carrying a DECISION rather than the ones that merely differ,
which is the count the banner itself reports — so the popover can never
contradict the banner that opened it.
