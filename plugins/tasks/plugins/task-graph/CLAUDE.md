# task-graph

## This "cluster" ≠ `task-deps-tree`'s — do not unify them

Here: `TaskGraph.closure(id, {includeGroups: true})` follows `groupId` upward only
and never `folderId`. Asymmetric ⇒ not an equivalence relation ⇒ **not expressible
as a label at all**. `useTaskGraphAvailable` asks a live question ("edges right
now"), so the card correctly comes and goes with the edges.

`task-deps-tree` asks the opposite: a persisted *monotone* `tasks.clusterId` label
over `{dependency edges, folderId}` that never shrinks, so a task can't vanish from
the tree (`research/2026-08-03-tasks-monotone-deps-tree-membership.md`). The two
disagreeing is the design, not drift.
