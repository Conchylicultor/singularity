# attempt-status

Single source of truth for `Attempt` status display metadata. All plugins that
render an attempt's status as a colored badge import `AttemptStatusBadge` from
here instead of defining their own color/label maps. Mirrors the `task-status`
plugin for the attempt enum. Labels are the sentence-case of the status key,
derived via `formatStatusLabel`, so they never drift from the house casing rule.

## No status editorialises

Every `AttemptStatus` names a fact the row proves (**I6**, `tasks-core/CLAUDE.md`),
so the badge reports that fact and nothing more. Only `completed` carries colour —
the one arm making a claim the user is waiting on. The rest recede to muted type,
per `task-status`'s "colour is reserved for what needs action".

Two stylings look under-done and must stay that way:

- `closed` is **not** italic/struck. A missing `pushes` row proves nothing (I3), so
  "ended with nothing recorded as landed" is not a verdict — it gets neutral type.
- `dormant` is **not** warning-tinted. It is usually hibernation parking an idle
  pane, and the attempt is resumable; a tint would cry wolf on routine.
