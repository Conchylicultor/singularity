# task-deps-tree

## Membership: a persisted monotone label, not a graph walk

`taskClusterIds` (`core/cluster.ts`) filters on `tasks.clusterId ?? tasks.id` — a
union-find representative written by `unionTaskClusters`
(`tasks-core/…/mutations/clusters.ts`) on every membership-edge creation and
**never** rewritten on removal. So a task joins a tree and can never fall out of
it: detach its last edge and it stays, rendering as a parallel root. `NULL` =
never unioned = own singleton.

Deliberately path-dependent (a function of history, not current state) — hence
persisted state, NOT a `derived-view`/`derived-table`, which rebuild on boot and
would re-split the clusters. Design:
`research/2026-08-03-tasks-monotone-deps-tree-membership.md`.

`groupId` deliberately does **not** union: the relation is exactly
`{dependency edges, folderId}`. Adding `groupId` expands what the tree means.

**This "cluster" ≠ `task-graph`'s — do not unify.** `task-graph` uses
`TaskGraph.closure(id, {includeGroups: true})`: follows `groupId` upward only,
never `folderId`. Asymmetric ⇒ not an equivalence relation ⇒ not expressible as a
label at all. Its `useTaskGraphAvailable` also asks a live question ("edges right
now"), the opposite of the monotone one here.
