# reports-investigation

Bridges the `reports` plugin's investigation flow to the `tasks` domain. When a
user clicks "investigate" on a report, `reports` emits an
`InvestigationTaskRequest` into its `reportInvestigationSink` — this plugin
registers the handler that turns that request into a real root task stamped with
the **Reports** category (idempotent: an already-linked live task is reused).

## Why it lives under `tasks/`

The bridge is the piece that legitimately holds the `tasks` dependency
(`createTask` / `getTask` / `setTaskCategory` / `TaskCategory`). Keeping it in the
`tasks` subtree — rather than under `reports/plugins/` — keeps reports' own server
closure free of `tasks`, so reporting can ship in a self-contained released app.
A composition that omits this plugin simply leaves the sink unregistered: reports'
`investigateReport` then throws loudly (a missing capability, not silent).

The mirror of the Edge-1 `defineReportSink` inversion: the **emitter** (`reports`)
owns the sink; the **capability-holder** (this bridge, via `tasks`) registers into
it. The server registry runs `onReady` for every discovered plugin regardless of
who imports it, so this bridge boots and wires itself even though nothing imports
it.

## Report investigations automation

`report-investigations` (`server/internal/automation.ts`, a `tasks/automations`
automation, **off by default**). Its config (`shared/config.ts`) adds the scope
to the common fields: `severity` (error | warning | everything, matched against
each kind's bell variant), `minCount` (occurrences, default 3) and
`excludedKinds` (default `report-storm`).

- **Woken** by reports' `reportRecordedSignal` (emitted for every recorded
  occurrence of an uninvestigated, non-noise report — after the duress and
  fan-out gates) calling the handle's `fire()`, so a burst settles into one run;
  or on a schedule, as the config picks.
- **Each run** files ONE task for up to 20 in-scope uninvestigated reports,
  oldest first (`{{reports}}` renders each with its kind's `renderTask`, grouped
  by kind), and links every one to it (`linkReportsToTask`) — so they are no
  longer uninvestigated, Debug → Reports shows "View task", and the next run
  skips them. A report whose task was dropped is not re-filed.
- **Which reports** is its pane section (`web/components/report-scope-section.tsx`,
  through `Automations.Section`), counting the matches live from
  `GET /api/report-investigations/scope`.
