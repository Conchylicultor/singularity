# task-ids

The three id kinds the tasks / attempts / conversations tables are keyed by,
declared once with `defineIdKind` (`plugins/ids`): `taskIdKind` (`task-`),
`attemptIdKind` (`att-`) and `conversationIdKind` (`conv-`). One object each owns
the mint, the branded type (`TaskId`, …), validation and inline recognition, so
every reader of the shape — the active-data chips, the worktree and tmux-session
name parsers, the build e2e — reads the kind instead of re-typing a regex that
drifts silently from the mint.

**Why a leaf plugin, not `tasks-core/core`.** A worktree's name IS its attempt
id, so `infra/worktree`'s name parser reads `attemptIdKind` — and `tasks-core`
imports `infra/worktree`. Declared in `tasks-core`, the kind would close a
`tasks-core → infra/worktree → tasks-core` cycle; declared here, both import a
leaf that imports nothing but `ids`. The kinds are registered (`IdKinds.Kind`)
by `tasks-core`, which owns the tables.

All three mint the `stamped` shape (`<prefix>-<epochSeconds>-<6 base36>`,
zero-padded). Live rows keep their older shapes (task: epoch ms + 6; att/conv:
epoch s + 4) and stay recognised by the generic body every kind shares. `claude`
is a recognition-only alias of both att and conv (one legacy value named both;
the oldest are suffix-less `claude-<epoch>`). `core/id-kinds.test.ts` pins
recognition against real mints.
