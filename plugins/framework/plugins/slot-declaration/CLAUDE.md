# slot-declaration

The slot contract, split out of `web-sdk` so it can be read without React.

- `SlotMeta` — what a slot IS (`kind`) and whether its contributions are
  user-orderable (`reorderable`), stamped by the constructor. Not sniffed from
  which render method got attached, and not grepped from a constructor's name.
- The created-set — `defineSlot` (the single funnel every constructor calls)
  appends every slot at construction, so nothing has to be kept in sync.
- `collectSlots` — the ONE normalisation of a plugin's `slots` RECORD
  declaration (one level deep), shared by `PluginProvider`, the slots facet and
  the build-time orphan guard, so the three cannot disagree.

**Why a leaf and not part of `web-sdk/core`.** Its build-time readers (the slots
facet, `codegen`'s declaration guard) run in the barrel-import process. Pulling
`web-sdk/core` in would drag React into their module graph *before*
`registerBarrelStubs` runs, binding the real package ahead of the stub the whole
barrel-import phase relies on. Module eval here depends on nothing but a type
import — keep it that way.
