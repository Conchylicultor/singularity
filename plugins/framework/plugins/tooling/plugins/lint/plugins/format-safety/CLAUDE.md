# format-safety

Contributes the repo-wide `no-adhoc-prettier` ESLint rule: importing prettier
(static, dynamic, or `require`), spawning its CLI (`["prettier", …]`,
`["bunx"|"npx", "prettier", …]`), or invoking it in command position in a shell
string is banned everywhere except its one sanctioned home,
[`tooling/format`](../../../format/CLAUDE.md).

## Why

The build (writer) and the `*-in-sync` / `format-clean` checks (readers) must
emit byte-identical output. That holds only because ONE module owns the
allowlist and the hardcoded options object — a second call site with its own
options, its own `resolveConfig()` walk, or its own file-type predicate breaks
it by construction. A spawned CLI also costs ~500 ms per invocation on a path
that formats one file per emit site, and a *static* import hoists above
`ensureDeps()`, resolving out of the very `node_modules` it exists to repair.

Detection is command-position anchored (argv-array shape for spawns; `prettier`
at the start of a string or right after a shell separator, followed by
whitespace). The trailing whitespace requirement is what lets the rule name its
own banned token: a bare `"prettier"` string — needed by the module-name and
argv checks — does not match, while `prettier --write .` does. So neither the
rule nor its `RuleTester` test needs an allowlist entry.
