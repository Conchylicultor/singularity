# repo-walk-safety

Contributes `no-adhoc-repo-walk`: a hand-written list of build-output directory
names — `"node_modules"` alongside `"dist"` / `".git"` / `".cache"` — in an array
or `new Set([...])` is banned outside the allowlist in [`lint/index.ts`](lint/index.ts).

## Why

Such a list is a guess at what `.gitignore` already states exactly, and it is
always missing one. `type-check` held two copies that both omitted `.cache/` —
the gitignored directory it writes its own `.tsbuildinfo` into — so a `.ts` left
there counted as source and failed the coverage gate. Ask git: `listRepoFiles`
([`checks/core/repo-files.ts`](../../../checks/core/repo-files.ts)) returns
tracked + untracked-not-ignored, the same universe the check runner's tree hash
uses.

## The allowlist has two kinds of entry

- **Bounded walks of a known subtree** (`ensure-deps`, `global-css`) skip
  `node_modules` because descending is pointless, not to define "source". Legal.
- **`boundaries/core/check.ts` still has the bug.** It is one `listRepoFiles`
  call away but needs its own review. Tracked as a separate task — don't read
  that entry as blessing the pattern.
