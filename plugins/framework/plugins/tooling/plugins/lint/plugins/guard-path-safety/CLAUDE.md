# guard-path-safety

One repo-wide ESLint rule holding a single invariant over the PreToolUse guards:
**a guard does not construct a filesystem path itself.** Every path a guard
compares comes out of [`guards/core/argv.ts`](../../../guards/core/argv.ts),
which owns the per-command operand grammar and folds in `call.cwd`.

## `no-adhoc-path-resolve`

Inside `guards/core/guards/**`, a VALUE import from `node:path` (or bare `path`)
is an error — named, default, or namespace. `import type` is fine; naming a path
type costs nothing, only holding the constructor does. `require("path")` /
dynamic import are out of scope (the `no-adhoc-import-scan` convention).

Self-limits by filename in-rule (the `no-adhoc-check-runner` precedent), because
contributed rules are enabled repo-wide over `**/*.{ts,tsx}`. The fence stops at
`core/guards/` — `core/argv.ts` is one level up and is exactly the file allowed
to build a path.

**Why this rule and not the obvious one.** Keying on `.args.filter(` would be
more allowlist than rule: five guards read `call.args` legitimately for non-path
reasons (flag clusters, `find`'s `-prune`, a git subcommand). Banning the
constructor is the tight, syntactic way to say "a guard does not build a path".
No rung-1 fix exists — `.args` must stay `string[]` for those guards — so lint is
the strongest rung available. Background:
`research/2026-08-19-tooling-guard-argv-operand-grammar.md`.

## Exemptions

Three production files, in the barrel's `ignores`. Each has to clear one bar:
the path it builds provably never came from a command's arguments, so the
guessed-operand failure this rule exists to close cannot occur there. That is a
property you can check, not a judgement call — a new guard that wants a path out
of a *command* does not qualify, however inconvenient, and belongs in
`core/argv.ts` instead.

- `main-edits.ts` guards the **Write/Edit tools**, not Bash. Its input is a tool
  payload with a declared `file_path` — no shell operands at all, so there is no
  grammar for `core/argv.ts` to apply and nothing for it to hand back.
- `git-diff-main.ts` composes its own once-per-session marker file from
  `ctx.cwd` — the guard's private bookkeeping, not a path it compares a command
  against.
- `poll-loop.ts` does the same for its per-session state file under `tmpdir()`.

Plus `**/*.test.ts(x)`, where a fixture path is scaffolding. (Contributed rules
are already off in `NON_APP_FILE_GLOBS`; the entry keeps the exemption true if
this rule is ever opted into `enforceEverywhere`.)
