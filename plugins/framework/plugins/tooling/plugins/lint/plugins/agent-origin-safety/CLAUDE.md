# agent-origin-safety

`no-unmarked-app-fetch` — in `e2e/`, call the app under test through
`agentFetch`, not a bare `fetch`.

`withBrowser` stamps the agent-origin headers on the browser CONTEXT, which
covers everything the page issues but cannot cover a request the script makes
from Node. Unmarked, the writes it causes are invisible to the cleanup: a page
it creates is never swept, a config document it writes is not in the revert
ledger and stays changed in the user's config. The script still goes green.

**Absolute vs relative is the discriminator, not style.** `` fetch(`${base}/api/…`) ``
runs in Node and is the hole; `fetch("/api/…")` inside `page.evaluate` runs in
the browser and is already marked — flagging it would be wrong, and there is no
`agentFetch` in the page to migrate it to.

`enforceEverywhere` (contributed rules are off in `e2e/` by default) on the same
grounds as `route-teardown-safety`: it catches a bug with a silent failure mode,
and the remedy lives in the e2e-harness's own `e2e` barrel, which every e2e file
may import. The rule then scopes itself to `/e2e/` by filename — repo-wide is
how it reaches e2e at all, not a claim about server or web code.
