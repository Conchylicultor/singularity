# route-teardown-safety

Contributes the repo-wide `no-unroute` ESLint rule: a Playwright route may not be
torn down while a handler might still be running.

`page.unroute()` does not wait for handlers already in flight. When it removes the
last handler, Playwright clears the network-interception patterns, which continues
any paused request **right then** — so a stall meant to hold the server for four
seconds ends whenever the script reached its teardown, and the sleeping handler's
eventual `route.continue()` throws `Route is already handled!` into a promise with
nowhere to land. A script built on that shape reports success while measuring an
overlay it never made the server confirm.

Use [`stallRoute`](../../../../e2e-harness/e2e/stall.ts) from the e2e-harness
`e2e` barrel instead: the stall ends on a signal (an elapsed timer, or an explicit
`release()`), and the handler that continues the route is the one that paused it,
so there is no teardown to race. `unrouteAll()` is allowed only with an explicit
`behavior` — `'wait'` drains running handlers, `'ignoreErrors'` abandons them; the
default does neither.

The rule is in `enforceEverywhere` because it catches a bug rather than an
architecture deviation, and because its remedy lives in an `e2e` barrel that e2e
files may legally import — the two things the `NON_APP_FILE_GLOBS` exemption exists
to respect. There is no `ignores` allowlist: `stallRoute` never unroutes, so
nothing needs one.
