# space-ramp-in-sync

Fails if
`plugins/primitives/plugins/css/plugins/space-ramp/core/ramp.generated.ts` drifts
from the `/* @ramp … */` declarations in
`plugins/primitives/plugins/css/plugins/ui-kit/web/theme/app.css`.

app.css is the **single source of truth** for the spacing ramp, because it is
where the 112 step-keyed `@utility` classes actually exist. The step set and every
family's literal class table are **generated** from it, mirroring
`app-css-utilities-in-sync` (same manifest pattern, same app.css parser).

The check re-runs the generator in-memory (`renderSpaceRamp(root)`) and
string-compares it to the committed file. A thrown **declaration-validation**
error is reported as a check failure, not a crash:

- a missing, duplicated or empty `@ramp` declaration;
- **a declared family missing a declared step** — the load-bearing one. Every
  family named in `/* @ramp families: … */` must carry every step named in
  `/* @ramp steps: … */`, so a step cannot reach the TypeScript union without the
  CSS that backs it, and a rename that lands in 13 of 14 families is loud.

The reverse direction is deliberately not checked: `p-chip`, `p-control`, `p-row`
and `p-card` are legitimate non-ramp members of the `p` prefix.
