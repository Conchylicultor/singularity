# no-raw-sse

## It bans SSE *writers*, not the *string*

The scan greps the raw token (`maskStrings: false` — it legitimately lives in
string literals), so it needs one carve-out: an **`Accept` header** says the
caller can RECEIVE a stream, the inverse of sending one. Don't remove it — the
MCP transport 406s unless a caller accepts both `application/json` and
`text/event-stream` (`enableJsonResponse` included), so without it no TS could
call our own `/api/mcp/*`.

A shape, not a path — default-deny still holds everywhere else. Line-scoped, so
a header split across lines fails loudly; join the line.
