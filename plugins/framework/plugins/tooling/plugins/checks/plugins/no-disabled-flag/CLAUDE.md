# no-disabled-flag

No plugin `package.json` may carry `singularity.disabled`.

The flag used to be one of two mechanisms answering "is this plugin in the app?".
It is gone: codegen no longer reads it, `PluginNode` no longer carries it, and a
plugin leaves the app by being negated out of the `base-exclusions` composition
row (`plugins/plugin-meta/plugins/composition/core/config.ts`), whose negatives
every composition inherits.

Without this check a re-added flag would be **silently inert** — the file would
say the plugin is off while every registry still shipped it. The check turns that
into a message naming the exact replacement, `"!<plugin.id>.**"`, for each
offending file.

Discovery goes through `listCandidateSources` (untracked-aware), because the file
most likely to carry a stale flag is a brand-new plugin's not-yet-committed
`package.json`.
