# host-budget

Bounds how many holders host admission can hand out at once:

```
Σ (every pool's size in HOST_POOLS) + B  ≤  hostCpuCeiling() × MAX_OVERSUBSCRIPTION
```

with `MAX_OVERSUBSCRIPTION = 2`. Today that reads `13 + 9 = 22 ≤ 36` — passing
with room, and a pool declared at `size: 50` trips it. Sizes are read from
`host-admission/core`'s `HOST_POOLS` table, never by importing server pool code.

**This is a stampede bar, not a model of the box.** Do not read the `× 2` as
"two threads per core": most admitted holders are not CPU-saturating (heavy-read
and worktree-mutate are IO-bound, push waits on git and the network), and the
box runs far more work that is never admitted at all — ~16 backends, agent
sessions, editors — than work that is. A number claiming to schedule cores here
would be false precision. What the bound genuinely catches is an
obviously-wrong size that nothing else would notice.

Until 2026-09-09 the check asserted something stronger-looking: that the summed
CPU *cost* of every pool plus the residual `B` fit under `hostCpuCeiling()`, and
that `B` stayed `≥ 1`. Both halves are now true by construction. Pools declare
no cost — a size is a cardinality cap, nothing is reserved — and `B` is computed
from host facts alone, so nothing a pool declares can push it anywhere; the only
way the pre-floor `rawFleetCeiling()` falls below 1 is a host with less than one
worker's worth of RAM, which is "this box is smaller than one worker", not an
overcommit, and which `cpuBudget()`'s `max(1, …)` floor already handles.

The check is repointed rather than deleted because the structural bar would
otherwise get weaker, not simpler. `host-pools-declared` keeps
`createHostSemaphore` from being imported outside `host-admission`, but with
this check gone nothing at all would stand between a `size: 50` pool and the
box. Keeping the id also keeps the call-site comments that name it correct. See
[`research/2026-09-09-global-host-pools-stop-reserving-cpu.md`](../../../../../../../../research/2026-09-09-global-host-pools-stop-reserving-cpu.md)
§4.
