# no-gitlinks

Fails if the repo would commit a **gitlink** — an index entry of mode `160000`
that records a directory as "commit X of another repository" instead of as
content. The repo has no submodules and no `.gitmodules`, so every gitlink is a
checkout swept in by accident. There is no allowlist. Adopting a real submodule
would be a deliberate decision that revisits this check.

It catches the two ways one gets in:

- **Already tracked** — `git ls-files --stage` has a `160000` entry. A push
  commits first and checks the rebased result, so at push time this is exactly
  "the commit about to land on main carries a gitlink".
- **About to be swept in** — an untracked, un-ignored directory holds its own
  repository (a clone, `git init`, or `git worktree add` target). `git add -A`,
  which is how `./singularity push -m` stages, records it as a gitlink and only
  prints a warning. This arm fires at `build` / `./singularity check`, before
  anything is committed.

Why a check and not a guard on the staging step: git has no setting that makes
`git add` refuse an embedded repository. There are also several staging sites
(push's commit, the generated-artifact amend, a raw commit, `--from-main`), and
one check covers every one of them.

`.gitignore` is not enough on its own: it never applies to a path that is
already tracked. Background:
[`research/2026-09-10-global-stray-worktree-gitlink.md`](../../../../../../../research/2026-09-10-global-stray-worktree-gitlink.md).
