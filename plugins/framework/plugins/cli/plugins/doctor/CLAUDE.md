# doctor

Names **every** missing prerequisite of a dev checkout in one run, each with the
command that fixes it — instead of each one surfacing on its own, several only
minutes into a build (the clean-VM install of 2026-09-18 met them one at a time).

`doctor.sh` is the check, and the only copy of it. POSIX sh because its most
important case is Bun itself missing. It runs from the checkout it checks (cwd):

| who runs it | when |
|---|---|
| `mise run doctor` (`[tasks.doctor]` in `mise.toml`) | by hand, and at the end of every `mise install` (the `postinstall` hook) |
| `assertPrerequisites()` (`cli/`) | first step of `./singularity start` and a deploying `build` — not `--hermetic`, not the release launcher: a bundle needs no dev toolchain |
| the `./singularity` wrapper | when `bun` is not on PATH, before failing |

What it checks: not root; Xcode command-line tools (macOS) and a working git;
mise installed and active in the shell (`MISE_SHELL` set, or its shims on PATH —
tool install dirs on PATH do not count, since `mise run` adds them itself); the
locked toolchain installed (`mise install --dry-run-code`, tools named by
`mise ls --missing`); Claude Code installed (same lookup as `resolveClaudeBin()` in
`infra/paths/server/internal/bins.ts`, kept in step by `doctor.test.ts`) and
signed in (`claude auth status --json`).

It asks only "is it there". Which release — floors, holds, something shadowing
mise — is `toolchain:resolved`'s job (`plugins/toolchain`). The tool list is
mise's, read from `mise.toml` + `mise.lock`, so adding a tool there needs no
change here.

The running app asks the Claude Code half again on its own — sign-outs and
uninstalls happen between builds — through `infra/claude-cli/plugins/availability`
(the health report's Claude Code row, and a refusal with the fix before any
launch).

Git hooks are not checked: mise's `setup` task sets `core.hooksPath` on every
`mise install`.
