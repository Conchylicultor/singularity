# build

`./singularity build` — the command the agent workflow runs on. It takes this
checkout from source to a running app at `http://<worktree>.localhost:9000`.

## The two postures

One pipeline (`cli/internal/app-artifacts.ts`), two ways to run it:

- **Deploy** (the default) — codegen, migrations, the web dist, the backend
  restart, the gateway registration, the deploy receipt. Everything about the
  live dev cluster.
- **Hermetic** (`--hermetic --composition <name>`) — produce those compositions'
  artifact sets and touch no cluster at all: no Postgres, no DB fork, no
  gateway, no run ledger. This is the phase `release` shells into, which is why
  it must run on a bare host from a fresh `git clone`.

The posture branch is the **literal first statement** of `cli/run.ts`, ahead of
`markBuildInProgress` and every other arming call. That is what makes the
hermetic path's emptiness structural rather than a claim maintained by ~20
scattered `if (!hermetic)` guards — and it is what lets stage 2's exit 2
(drizzle prompt) and exit 1 (missing `--migration-name`) reach `release`
unrewritten and unburied.

## Layout

- `cli/index.ts` — the data-only declaration: name, description, and the ten
  flags, in commander's own syntax. Loads on **every** `./singularity`
  invocation, so it may reach no npm package and no `web`/`server` barrel
  (`cli:command-declarations-light`).
- `cli/run.ts` — the action, reached through the declaration's lazy
  `import("./run")`. This is where `pg`, the plugin server barrels and the whole
  build pipeline load, i.e. only when `build` is the command actually running.
- `cli/internal/` — build-private machinery, reached from nowhere else in the
  repo: the shared artifact pipeline (`app-artifacts`), target resolution
  (`build-targets`), the deploy half (`deploy-namespace`), the atomic dist
  publish + leftover sweep (`dist-publish`), the hermetic driver
  (`hermetic-build`), the experimental marker, and the legacy in-checkout dist
  reaper.

`build` is deliberately **not** `detachable`: the orphan guard exiting it when
its invoking shell dies is what stops an abandoned build from sitting on the
build lock and a host grant. The detached self-restart build exempts itself
through `SINGULARITY_BUILD_DETACHED` instead.

`pg` is a dependency of this plugin rather than of the CLI host, because
`cli/run.ts` is its only importer here (`databaseReady` and `waitForPg` both
`await import("pg")`).
