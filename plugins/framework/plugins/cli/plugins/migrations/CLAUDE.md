# migrations

Drizzle migration generation for the CLI: the generate / rename / journal
pipeline (`migrations.ts`) and the interactive drizzle-kit prompt driver
(`migrations-interactive.ts`) that answers its rename-vs-create questions.

Three commands need it — `build` (which generates a migration as a build stage),
`regen-migrations` (that stage standalone, for the post-rebase normalize path),
and `build`'s hermetic artifact stages. Once each is its own sub-plugin, none of
them can reach the host's `bin/`, which is why this is a plugin rather than two
files beside the commands.

`migrations.ts` re-exports the interactive module's answer types, so a caller
naming a `MigrationAnswer` need not know which of the two files defines it. That
is a same-plugin re-export and stays legal; the barrel surfaces no other
plugin's names.

Never run `drizzle-kit generate` or the migration runner by hand — always go
through `./singularity build`.
