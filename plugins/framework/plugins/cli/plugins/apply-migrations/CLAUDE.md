# apply-migrations

`./singularity apply-migrations` — apply pending SQL migrations to one
namespace's database: `--namespace <ns>`, or, with no flag, the namespace this
checkout owns (`checkoutNamespace(REPO_ROOT)`, minted from git).

One caller: the fresh-clone bootstrap (mise `setup`), which needs the base
`singularity` DB to exist and be migrated *before* the first build. Every other
path gets migrations for free — the server runs them itself on boot — so
reaching for this command anywhere else is a sign the boot path is being worked
around.

## Why it opens its own connection

It does not import `db` from `@plugins/database/server`: that barrel's worktree
pool is scoped to the process's RUNTIME namespace, which a CLI process does not
have — and which would be the wrong question here anyway, since which namespace
to migrate is this command's argument. Instead it dials
Postgres directly with `pg` + `drizzle-orm`, the same shape the migration
tooling uses (`plugins/database/plugins/migrations/{drizzle.config.ts,check/*}`),
skipping pgbouncer because bootstrap connects straight to Postgres.

`pg` is declared on THIS plugin rather than on the framework CLI host: it is
reached only through `cli/index.ts`'s lazy `import("./run")`, so no other
command pays for a Postgres driver it never touches.
