# db

`./singularity db` — worktree database operations. A command GROUP: it routes,
and the declaration union makes "also runs" unspellable, so bare `db` prints its
subcommand help by construction.

## `db fork`

Forks the main `singularity` database into `[target]` (default: this worktree's
name). It exists for checkouts made with a bare `git worktree add`, outside
Singularity — those get no fork on creation, so they come up with no database at
all. Idempotent: a no-op when the DB already exists.

The interesting part is what it *refuses* to do. Which tables a fork must not
copy is declared by the plugins that own them and collected at server boot, and
a CLI process never boots the server. So `fork.ts` asks a backend that has: this
checkout's own first (the exclusion set is a function of the code, so only that
backend can answer for this checkout), then main's (the one backend a brand-new
worktree can count on). If neither answers it fails loudly rather than forking
with an empty exclusion set — that would copy every debug table and quietly hand
back a ~1 GB database full of main's traces.

`cli/index.ts` is the data-only declaration; `cli/fork.ts` is the implementation
behind its lazy `import()`, and it is the half that reaches
`@plugins/database/plugins/admin/server`. Adding a second operation (drop, list,
backup — `database/plugins/admin/server` already exports them) is a file beside
`fork.ts` plus one entry in `subcommands`.
