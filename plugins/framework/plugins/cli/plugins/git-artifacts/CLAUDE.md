# git-artifacts

The half of the generated-artifact merge contract that **runs inside a CLI
command**.

`.gitattributes` routes every generated file to a merge driver that does the
cheap thing — take the upstream side, drop a marker — because the file is a pure
function of sources git just merged correctly. `normalize-generated` is the
other half: re-derive from the merged tree, amend, consume the marker.
`register-merge-drivers` installs the drivers themselves.

Three commands need it: `push` (around its own rebase, with the `post-rewrite`
hook suppressed), `build` (which reaches the same state by regenerating
everything and clearing the markers), and the `normalize-generated` command the
hook invokes.

## What deliberately stays in `cli/core`

The marker names, git-dir resolution and conflict scan live in
`@plugins/framework/plugins/cli/core`, not here. The OTHER side of the contract
is a check — `tooling/…/generated-artifacts-normalized` — which has to read the
same facts, and a check may not import a `cli/` barrel. `core` is the one runtime
both can reach.
