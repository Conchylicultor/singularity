# stop

`./singularity stop` — stop the gateway daemon, and with it every backend it
supervises (Postgres and PgBouncer keep running as their own daemons, as they do
across any gateway restart).

On macOS the gateway is a launchd LaunchAgent (`./singularity start`) with
`KeepAlive`, so `kill <pid>` of a gateway that exits non-zero is followed by a
relaunch — a stop has to go through launchd: `launchctl bootout`. The plist stays
in `~/Library/LaunchAgents`, so the next login starts the gateway again;
`--disable` deletes it too. A gateway no service manager owns (another OS, or
one started before `start` registered with launchd) is SIGTERMed via its
pidfile. Either way the command waits for the process to be gone.

A system-level operation like `start`: agents never run it.
