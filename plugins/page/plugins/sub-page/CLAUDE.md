# sub-page

## An expanded special-kind page is a card

A page whose kind is not ordinary (`pageKindOf`: an agent-authored page, an
instructions page) is, while expanded inline, a CONTAINER: an `Editor.BlockFrame`
with `applies: isPageCard` groups its row and its whole content under one box,
painted with the tint its `PageReference.Decoration` gives the reference row. Its
content is that kind's — the agent's words, the human's instructions — so a wash
stopping at the title line would let the expanded lines read as the parent
page's own prose.

- **One predicate, two readers** (`web/internal/page-card.ts`): the frame's
  `applies`, and the row, which drops its own fill while the box paints it (kept,
  the title line is washed twice). It keeps the tint's `--scrim`, since `cn`
  merges only the fill away.
- **Collapsed is unchanged** — the row is a plain reference with its own tint.
  **An ordinary page is never a card**, so expanding one moves nothing.
- The kind test reads the closed `PageKind` set `page/editor` owns; the LOOK stays
  with each kind's decoration, so this plugin names no kind.

## Plugin reference

- Description: Sub-page block type: renders a child page inline in its parent's content flow as a clickable Notion-style page row. A void, text-less block — selectable and arrow-navigable, but Enter/Backspace can never originate in it. A page of a special kind (agent-authored, instructions) expanded inline is drawn as a card: its reference's tint washes the row and all of its content.
