# page/map

The `/map` block. It draws every overlay the `PageMap.Layer` contributions
derive from this page's blocks, on the vendor-neutral `MapView` (`plugins/map`).
It names no block type and no map vendor.

- **Nothing is stored** (`data` is `{}`, markdown `<map/>`). Overlays are
  recomputed from `useBlockEditor().blocks` on every render: the flat,
  optimistic list, including collapsed children. Only rows with the map block's
  own `pageId` count, so inline-expanded sub-pages stay off this page's map.
- **`PageMap.Layer`** = `{ id, overlays(blocks) → { overlays, unplaced },
  describeUnplaced(n), emptyHint? }`. It is a pure function, so it needs no
  hooks. `unplaced` counts items the layer owns but cannot draw (no coordinates).
  The block prints `describeUnplaced(n)` under the map instead of dropping them
  silently. Overlay ids are namespaced `<layer>:<id>` by `derivePageMap`, and a
  layer's `blockId` is how a pin click finds its block.
- **Pin click**: marks the pin active, then scrolls to the block's row (via
  `blockContentScope`, never `document`) and selects it with
  `useSelectionControl`. A block inside a collapsed toggle has no row, so the
  pin only turns active.
- Read-only surfaces (version-history preview) still render the generic
  placeholder. A read-only map needs a page-forest context that `read-only-view`
  does not provide.
