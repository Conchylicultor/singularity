# inline-page-link

## The token is NAMESPACED, so the id inside it stays opaque

Stored in `data.text` as `[[page:<pageId>]]` (`core/tokens.ts`, the single
source of truth; same shape as `inline-date`'s `[[date:<iso>]]`). The `page:`
prefix is the entire disambiguator against arbitrary `[[…]]` text a user might
type — which is what lets the id body carry **no shape constraint**. A block id
is an opaque key (`editor/core/block-id.ts`: "Nothing parses this format, and
nothing may start"); the retired pattern destructured one into
`block-<epochMillis>-<base36>`, so when the mint moved to `block-<uuid>` every
link silently stopped parsing — no chip on re-parse, no backlinks edge.

- **Group 2 is read-only compatibility** for the pre-namespace form; nothing
  mints it, and readers take `m[1] ?? m[2]!`. Do not widen it to uuids to
  rescue pre-namespace uuid-bodied tokens — that is the defect, re-admitted.
- **A fixture may never hand-write an id.** `core/tokens.test.ts` pins the
  pattern to `pageLinkToken(newBlockId())`; hand-written literals are why the
  break shipped green. No migration: the next edit to a block re-serializes its
  decorator node into the new form and reindex heals its backlinks.

`active-data/page-link` is the bare-id-in-prose twin — no delimiter, so no
namespace can help it and it genuinely parses shape, pinned the same way.

## This plugin owns BOTH renderings of its token

The Lexical decorator (`web/components/page-link-inline-node.tsx`) and the
static chip (`web/components/page-link-chip.tsx`) are two renderings of one
declaration, and the registration in `web/internal/register.tsx` carries both —
the node for the editor, `renderToken` for every surface that mounts no Lexical
(page history, version diffs, the public site).

`page/read-only-view` used to own that chip and to name this token type by hand.
It named `page/math/inline` by hand too, and those two by hand were the whole of
its token support — which is why `[[date:…]]` rendered as literal brackets
everywhere, for as long as inline dates existed. Nothing failed, so nothing said
so. Now the read surface walks the registry and names no family at all, which is
what makes the omission unspellable: `renderToken` sits on the same
discriminated arm as `node`, so a family that can appear in a document and
cannot paint itself outside Lexical is a tsc error.
