# instructions-page

The **page** form of [`instructions`](../../CLAUDE.md): a sub-page a person writes
as standing instructions to every agent working under its PARENT page — a
`CLAUDE.md` sitting in a folder. What the user sees:

- in the parent page, an ordinary sub-page row tinted with the inline
  `<instructions>` card's `primary` wash, even collapsed;
- at that row's right edge, a **Global** chip when the page reaches every
  conversation at its start (nothing otherwise — the tint already says
  "instructions");
- the same tint on the page's row in the Pages sidebar;
- `/instructions page` (and the gutter `+`) turns the caret's line into one, its
  other words becoming the title; the page header's kind control
  ([`apps/pages/page-author`](../../../../../../../apps/plugins/pages/plugins/page-author/CLAUDE.md))
  turns any page into one, and holds the Global switch.

## Not a block type, and web-only

An instructions page is a `page` row whose data says `instructions: true`
(`PageDataSchema`, `page/editor/core`), exactly as an agent-authored page is one
whose data says `author: "agent"`. So this plugin declares no block type and has
no `core`/`server` half. Everything that reads the kind reads it off the row:

- **markdown** — `pageBlockMarkdown`'s `<instructions-page id title global/>`
  spelling. It is `pointerOnly`: a parse without the `id` is refused loudly, so an
  agent can echo an existing pointer back while editing the page around it, and
  can never mint one. Minting would be refused by the write policy anyway (below),
  but the parse refusal says why before any plan is built.
- **authorship** — `pageBlockAuthor.authorFromData` answers `"human"` for an
  instructions page, explicitly, where an ordinary page answers nothing. The write
  walk stops at the nearest row that declares anything, so this keeps an
  instructions page nested inside an agent page closed to that agent.
- **kind changes** — `setPageKind` only. `rewriteBlockData` refuses a data write
  whose markdown spelling differs from the stored row's, which covers turning a
  page into (or out of) an instructions page by data.

It contributes to two generic seams and names nothing else:

- **`PageReference.Decoration`** — `applies` reads `instructions === true`; the
  chip reads the page's kind off the live pages list, waiting as a shimmer rather
  than claiming "not global" while the list loads.
- **`Editor.InsertAction`** — `/instructions page`, listed right after the inline
  card (`after: instructionsBlock.type`). It calls turn-into-page with
  `kind: { kind: "instructions", global: false }`.
