# divider

## The divider declares where its caret lives, and writes no caret code

A divider owns no editable text, so nothing on screen blinks to say the caret is
on it. It answers that with one field on its `Editor.Block` registration —
`caret: "editor"` — and the editor mounts its caret host around this renderer.

Everything a void block needs then comes from the host: it is focusable, it
paints the "the caret is on this block" cue, ↑/↓ leave it, Backspace deletes the
block, and Enter starts a paragraph below. The component is a `<hr>` in an
`<Inset x={BLOCK_INSET} y="sm">` and nothing more.

This used to be hand-written here — the divider carried its own Backspace and
Enter, and its own focus cue drawn on `isFocused` while the browser's outline was
suppressed unconditionally, so a box that genuinely had keyboard focus while the
editor's model disagreed showed nothing at all. Those are the editor's meanings
for *every* void block, so they moved to the editor. If a divider ever needs a
keyboard behaviour of its own again, that is the signal it is no longer a plain
rule — not a reason to re-add a local `onKeyDown`.
