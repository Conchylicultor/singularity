# place

## The card's circle: glyph from a neutral `kind`, colour from a `family`

The resolved card is one row: a coloured circle, the name, and
`category · address`. Both halves of the circle are neutral vocabulary owned
here (`core/kinds.ts`), mapped by the provider so its own taxonomy never
reaches block data:

- **Glyph ← `data.kind`** (clothing, café, museum, …). Glyphs are in
  `web/internal/kind-glyphs.ts`; Google's types map onto kinds in
  `plugins/google/server/internal/type-to-kind.ts`. To add a kind, add it to
  `PLACE_KINDS` and add its glyph (tsc fails until both exist), then map the
  provider types that should produce it.
- **Colour ← `data.family`**, one per heading of Google's place-type Table A
  (shopping, food, lodging, culture, …). The taxonomy is Google's; the names
  are ours. The Google provider carries a generated copy of Table A
  (`plugins/google/server/internal/table-a.ts`). Each family is painted with
  its own theme token, `--place-<family>`, from the `place` token group
  (`plugins/ui/plugins/tokens/plugins/place-palette`) — not the categorical
  slots other avatars use — whose defaults are the pin colours sampled from
  the Google Maps app, so a place reads the same as on the map. The card hands
  it to `Avatar` as `fill`.

Both are optional: an unmapped type, or a snapshot stored before the field
existed, draws a generic pin / neutral circle until the next refresh.

## Plugin reference

- Sub-plugins:
