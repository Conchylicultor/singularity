# place

## The card's icon is a neutral `kind`, mapped by the provider

The resolved card is one row: a coloured circle, the name, and
`category · address`. The circle's glyph and colour come from `data.kind`, a
closed set owned here (`core/kinds.ts`: kind → family, family → avatar palette
colour). The glyphs are in `web/internal/kind-glyphs.ts`. A provider never stores
its own taxonomy: Google's `primaryType`/`types` are mapped onto a kind in
`plugins/google/server/internal/type-to-kind.ts`, and only the kind reaches the
block. `kind` is optional, so an unmapped type, or a snapshot stored before kinds
existed, draws a grey pin until the next refresh.

To add a kind, add a row to `PLACE_KINDS` and add its glyph. tsc fails until
both exist. Then map the provider types that should produce it.

## Plugin reference

- Description: Place block type: search an address or business through a registered place provider and render it as a card (name, address, category, link out to the provider's map). Owns the Place.Provider registry, so the block names no provider. Place block server half: the definePlaceProvider registry plus the two provider-agnostic lookup endpoints (search, resolve), which dispatch by `providerId` and name no provider. Also registers the place `data` schema at the server write boundary.
