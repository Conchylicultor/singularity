# google

## Table A: the family of a place

A place's family (its card colour) is the heading Google files its
`primaryType` under in Table A
(https://developers.google.com/maps/documentation/places/web-service/place-types).
No API returns or lists those headings, so `server/internal/table-a.ts` is a
copy, GENERATED by `scripts/fetch-table-a.ts` — never edit it by hand:

```
./singularity run plugins/page/plugins/place/plugins/google/scripts/fetch-table-a.ts
```

When Google returns a `primaryType` in neither table, the place still resolves
(neutral circle) and a `place-google-unknown-type` warning report names the
type: rerun the script. A heading Google adds fails the script until it is
added to `GOOGLE_HEADINGS` (`server/internal/google-headings.ts`) and mapped to
a family (tsc enforces the mapping).

Where a heading paints a type unlike the Google Maps app, a short
`GOOGLE_FAMILY_OVERRIDES` (`server/internal/type-to-family.ts`) wins: parks and
gardens, which Google files under "Entertainment and Recreation", are `nature`
(green, as in the app). Keep it short; everything else follows the heading.

## Plugin reference

- Description: Google Maps as a place-lookup source for the /place block: contributes the provider's name, icon, and the 'set up Google Maps' affordance the block renders while no API key is configured. Google Places provider for the /place block: adapts the Places API client (autocomplete + details) onto the place-provider registry, reading the API key through the Google Maps integration. Colours a place by the Table A heading of its type (a vendored copy of Google's place-type table), filing a place-google-unknown-type report when Google returns a type the copy lacks.

  - Contributes: `Place.Provider` "Google Maps"

    - `integrations/google-maps.MapsAccessAction`

  - Contributes: `report-kind` "place-google-unknown-type"
  - Uses:

    - `reports.recordReport`
    - `reports.ReportKind`
    - `reports.ReportRow`
