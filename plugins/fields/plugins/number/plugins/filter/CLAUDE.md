# number / filter

The **number** type's `data-view.filter` capability.

Contributes `DataViewSlots.Filter({ match: "number", domain: "number", ... })`
— `=` `≠` `>` `<` `≥` `≤` (one numeric input) lowering to the filter language's
`eq` `ne` `gt` `lt` `gte` `lte`, `between` (a min/max pair, either bound open)
lowering to `and(gte, lte)` or the one bound given, and `is empty` / `is not
empty`. A non-finite / absent operand, or `between` with no bound, lowers to
`undefined` (incomplete). `≠` is the complement of `=`, so it KEEPS a row with no
value (it used to drop it — the decided change of
`research/2026-09-25-global-unified-filter-language.md`). Lowerings live in
`web/internal/number-lower.ts`, pinned by `number-lower.test.ts`. Derived numeric
types (e.g. `int`) reuse this set via the `extends`-chain fallback.
