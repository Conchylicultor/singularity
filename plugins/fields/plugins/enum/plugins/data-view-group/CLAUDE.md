# enum / data-view-group

The **enum** type's `data-view.grouping` capability.

Contributes `DataViewSlots.Grouping({ match: "enum", label: "Group by", groupings })`
— the one way an enum field buckets: a section per distinct value.

This behaviour used to live inside data-view itself (`sectionLabel` and the
`field.options` ordering block in `use-data-view-sections.ts`, both branching on
`field.type === "enum"`). It is preserved here exactly, and data-view now names
no field type:

- **key** — `String(value)`.
- **label** — the matching `field.options` entry's `label`, falling back to the
  stringified value. `field.options` is the ONE choice-list contract, so a
  user-authored custom column shows its option's label and never the opaque
  minted id it stores.
- **order** — the value's index in `field.options`. Values matching no option
  sort **after** every known one and, among themselves, in natural value order.

The type offers a **single** grouping, so the view-settings popover shows only
the field picker for enum fields — the granularity band appears when a type
offers more than one.

The unknown values are ranked with `compareValues` from
`@plugins/primitives/plugins/data-view/core` — data-view's own single definition
of `FieldValue` ordering, shared with the identity grouping. Never hand-roll a
second comparator here: this migration's whole point is that ordering did not
change, and two comparators are two answers waiting to diverge.
