# json / storage

The **json** type's storage capability: contributes `Fields.Storage({ type,
decode })` (server runtime), so it is handed the FIELD's own schema and builds
the `jsonb` column from it. Resolved by exact token through
`resolveFieldStorage("json")`.

That is what makes `jsonField<T>({ schema })` true rather than asserted. `T` used
to come from `defineEntity`'s `EntityColumns` cast and from nothing that ran:
Postgres genuinely decodes the JSON, so the value was real, but its SHAPE was a
claim about rows nobody checked. Now the schema that declares the shape is the
schema that decodes the column — on every read and every write (`parsedJson`,
`plugins/database/plugins/sql-column`).

Note it **normalizes**: a `z.object` strips undeclared keys in both directions.
Where every key matters, the schema says so (`.passthrough()`, or a `z.record`).

## The one discrimination

```ts
valueSchema instanceof ZodUnknown ? jsonb(name) : parsedJson(name, valueSchema)
```

A `jsonField({ schema: z.unknown() })` keeps a bare `jsonb` column and pays
nothing; anything else gets a real decoder. The branch is on the schema the
author actually wrote — which is the whole design: **the schema is the dial.**

A zod parse costs what the SCHEMA's depth costs, not what the payload's size
costs. The largest jsonb value in the repo (`traces.snapshot`, avg 123 KB)
decodes in 1.7 µs against the 561 µs `JSON.parse` pg already pays, because its
schema is eight scalars plus a `z.record(z.unknown())`. A schema that declines to
describe a payload declines to pay for it. So there is no second opt-in knob —
one could only disagree with the schema.

`ZodAny` is deliberately NOT in the branch: `any` is assignable to every `V`, so
an `instanceof ZodAny` would prove nothing and a `jsonField<Foo>({ schema:
z.any() })` would skip the decoder while declaring `Foo`. It falls through to
`parsedJson`, where `z.any().parse` costs nothing and claims nothing.

`getSQLType()` is `"jsonb"` either way, so adopting the decoder generates no
migration (see `sql-column/CLAUDE.md`). `internal/storage.test.ts` pins both
branches.
