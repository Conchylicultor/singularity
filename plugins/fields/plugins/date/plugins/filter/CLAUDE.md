# date / filter

The **date** type's `data-view.filter` capability.

Contributes `DataViewSlots.Filter({ match: "date", domain: "instant", ... })` —
the full date operator set (`is` / `is before` / `is after` / `is on or before` /
`is on or after` / `is between` / `is within the past` / `is within the next` /
`is empty` / `is not empty`). Each operator `lower`s its rule
(`web/internal/date-lower.ts`, pinned by `date-lower.test.ts`) into the filter
language's `instant` domain, day-granular: an anchor resolves to the start of its
local day and each comparison becomes a half-open ISO-instant range — `is` →
`and(gte dayStart, lt nextDayStart)`, `is before` → `lt dayStart`, `is after` →
`gte nextDayStart`, `on or before` → `lt nextDayStart`, `on or after` →
`gte dayStart`, `between` / `within` → `gte lo` + `lt (hi's next day)`. The upper
bound is therefore the whole day. An empty/invalid operand lowers to `undefined`
(incomplete: keeps every row, not counted).

## Relative anchors

Every scalar operand is a **`DateAnchor`** (`core/internal/date-anchor.ts`), a
JSON-serializable union resolved against `now` *at lowering time* — on the
client, so the filter language never sees a clock:

- `{ kind: "date"; iso }` — an absolute calendar day (the exact-date picker).
- `{ kind: "relative"; unit; amount }` — `now ± amount` units (signed: `<0` ago,
  `>0` from now), e.g. Today / Yesterday / Tomorrow / "3 days ago". A saved
  "due on or before Today" stays correct as the clock advances.

A legacy bare ISO string still resolves as an absolute day (backward compat), so
pre-existing stored operands keep working. `resolveAnchorDay(operand, now?)` is
the single resolver. `now` is a number or a thunk (default `Date.now`); a thunk
is called ONLY for a relative anchor, which is how the lowering reads the
DataView's `ctx.now` lazily — an absolute date records no clock read, so only a
filter with a relative anchor re-lowers at local midnight (`useFilterClock`).
`addUnits` shifts via `Date` setters, so month/year arithmetic and DST stay
calendar-correct.

The value inputs (`web/components/date-filter.tsx`) are a popover-driven anchor
chooser: a Relative section (presets + the custom-relative builder) above an
Exact date `<Calendar>` (`@plugins/primitives/plugins/date-picker/web`).

**The Relative section is not redundant with the calendar** — a calendar can
only express `{kind:"date"}`. Deleting it would drop `{kind:"relative"}` anchors
("3 days ago"), which is the whole point of the union. The calendar emits
`toISODay(d)`, i.e. the bare `yyyy-mm-dd` the lowering resolves through
`resolveAnchorDay`; emitting a full ISO instant instead would silently change
filter semantics. (The lowering runs in the browser for server-delegated
DataViews too — the server receives only absolute instant bounds.)

## Within operators

`is within the past` / `is within the next` take a magnitude operand
`{ unit, amount }` (positive; default `1 week`); the direction is implied by the
operator. `withinRange(operand, "past"|"next", now?)` resolves the inclusive
`[lo, hi]` start-of-day window around today (reading a thunk `now` only for a
complete operand); an empty/invalid operand lowers to `undefined` (incomplete
rule), mirroring the scalar operators.
