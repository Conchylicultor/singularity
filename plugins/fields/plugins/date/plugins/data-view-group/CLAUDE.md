# date / data-view-group

The **date** type's `data-view.grouping` capability.

Contributes `DataViewSlots.Grouping({ match: "date", label: "Group dates by",
groupings })` — the five ways a date field partitions a DataView into sections:

| | |
|---|---|
| **Smart** | relative to today, coarsening with distance — Today, Tomorrow, Later this week, Next week, Later this month, Next month, Later this year, Later, and the mirror image into the past. Fifteen buckets, ordered `−7…+7`. The Gmail reading. |
| **Day / Week / Month / Year** | one fixed granularity, absolute labels, ordered by the bucket's own start instant. |

This is what lets data-view name no field type: the primitive partitions, orders
and renders sections, and the *type* says how its values bucket — the same way
it already declares its cell, its filter, its SQL cast and its value codec.

## The rules the bucket math obeys

- **Local calendar, never UTC.** Every boundary goes through
  `date-picker/core`'s day math (`startOfDay` / `startOfWeek` / `startOfMonth` /
  `addDays` / `addMonths`), whose rule is `Date` setters and never epoch
  arithmetic — so a spring-forward day is still one bucket, and a late evening
  west of Greenwich is not filed under tomorrow.
- **The clock is injected.** `ctx.now` is the only source of "today"; nothing
  here calls `Date.now()`. Beyond testability, the partition runs inside a
  `useMemo`, so a clock read would change the memo key every render.
- **Weeks start Monday** — `WEEK_STARTS_ON`, one constant every week boundary in
  the file derives from, so Smart's week buckets and the Week granularity can
  never disagree about where a week breaks.
- **Smart's ladder is ordered by proximity, not calendar containment.** A date
  next Tuesday that falls in the next month is "Next week", not "Next month" —
  the nearer of two true statements is the informative one.
- **A value that cannot be bucketed answers `null`**, never a minted "None"
  bucket — data-view files that row in its own None section. A catch-all bucket
  would be a second section wearing that name, and its ordinal would have to be
  non-finite: last ascending, first the moment the view's sort flipped.

The bucket math is pure and lives in `core/`, so it is `bun:test`-able next to
its source (`core/internal/date-groupings.test.ts` pins `now` to a local literal
chosen so all fifteen Smart buckets are reachable at once).
