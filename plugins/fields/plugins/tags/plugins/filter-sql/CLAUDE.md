# tags / filter-sql

Server twin of `tags/plugins/filter`'s predicates, over the `jsonb` string array
`tags/plugins/storage` maps to. Without it, a `tags` rule is silently dropped by
server-delegated `compileWhere`.

Two rules that look wrong and are not:

- **The containment operators use the BARE column, not `COALESCE(col,'[]')`.**
  `NULL @> x` is NULL ⇒ row excluded, which is already what the JS predicate
  says for a missing value; COALESCE would only make a GIN index on the column
  unusable. The null branch is ORed back in exactly where JS says *true* for a
  missing value — `does-not-contain` — mirroring `enum`'s `is-not`.
- **`is-empty` / `is-not-empty` wrap the column in a `jsonb_typeof` CASE.**
  `jsonb_array_length` RAISES on a non-array, so a corrupt row would 500 the
  whole query instead of being read as `[]` like JS does. These predicates
  cannot use an index anyway, so the guard is free.

Empty operand → `undefined` (rule dropped), matching the JS predicates'
permissive-on-empty behavior and the `FilterSqlBuilder` contract.
