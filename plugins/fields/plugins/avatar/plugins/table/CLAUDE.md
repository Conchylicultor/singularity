# avatar / table

The **avatar** type's `data-view.cell` capability.

Contributes `DataViewSlots.Cell({ match: "avatar", ..., chip: true })` — a
read-only `AvatarCell` that draws an `Avatar` disc from the field's structured
display projection (`FieldDef.data`), never from its scalar `value`. `chip: true`
makes a list subtitle separate the disc by spacing rather than ` · `. The size
is the ambient `ControlSize` every DataView body already provides.

- **Payload** — `AvatarFieldData = AvatarSpec & { fallbackKey?: string }`.
  `fallbackKey` is render-time only: it seeds the derived colour when `color` is
  null, and never touches the persisted `AvatarSpec`.
- **Assert** — `data` is `unknown` at the cell boundary, so `AvatarCell` checks
  its shape and throws `AvatarCellDataError` on anything else. A wrong payload is
  a crash, never a blank cell.
- **`avatarFieldDef({ id, label, avatar, leading?, visible? })`** — the one typed
  spelling for an avatar DataView field: sets `type: "avatar"` and wires `avatar`
  as `data`, so a wrong payload is a type error at the declaration. Not to be
  confused with `avatarField` in `fields/avatar/plugins/config`, the unrelated
  config_v2 factory.
