# barrel-import

## One import at a time

`importBarrel` admits a single import process-wide (a `createSemaphore(1)` lane).
Barrels import barrels, so the module graph has cycles, and ESM answers a dynamic
`import()` for a module already being evaluated with its *partial* namespace — a
reader that then touches `default` gets `Cannot access 'default' before
initialization`. That only needs two import loops overlapping, and this process
has ~7 of them (the two scoped slot-declaration passes, the docs tree,
`token-group-vars`, `config-origin`, `registrations-paired`, the page checks)
running under the check runner's `Promise.all`. The lane is what makes any pair
of them safe; the second one through finds the ESM cache warm, so it costs
essentially nothing. See `research/2026-08-20-global-slot-naming-witness.md`.

## Each import yields, and is marked

Inside the lane, every import is followed by a macrotask yield. A loop over ~800
barrels used to evaluate them back to back and hold the thread every other check
shares for seconds; yielding inside the lane keeps import order intact.

Each import also runs as a `barrel import` thread activity
(`withThreadActivity`, `infra/stack-sampler`), detail = the repo-relative barrel
path. Loading a module leaves no JS frame on most stack samples, so without the
mark the check-thread watch could only call that time `native (anonymous)`.
