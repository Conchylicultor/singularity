# audio-fetch

One YouTube video's audio, downloaded once per machine. Design:
[`research/2026-09-30-infra-audio-analysis-beat-features.md`](../../../../../../research/2026-09-30-infra-audio-analysis-beat-features.md).

```ts
// in a supervised job's run body, or a CLI command (it needs an ExecContext):
const audio = await fetchYouTubeAudio(videoId, exec, { log });
// { path, format: "webm" | "m4a", durationSec, title, channel, ytDlpVersion }
```

- **What it downloads**: `-f bestaudio`, in the container YouTube serves
  (webm/opus, sometimes m4a/aac). No ffmpeg, no post-processing, no fixup.
  Decoding is the consumer's job (PyAV reads both).
- **How**: the parent's `python/` uv project (yt-dlp + yt-dlp-ejs; the
  search runs it too), the on-demand `youtube-audio` dependency (`ytDlpDep`,
  `integrations/youtube/deps`), installed by `ensureDep` on first use.
  `youtube_audio.fetch` runs yt-dlp through its Python API with bun
  (`process.execPath`) as the JavaScript runtime that solves YouTube's
  challenges. Its own project, apart from the audio-analysis one, so the
  frequent yt-dlp bump the `uv` updater makes reinstalls ≈15 MB, never torch.
- **Cache**: `cache/youtube-audio/<videoId>.<ext>` + `<videoId>.json`
  (written last: its presence with the audio is "cached"). A hit touches both
  and returns without Python or a lock. A miss takes the host flock
  `locks/<videoId>.lock`, re-checks, then downloads to a temp name and
  renames — so two worktrees asking for one video download it once.
- **Refused streams are retried.** googlevideo now and then answers a
  freshly signed stream URL's first request with an HTTP 403 (measured
  2026-10-07: 1 in ~70 downloads, never twice in a row on the same video).
  yt-dlp never retries a 403 and keeps the refused URL, so the module
  re-extracts (a new signed URL, often on another CDN node) and tries again:
  up to 3 attempts, 1 s then 3 s apart. Investigation:
  [`research/2026-10-07-integrations-youtube-audio-403.md`](../../../../../../research/2026-10-07-integrations-youtube-audio-403.md).
- **Failure is a document, not a traceback.** The module's stdout is
  `{ ok: true, …audio, attempts }` or
  `{ ok: false, kind, message, detail, attempts }` (exit 0); a non-zero exit is
  a crash (a bug). `failureError` maps the kind:

  | kind | thrown as | whose | retryable |
  |---|---|---|---|
  | `unavailable` (private, removed, age-gated, members-only) | `YouTubeAudioUnavailableError` | the video | no (`NonRetryableError`) |
  | `refused` (still 403 after 3 tries, or another download error) | `YouTubeAudioDownloadError` | the video | yes |
  | `blocked` (bot check, HTTP 429) | `YouTubeAccessError` | the machine | yes |
  | `network` (YouTube unreachable) | `YouTubeAccessError` | the machine | yes |

  Each carries `reason` (one readable line) and `detail` (yt-dlp's own).
  `network` and the 403/429 come from the exception yt-dlp raised;
  `unavailable` and the bot check only from its extractor's English message
  (no exception type tells them apart). `isYouTubeAudioError(err)` answers
  "this video's failure, not the machine's" — what a caller choosing between
  videos (the UG alignment's candidate walk) moves on from; on a
  `YouTubeAccessError` every other video would fail alike.
- **Sweep**: `youtube-audio.sweep`, daily (main only by its schedule). Removes
  a killed download's leftovers, then audio unused for 30 days, then the least
  recently used until the cache is ≤ 2 GB — each under its video's lock, never
  one being downloaded. The choice is `selectEvictions` (pure, unit-tested).

## Traps

- yt-dlp-ejs warns that bun newer than its last tested release is "not
  supported"; it still solves the challenges. Today the default client
  (visionos) needs no challenge at all, so a download rarely runs bun.
- visionos is the only player client that still serves audio without a PO
  token (2026-10-07: `android_vr`, `tv`, `web_safari`, `ios`, `mweb`, `web` all
  answer "Requested format is not available"). If it starts refusing every
  attempt, the next step is a PO-token provider, not a client switch.

## Plugin reference

- Description: YouTube audio download: fetchYouTubeAudio(videoId, exec) returns one video's best audio stream as served (webm/opus or m4a, no ffmpeg), downloaded by yt-dlp — JavaScript challenges solved on bun — from the on-demand `youtube-audio` Python dependency into a host-wide cache under a per-video host flock; a hit is a file read.
