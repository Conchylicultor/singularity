# client-tools

The Postgres client tools the app spawns — `pg_dump` and `pg_restore` — built from the **same Postgres release as the embedded server** and installed by `bun install`. Database forks (`admin/fork.ts`) and backups (`admin/backup.ts`) run these, never a copy on the PATH.

This plugin ships:

- The `@equin/pg-client-<platform>` packages as optionalDependencies in `package.json`, so `bun install` lands the binaries at `node_modules/@equin/pg-client-<platform>/native/bin/`.
- `pgClientBin(tool)` (server barrel) — the absolute path of a vendored tool. A release bundle points it at its own copy with `SINGULARITY_PG_CLIENT_BIN_DIR` (set by the launcher). A missing binary throws `PgClientToolMissingError`. There is no PATH fallback.

## Why vendored, and why never the PATH

`@embedded-postgres/*` (built from Zonky's artifacts) ships only `initdb`, `pg_ctl` and `postgres`. Before this plugin, the client tools came from whatever was on the PATH. That made a Homebrew `postgresql@18` a setup prerequisite, left a released bundle with no way to fork or back up, and let the versions drift: an 18.6 client ran against the 18.3 cluster.

## Where the binaries come from

[github.com/equinai/pg-client-embedded](https://github.com/equinai/pg-client-embedded) builds them in CI from the official PostgreSQL source tarball for darwin/linux × arm64/x64. libpq is linked in, and on Linux zlib too, so they need nothing beyond the C library. Every build is smoke-tested with a dump → restore round trip against the matching `@embedded-postgres` server before it is published. Same pattern as `@equin/pgbouncer-*`.

## Guardrails

- **`database-client-tools:version-matches-server`** (check) — the `@equin/pg-client-*` pin and the `@embedded-postgres/*` pin in `../embedded/package.json` must name the same Postgres `major.minor` (`18.3.0` ↔ `18.3.0-beta.17`), and each file's four platform pins must agree. To upgrade, publish the new client release first, then bump both pins together.
- **`db-client-tools/no-path-pg-client`** (lint) — rejects `"pg_dump"` / `"pg_restore"` / `"pg_dumpall"` as argv[0] of an array literal passed to a function call (`spawnCaptured(["pg_dump", …])`). That shape is a bare-name spawn, which is a PATH lookup. Use `pgClientBin(…)`.
