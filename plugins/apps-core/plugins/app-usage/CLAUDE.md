# app-usage

Per-app usage stats: how often each app is opened and how long it is actively
used, per local day. Design:
[`research/2026-10-08-apps-app-usage-stats.md`](../../../../research/2026-10-08-apps-app-usage-stats.md).

## What counts

- **Launch**: the focused app (`useFocusedAppId`) becomes X while the last
  focused app was not X. A transient `undefined` does not reset "last", and the
  last app survives a reload in `sessionStorage`, so a reload is not a launch.
  Every app counts, Home included; a consumer filters what it does not want.
- **Active time**: X is focused AND the page is visible AND the window has OS
  focus AND there was keyboard/pointer input in the last 5 minutes. On the idle
  deadline the stretch ends at the last input, so the wait is never counted.
  Only the OS-focused window accrues, so two windows cannot double-count.

## The tracker is event-driven

`web/internal/usage-tracker.ts` is a pure state machine fed by events (focused
app, `visibilitychange`, window `focus`/`blur`, input, `pagehide`) through the
headless `AppUsageRecorder` on `Core.Root`. Its only timers are one-shots: the
idle deadline (armed once, re-armed for the remainder when it fires early) and
a flush retry. Deltas per (local day, app) are flushed on an app change, a
pause, `pagehide`, the idle deadline, and — for a long session — on the first
input once the oldest unsent time is a minute old. A failed flush (server down)
is restored and retried. A stretch crossing local midnight is split per day.

## Storage

`app_usage_daily`, one row per (local day, app), every column additive: the
flush upsert adds deltas, so concurrent flushes sum. The day is the user's
local day, bucketed by the browser. Swept after two years (`last_flushed_at`), so
"all time" means within retention. `appUsageSummary` is a `liveValue` — one
`GROUP BY app_id` with 7-day and total sums — recomputed by the change feed on
every flush.

## Plugin reference
