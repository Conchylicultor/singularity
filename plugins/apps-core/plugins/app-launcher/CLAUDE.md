# app-launcher

The top-left brand of every app, contributed once as `AppShell.Brand` — apps
never draw their own header (the shell places it; see
[`primitives/app-shell`](../../../primitives/plugins/app-shell/CLAUDE.md)).

- **Launcher** (both forms) — the current app's own mark in an icon button: its
  `Apps.App` entry's `mark` (a drawn logo) when it registers one, else its rail
  `icon`; the Equin mark (`/icon.svg`) outside any app. Each app keeps its
  identity at the top-left; the button is the same launcher everywhere. It is
  wrapped in [`HoverPopover`](../../../primitives/plugins/overlay/plugins/hover-popover/CLAUDE.md).
  Click (link gestures: ⌘/middle-click opens it in a new browser tab) → the app gallery, i.e.
  the `Apps.App` entry flagged `default` via `defaultApp()` — never named.
  Hover / ArrowDown → every other `Apps.App` entry, in rail order, as the
  `icons` DataView at `density="compact"` (four tiles a row in the `picker`
  popover) — the same view and the same fields as Home's gallery, so the two
  cannot drift. `appFields` (exported) is that schema: the tile (leading,
  drawn through `AppIconTile`) and the name. It lives here, not in `app-icon`:
  `apps-core` imports `app-icon`, and data-view's own imports reach back to
  `apps-core`, so `app-icon` importing data-view would close a cycle. The current app is the view's
  `selectedRowId` (marked, and where ArrowDown lands); the view owns the arrow
  keys. No toolbar band: a hosted frame draws the grid, then a footer line with
  "All apps" (= the icon's click) and the hover-revealed options trigger
  (search). Its own view config, `apps-core.launcher`. A pick goes through
  `useActivateApp` (tabs), the one activation the rail and Home share.
- **`form="header"`** (sidebar header) — launcher + the current app's name, a
  link to that app's own `basePath` (not the gallery). The name is the row's
  flexible, truncating cell; the launcher is rigid.
- **`form="icon"`** (leading edge of a sidebar-less app's top chrome) — the
  launcher alone.
- **Floating** (`FloatingAppLauncher`, `Apps.Overlay` — inside the tab state, which switching apps needs; `Core.Root` is outside it) — solo (fullscreen) hides
  the rail and tab bar, so an app that draws no brand (Home's gallery, the
  website) would have no way to another app. In solo, when the focused surface
  draws no brand, the launcher floats at the top-left on the same anchored band
  as the floating action bar (`floating-bar-band`), hidden until the pointer
  comes within 96px of the corner (a window `pointermove` listener — an
  invisible hover zone would swallow clicks on the app) and kept shown while
  focused or while its grid is open. "Draws no brand" is read from what is
  mounted — `useBrandDrawnOn(focusedTabId)` from `primitives/app-shell` —
  never declared per app.

## Plugin reference

- Description: The app brand every app shell draws (AppShell.Brand): the launcher — the current app's own mark — click for the app gallery (the default Apps.App entry), hover or ArrowDown for a grid of every other installed app (switching exactly as the rail does) — plus, as the sidebar header, the current app's name linking to its own home. In solo (fullscreen) mode, a surface that draws no brand gets the launcher floating at the top-left, revealed as the pointer nears the corner.
