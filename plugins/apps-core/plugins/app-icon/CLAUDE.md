# app-icon

Canonical, serializable identity of an app's icon. One descriptor authored once
per app, rendered everywhere an app's glyph appears (rail, tab bar, window
chrome, launcher).

## `AppIcon` — the serializable descriptor

`AppIcon` (in `core/`) is a plain, JSON-serializable discriminated union:

```ts
type AppIcon = { kind: "symbol"; symbol: SymbolRef; color?: AvatarColor };
```

It carries the icon as data — a Material Symbols `SymbolRef` from
[`ui/icons`](../../../ui/plugins/icons/CLAUDE.md) — not a React component, so
a non-React consumer (a generated favicon, a Tauri window-icon) can read the
same value the UI does. The `kind` discriminant is the seam: a future
`{ kind: "image"; src }` variant drops in with one extra render branch and zero
changes to existing `kind: "symbol"` authors.

## Authoring

- `appIcon(symbol("…"))` (core) — build an `AppIcon`:
  `icon: appIcon(symbol("home"))`. `appIcon(symbol, { color })` also declares
  the app's tile colour (an `AvatarColor` from `primitives/avatar/core`, e.g.
  Settings is `slate`); omitted, a launcher derives the colour from the app id.
- The shell's `defineApp({ iconKey })` (core) names the same Material Symbols
  glyph — the release CLI reads it statically. tsc checks the name exists
  (`iconKey: SymbolName`); the `app-icon:key-in-sync` check keeps it equal to the
  web shell's `appIcon(symbol("…"))`.
- `DEFAULT_APP_ICON` (web) — fallback glyph for tabs/windows whose owning app
  cannot be resolved.

## Rendering

- `<AppIconView icon active? className />` draws an `AppIcon` through `<Icon>`,
  in the theme scope's icon style (`active` = the focused app).
- Anything taking an `icon: IconRef` (the `ui/tab-bar` `Tab`, `IconButton`) takes
  `appIcon.symbol` directly.
- `appIconToSvg(glyph, opts)` (core) — rasterizable SVG markup for the release
  CLI, from the glyph `symbolBody(iconKey)` (`ui/icons/server`) reads out of the
  installed Iconify JSON in the default icon style.
