# map/google

The only map-vendor code in the repo. Everything else draws maps through
`GeoMap` (`plugins/map`).

- **Credential**: the public browser key plus an optional map id, read through
  `useMapsBrowserConfig` from `integrations/google-maps`. It is not the server-only
  Places key; that plugin's CLAUDE.md explains why there are two.
- **Loud failure**: Google reports a refused key only through
  `window.gm_authFailure`, and `@vis.gl/react-google-maps` 1.10 no longer hooks
  it. `internal/auth-failure.ts` installs it and chains to any earlier handler.
  The canvas then swaps itself for `MapErrorCard`. A refusal lasts for the whole
  page, because the script loads once with one key, so after a fix the user has
  to reload.
- **Tones**: Google strokes take colour strings, so `useToneColors` resolves each
  `MapTone` token against the map's own element and normalises it to `rgb()`,
  because a theme may use `oklch`. A stroke is not drawn until its colour is known.
- `DEMO_MAP_ID` is used while no map id is set, because Advanced Markers require
  some map id.

## Plugin reference

- Description: Google Maps JavaScript API as the map renderer: draws GeoMap overlays (pins as AdvancedMarkers holding each pin's contributed content, paths as polylines, areas as polygons, strokes in resolved theme tones), frames them only when the set of positions changes, shows the live-map set-up action until a browser key is set, and replaces Google's silent grey map with an error card when the key is refused. Lazily loaded off the boot wave.
- Web:
  - Contributes: `GeoMap.Renderer` "Google Maps" → `LazyBoundary`
  - Uses:
    - `integrations/google-maps.MapsMapAccessAction`
    - `integrations/google-maps.useMapsAccess`
    - `integrations/google-maps.useMapsBrowserConfig`
