# plugin-link

Renders plugin hierarchy IDs in backtick-wrapped inline code as clickable
chips that open the plugin-view pane. When a model emits `` `tasks` `` or
`` `active-data.conv` ``, `usePluginClaim` resolves it against the live plugin
tree (`GET /api/plugin-view/tree`) and `claimed`s it; the chip is a pure renderer
reached only on a claim.

The pattern is a broad kebab-case + dot-joined regex, so it full-matches plenty of
tokens that are not plugins. Those are **`declined`**, not rendered as a plain
`<code>` — declining hands the token to the next code contribution (e.g. a commit
sha, which is also a valid plugin name), and the host renders the fallback. See the
claim protocol in [`../../CLAUDE.md`](../../CLAUDE.md).

A failed tree fetch declines too, rather than staying `pending`: `pending` halts the
arbitration chain by design, so a dead endpoint would otherwise block every other
candidate on the token forever.
