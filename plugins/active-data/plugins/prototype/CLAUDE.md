# prototype

Renders raw `proto-<id>` strings (e.g. `proto-1786877040-w2vi`) inline as
clickable chips. Agents write the bare id — no tag wrapping — and the
active-data linkify primitive replaces matches at render time. Clicking opens
`prototypeDetailPane` (`proto/:name`) with `mode: "push"`, so the mock appears
as a live column beside the surface the text was read in:
`/agents/c/<convId>/proto/proto-…`.

This is the point of giving a prototype an id at all. A prototype is the one
entity whose whole value is *being looked at*, and until it had a token an agent
could write, a mock it had just built was something the user had to go and find.
See [`research/2026-08-21-global-prototype-ids-and-mint.md`](../../../../research/2026-08-21-global-prototype-ids-and-mint.md).

**The pattern imports the id's shape; it does not re-type it.** `attempt` and
`page-link` each declare the format again in their own `internal/pattern.ts`, so
the mint and the chip are two independent spellings of one thing — change the
mint and the chips silently stop matching, with nothing failing. Here
`PROTOTYPE_ID_RE` comes from `files/core/id.ts`, the single spelling that the
mint and the folder-name validation also read, pinned to `newPrototypeId()` by
that plugin's `id.test.ts`. `internal/pattern.test.ts` pins the
boundary-wrapped reading on this side, with fixtures drawn from the real mint.

`inlineBoundary` supplies this reading's guards: a bare id in a sentence
linkifies, `~/…/proto-…/index.html` in a path does not. The core shape needs no
extra trailing guard (unlike `page-link`'s) because its suffix is a fixed `{4}`
and its digits must be followed by `-`, so it cannot backtrack into a shorter
match to satisfy the boundary lookahead.

**Resolution is free.** `prototypesResource` is a live, app-wide list
re-broadcast on every file change under the prototypes dir, so a transcript full
of ids costs no requests and a chip's label follows a `<title>` edit live.

Every arm that is not a resolved prototype — still loading, failed to load, or
no such folder — renders the raw id as plain text. That is `page-link`'s
behaviour rather than `attempt`'s, and an opaque id leaves no other honest
option: there is nothing to show about `proto-1786877040-w2vi` except its title,
so a chip that opens nothing would be worse than the text the model wrote.
(Making `prototypesResource` `resident: true` would close the pending window
outright, at the price of pulling a niche app's list into every app's boot
snapshot — not worth it for a brief flash of the raw id.)

The label is `PrototypeMeta.title` with nothing on top: a prototype with no
`<title>` of its own already reads `UNTITLED_PROTOTYPE` by the time the list
reaches here (`files/core/id.ts`), so the chip cannot label itself with the very
id it exists to replace. That fallback deliberately is NOT the directory name —
it was, and this chip is one of the three surfaces that would have shown a raw
id because of it.

`e2e/prototype-chip-verify.ts` drives the whole path against a deployed
conversation.
