# id-chip

The inline chip of a declared id kind (`plugins/ids`), from two factories a chip
family spreads into its barrels:

```ts
// web/index.ts
contributions: [...idChip({ presenter: { kind, icon?, useReferent, useOpen }, surfaces, component? })]
// server/index.ts
contributions: [...idChipServer({ kind, surfaces, resolve })]
```

- `idChip` mints the kind's `IdKinds.Presenter` and its `InlineChip.Tag(inlineChip(…))`
  — chip id = the kind's prefix, pattern = `idChipPattern(kind)`
  (`inlineBoundary(kind.pattern)`), `modelText: "resolved"`. Without `component`
  the chip is the generic one: the referent's title led by the kind's icon,
  opening via `useOpen`; every not-found arm renders the raw id as written.
- `idChipServer` contributes the kind's `IdKinds.Referent`, the
  `InlineTokenReferentSource` over the same pattern (tag = the kind's label), and
  — when `surfaces` includes `"document"` — the `Editor.InlineToken` (markdown
  `transparent`) that keeps a page block holding the chip agent-readable.

A family keeps its `surfaces` in its own `core/` and passes it to both, so the
two halves cannot disagree.

- `idChipServer({ referentTag })` names the tag a model reads the resolved id
  as; it defaults to the kind's label lowercased. `page-link` passes `"page"`
  (a `block-…` resolves to its page) so model-facing text stayed byte-identical
  when the family moved onto its kind.
- `rowReferent(useLiveRow(collection, id), title)` (web) folds a live by-id row
  read into the presenter's `IdReferentState` — loading / failed / missing /
  found — for the families whose referent is one row (`report`, `build-run`,
  `event-source`).

**Why factories the family calls, not chips generated from the Presenter slot.**
A web slot is readable only through a React hook, while `inlineChip()` must run
at module eval (the Lexical hosts and the runs↔doc projection read its registry
outside any render) and every chip must stand in the `InlineChip.Tag` declaration
the docs and the `active-data:*` chip checks read. Server contributions are a
static array too. So the family's barrel calls the factory once and every piece
derives from the kind; nothing here names a family.
