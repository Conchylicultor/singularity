# commit-link

A backticked commit sha in agent prose — `` `862de5c72` `` — becomes a chip with
the subject/author/date on hover that opens the commit-detail pane on click.

**Backticked only, anchored.** A `display:"code"` contribution: reached only from
inside an inline code span, only on a full-string match, so a bare sha in prose
stays inert. `/^(?=.*[a-f])[0-9a-f]{7,40}$/` — 7 is git's minimum `%h`, 40 a full
SHA-1, and the lookahead keeps all-digit tokens (request ids, ports, counts) from
becoming an HTTP lookup per code span. It costs the ~3.4% of 7-char shas that are
all digits: deliberate, since a false negative is invisible and a false positive
is a request.

**The worktree is always the literal `"main"`** (`internal/commit-worktree.ts`).
Worktrees share one object database, so `git log -1 <sha>` resolves a commit from
any branch or attempt, unpushed; and `"main"` goes through the self-healing
`ensureMainWorktreeRoot()`, unlike an attempt's `worktreePath`, which dies with
`worktree-cleanup`. The payoff is zero conversation-awareness — identical
behaviour on surfaces with no conversation in scope (task descriptions, Debug →
Memory, the story renderer). A conversation lookup here re-introduces the
degraded path.

**It declines; it never renders a fallback.** `useCommitClaim` maps `useCommitInfo`
onto the claim protocol, with `not-found` AND `error` both *settled* declines: a
pending claim stops the arbitration chain, so treating a dead backend as pending
would park the token and starve the next candidate (a short sha is also a valid
plugin name). What an unresolvable sha renders as is the host's call.
