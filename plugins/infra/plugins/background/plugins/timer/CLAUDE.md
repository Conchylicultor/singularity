# timer

`defineTimer({ name, description, everyMs, run, immediate?, unref?, profile? })`
— the one sanctioned in-process interval for the server
(`@plugins/infra/plugins/background/plugins/timer/server`, adds `mainOnly?`) and
central (`…/timer/central`) runtimes. Plan:
`research/2026-09-30-infra-background-activity-catalog.md` §4.

```ts
export const sweeperTimer = defineTimer({
  name: "jobs.stuck-lock-sweep",
  description: "Frees jobs whose worker died mid-run, …",
  everyMs: 60_000,
  run: () => sweepOnce(),
});
// plugin definition: register: [sweeperTimer], onReady: () => sweeperTimer.start()
```

- **Registered, then started.** Mount the timer in its plugin's `register`
  (that is what lists it); `start()` throws on an unregistered timer, and on a
  `mainOnly` one outside main. `stop()` is idempotent.
- **Tracked.** Each tick is a `timer:<name>` span (`profile: "invisible"` only
  for a sampler of the profiler's own host). Runs are recorded in memory — last
  run, runs/failures, a ring of `RECENT_RUNS_MAX` — and listed under **Timers**
  in Debug → Background activity (kind `timer` on a worktree backend,
  `central-timer` on central). The catalog is pushed when a run's outcome
  changes, otherwise at most once a minute per timer.
- **Fails loudly.** A throwing tick is recorded as failed, then rethrown on the
  server (an unhandled rejection the reports plugin files) and logged on central
  (no reports funnel there; an unhandled rejection would take the machine-wide
  process down). A failure you expect is still handled inside `run`.

## Not a polling escape hatch

CLAUDE.md's "No polling" still holds: work on a schedule is a `defineJob`
(cron), work on a change is a watcher / LISTEN / event. A timer is only for a
loop that cannot be either:

- **central** — it has no job queue;
- **out-of-queue watchdogs and samplers** — the queue's own recovery and
  alarms, and samplers of this process, which must keep running while the queue
  is wedged (and often tick below cron's one-minute floor);
- **real polling awaiting a push replacement** — kept visible here rather than
  hidden in a raw interval.

Enforced by two lint rules. `timer/no-unlisted-timer` (this plugin's `lint/`)
reports every `defineTimer(...)` call its owning plugin has not exempted — a new
timer means an entry in that plugin's own `exempt/index.ts` (rule
`timer/no-unlisted-timer`, with its reason); `./singularity check` fails on an
entry that no longer covers a timer. `detached-work-safety/
no-raw-set-interval` bans raw `setInterval` in server / central / shared / bin
code outright; its exemptions (`exempt/index.ts`) hold the few sites a timer cannot host (Worker and
child-process entries, the bin orphan guards, a primitive's per-instance
timer, a hand-started test harness). `shared/timer.ts` is the one
implementation site.

## Plugin reference
