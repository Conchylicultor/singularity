# catalog

The Background activity catalog: one list of everything the app runs on its
own. Plan: `research/2026-09-30-infra-background-activity-catalog.md`.

- **Providers, not a list.** A mechanism that runs things on its own declares a
  provider with `defineBackgroundKind({ kind, label, order, list, recentRuns?, runNow? })`
  (`order` places its groups in the list, lowest first)
  (server), mounts it in `register`, and calls `changed(name?)` when its entries
  may have moved. The catalog merges every provider (`mergeCatalog`: stamps
  `kind`, refuses a duplicate name within a kind, stable order) and **names none
  of them** — the jobs provider lives in `infra/jobs/plugins/background-arm`,
  warm-ups in `infra/warmup/plugins/background-arm`, timers in
  `infra/background/timer`.
- **Two halves.** The worktree backend serves `background.catalog`; the
  central runtime serves `background.central-catalog` (and
  `background.central-recent-runs`) from its own providers, declared with the
  central barrel's `defineBackgroundKind` — every central entry is scope
  `central`. The page merges them; each half loads and fails on its own (a line
  above the list says while central is loading or failed). Provider registry,
  merge and loaders live in `shared/`, one implementation for both.
- **Trigger sources.** `BackgroundTriggerSource({ kind, eventNames(name) })`
  (server contribution) fills an event-triggered entry's `names` from knowledge
  its provider does not own — the events plugin contributes one for `job`
  from its declared `Trigger`s. The catalog names neither side.
- **Live.** `background.catalog` (a `liveValue`, external, bounded by the
  declared set) is pushed on `changed`, throttled to one push per 3 s so
  per-minute work cannot churn it. `background.recent-runs` (params
  `kind`, `name`) is the same per entry, at most `RECENT_RUNS_MAX` runs;
  `{ tracked: false }` says a provider keeps no history (never an empty list).
- **Run now.** `POST /api/background/run-now {kind, name}` re-reads the entry
  and refuses (409) one listed `canRunNow: false`.
- **Page.** Debug → Background activity (`/debug/background`), a list DataView
  (`infra.background.catalog`, views in config: grouped by kind, internal
  plumbing hidden; a Failed view) and a detail pane per entry
  (`/debug/background/activity/<kind>/<name>`).

## Plugin reference

- Description: Debug → Background activity: a DataView over the pushed background.catalog — everything this backend runs on its own, grouped by kind, with a status dot, the trigger in words and its next run, and the last run — and a detail pane per entry with its scope, declaring plugin, recent runs and Run now. Background activity catalog: defineBackgroundKind registers a provider (a mechanism that runs things on its own: jobs, warm-ups, timers) that lists its entries with trigger, scope and latest run, its recent runs and an optional Run now; the catalog merges every provider into the pushed background.catalog value (throttled), serves background.recent-runs per entry and POST /api/background/run-now, fills event-triggered entries' event names from contributed BackgroundTriggerSource annotations, and names no provider. Background activity catalog, central half: defineBackgroundKind registers a provider for what the machine-wide central runtime runs on its own, merged into the pushed background.central-catalog value (every entry scope central) with background.central-recent-runs per entry.
