# events-test

## Queue harnesses

Regression checks, each returning `{ ok: true, … }` or `{ ok: false, step, error }`
(what each asserts, and why, is in `jobs/CLAUDE.md`): `crash-recovery`,
`queue-lock-no-steal`, `serial-queue`, `cron-dedup` — all `POST /api/events-test/<name>`.

`POST /api/events-test/queue-saturate` is a load generator, not a check: it
fills the `minutes` class and leaves a dead job, so queue observability can be
seen amber and then green as the jobs drain. Body (all optional): `count`
sleepers (default: the class's slots + 1, so one waits), `sleepMs` (90 s, max
20 min), `backdateMs` (0), `dead` (true — one `NonRetryableError` job).

- `backdateMs` moves EVERY sleeper's `run_at`, not only the one left waiting:
  the queue fetches oldest `run_at` first, so a lone back-dated row would be
  the first to start. Side effect: the started ones report a pickup time of
  ≈ `backdateMs`.
- Sleepers stop early on backend shutdown (`onShutdown`); `ctx.signal` is the
  deadline only, so without it a restart waits out every sleeper.

```bash
curl -sX POST http://<ns>.localhost:9000/api/events-test/queue-saturate \
  -H 'content-type: application/json' -d '{"backdateMs": 660000}'
```
