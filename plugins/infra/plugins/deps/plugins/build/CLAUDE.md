# build

The `build` installer kind of `infra/deps` — see the parent's
[`CLAUDE.md`](../../CLAUDE.md) for the engine.

```ts
// plugins/<feature>/deps/index.ts
export const shim = defineDep({
  id: "my-shim", owner: "…", description: "…", sizeHint: "≈50 KB",
  source: build({
    inputs: ["plugins/<feature>/native/**"],       // git ls-files globs, repo-relative
    tool: { versionArgv: ["cc", "--version"] },     // its stdout is in the identity
    output: "shim.dylib",                           // what run leaves in env/ (or (target) => name)
    // targets: "any" — only when run honours ctx.target (see below)
    run: (ctx) => ctx.run(["cc", "-o", ctx.output, "…"], { cwd: ctx.root, env: { ...process.env }, timeoutMs }),
    // admission: { none: "<why>" } — only for a build too small to be worth a host grant
  }),
  updates: { none: "built from this checkout's own source" },
});

// after ensureDep / readyNow:
const path = builtFile(ready);
```

- The identity is derived, never typed: every input file's sha256 (the working
  tree, so an uncommitted edit rebuilds; untracked-but-not-ignored files
  count), the tool's version output, and the target platform/arch. A new
  compiler or an edited source is a new install beside the old one.
- A tool whose version command fails, or a glob matching no file, makes the
  identity underivable: the dependency reads `failed`, never `absent`.
- **Targets.** The declaration's own source builds for this host.
  `forTarget(target)` (what `sealDep` calls to seal a release bundle for its
  platform) builds for another one when `targets` says the toolchain can:
  `"any"` (Go: `run` maps `ctx.target` to `GOOS`/`GOARCH`/`CGO_ENABLED` —
  `infra/launcher`'s `gateway-binary`), or a function answering per target with
  a reason when not. Omitted means this host only, so a build that never said
  it cross-compiles is never asked to. `output` may be a function of the target
  (`.dylib` / `.so`); `builtFile` reads the host's, which is right because a
  sealed bundle is only ever read on its own platform (the engine refuses
  another).
- **C (`cc`) is host only, honestly.** Cross-compiling C to another OS needs
  that OS's headers and linker (a sysroot), which a Mac does not have; the
  signal-origin shim therefore declares no `targets`. It is not bundled either:
  only the `build` / `check` / `push` CLI ops arm the tap, and a release runs
  none of them.
