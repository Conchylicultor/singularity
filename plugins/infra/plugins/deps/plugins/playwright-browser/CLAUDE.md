# playwright-browser

The `playwright-browser` installer kind of `infra/deps` — see the parent's
[`CLAUDE.md`](../../CLAUDE.md) for the engine.

```ts
// plugins/<feature>/deps/index.ts
export const chromium = defineDep({
  id: "chromium", owner: "…", description: "…", sizeHint: "≈600 MB",
  source: playwrightBrowser({ browser: "chromium" }),
  updates: { none: "follows the playwright npm pin" },
});

// after ensureDep / readyNow / ensureDepViaCli:
const browser = await launchChromium(ready, { args, timeout });   // headless shell
const headed = await launchChromium(ready, { headless: false });  // headed binary
```

- **One module graph.** `playwright` (and its nested `playwright-core`) is
  resolved with `Bun.resolveSync` from THIS plugin's directory in the checkout
  asked — for the identity, for the installer CLI, and for the registry that
  reports the executables — and `launchChromium` imports `playwright` from here
  too. Installer, identity and launcher cannot disagree about the version.
- **Never a package runner.** The install spawns `process.execPath <resolved
  playwright cli> install chromium`; a `bunx`/`npx` spelling resolves outside
  the workspace and can install registry `latest`
  (`e2e-harness:pinned-playwright-invocation` keeps it out of the tree).
- **Recorded, not re-derived.** `playwright install chromium` fetches the
  headed binary AND `chrome-headless-shell` (the two a headed and a headless
  launch run). A one-line child with the same `PLAYWRIGHT_BROWSERS_PATH` asks
  Playwright's registry (`playwright-core/lib/coreBundle`'s
  `registry.findExecutable("chromium" | "chromium-headless-shell")`) where they
  are and writes `env/executables.json`. A child, because the registry fixes its
  browsers path when it is first loaded. `isIntact` = both recorded files
  exist, so a payload deleted by hand reads `absent` and reinstalls.
- **`launchChromium` takes a `Ready`**: launched without ensuring is a type
  error. `headless` (default `true`) picks the recorded headless shell;
  `false` the headed binary.
- `core/` holds the record (`BROWSER_EXECUTABLES_FILE`, its schema) and its
  reader `readBrowserExecutables(envDir)`, so host code that cannot reach the
  `deps/` barrel (the layout-geometry suite under `web/`) reads an install the
  same way the kind does, after `./singularity deps install chromium --json`.
- No updater: a new `playwright` pin is a new identity, installed beside the
  old one on first use; the deps sweep reclaims the old one.
