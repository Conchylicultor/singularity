# background-arm

The `daemon` kind of the Background activity catalog
(`infra/background/catalog`). A child of `daemon` rather than part of it for
the same reason as the file-watcher arm: the daemon barrel is imported by
plugins that load early (the sentinel), and must stay free of the catalog's
server barrel.

- **List.** Every declaration made with `defineDaemon` (`listDaemons`), grouped
  `Long-lived processes`, trigger `boot` or `on-demand` (`startedBy`). Scope
  from `where`: `main` / `host-singleton` → main, otherwise every worktree.
- **Facts.** `Instances` (count), one `Instance` fact per instance (state, pid
  — or the backend's pid for a worker thread — since when ("seen since" for a
  pid-file process this backend did not parent), restarts, `ps` uptime, memory
  and CPU; at most 10, then a count), `Last exit`, `Restart policy`, `Liveness`.
  Memory and CPU come from ONE `ps` over every running pid per catalog load;
  a timed-out `ps` says so in the fact rather than leaving it out.
- **Runs.** Each incarnation is a run, kept in memory by the daemon registry (a
  ring of the last 20 plus counters). No Run now: a daemon is started by its
  owner, not by a person.
- **Pushes.** `onDaemonActivity` (every instance transition — rare by
  construction) drives `changed(name)`. Pid-file liveness is read during
  `list()`, so a preview or gateway that died shows at the next load.
