# display

The **human-facing spelling** of the singularity data dirs — the `~/…` form a
message, a UI empty state, or an agent prompt writes when it tells somebody
where a directory is. The parent `paths` plugin owns the same directories as
*resolved absolute paths*; this owns how they are *written*.

Why a separate plugin, and not another export on `paths/core`: that barrel
re-exports `core/internal/paths.ts`, which calls `homedir()` at module scope.
The browser cannot import it — a single `node:os` edge breaks the web bundle at
module eval. Yet the browser is exactly where these strings are needed (the
prototypes gallery's empty state, the two agent-launch prompts). So the
web-safe half is its own leaf: **string literals only, no `node:*`, no import of
the sibling `paths` module.** Same reasoning as `infra/duress/latch`, one notch
stricter.

Consumers therefore import `@plugins/infra/plugins/paths/plugins/display/core`
directly, from any runtime. `paths/server` deliberately does NOT re-export these
(a cross-plugin re-export, banned — and it would hide the real dependency).

The spelling is a literal, not derived from `PROTOTYPES_DIR`: that constant is
already expanded, and re-shortening it back to `~` would be a second, lossier
spelling. The two files live in one plugin family so a change to either is read
against the other.

Adding a constant: name it `<THING>_DIR_DISPLAY`, document which `paths`
constant it is the prose twin of, and add this file to `ALLOWED_PATHS` in
`plugins/infra/plugins/paths/check/index.ts` if it is not already there —
`paths:no-hardcoded-paths` allows the path family's OWNER to spell its own
paths, and nobody else.
