# html-decode

Bun's `HTMLRewriter` is a **streaming rewriter over source bytes: it decodes
NOTHING.** Both `el.getAttribute(name)` and text chunks come back as raw,
undecoded HTML source. Verified experimentally:

```
<meta property="og:title" content="single &#x27;quote&#39; &amp; amp">
  → getAttribute("content") === "single &#x27;quote&#39; &amp; amp"

<title>tag &#x27;quote&#x27; &amp; amp</title>
  → text chunk === "tag &#x27;quote&#x27; &amp; amp"
```

That is not a bug in the rewriter — a rewriter's job is to hand markup back
verbatim so the untouched parts round-trip byte-for-byte. It IS a trap for every
caller that treats a rewriter read as a *value*: a scraped title renders as the
literal `d&#x27;entretien`, and a URL attribute carrying `&amp;` resolves to a
wrong query string. Every value read out of an `HTMLRewriter` therefore needs
decoding **exactly once**, and this plugin is the single place that happens.

## API

```ts
import { decodeHtmlText, readHtmlAttr } from "@plugins/infra/plugins/html-decode/core";

// The only sanctioned way to read an attribute in a rewriter handler.
const content = readHtmlAttr(el, "content"); // string | undefined (undefined ⇔ absent)

// For text chunks, which must be accumulated FIRST and decoded once at the end.
const title = decodeHtmlText(accumulated);
```

Reading attributes only through `readHtmlAttr` is what makes correctness
structural rather than a rule to remember: a newly handled attribute cannot
forget to decode, because there is no undecoded read to reach for.

`decodeHtmlText` decodes **once**, not to a fixed point: `&amp;#x27;` becomes
`&#x27;`, never `'`. The source really did encode a literal `&#x27;`, and
re-decoding would corrupt it.

> **Text chunks: accumulate, then decode.** The rewriter splits text on its own
> buffer boundaries, so a character reference can straddle two chunks. Decode
> the whole accumulated string once at `lastInTextNode`, never per chunk.

## Shape

Core-only (no `web/`, no `server/`): a pure string function usable from any
runtime. `readHtmlAttr`'s element parameter is typed **structurally**
(`{ getAttribute(name: string): string | null }`) rather than against Bun's
ambient `HTMLRewriterTypes` global, so the primitive depends on no ambient type
name and is unit-testable with a plain object.

Decoding is delegated to [`entities`](https://www.npmjs.com/package/entities)
(`decodeHTML`) — zero-dep, and the decoder behind parse5/cheerio.
