# git

Reading git is slow, and every worktree backend wants the same answer at the same
moment — one `main` advance fans out across every checkout and every open view. So
the two questions here are **when did a ref move**, and **can I skip re-reading what
it points at?**

Reach for:

| You want | Use |
|---|---|
| To be told when `refs/heads/main` or this worktree's own branch advances | `git-watcher` |
| To skip an expensive git read while nothing it depends on has changed | `git-read-cache` |

The two are usually used together. The watcher hands you a SHA it already holds in
memory, and that SHA is exactly the kind of cheap signature the memo wants — so the
storm path becomes mostly memo hits doing no git work at all.

Not here: `primitives/commit-list` parses git's output into rows, and
`infra/host/host-read-pool` is the host-wide budget a heavy read waits for. `git-read-cache`
composes that budget rather than replacing it.

One caveat on the grouping. The memo in `git-read-cache` is not itself git-specific —
it takes a signature and a compute, and one consumer runs it over file timestamps with
no git anywhere. Its name records where the abstraction was first pulled out, not what
it is.

## Plugin reference

- Description: Umbrella for the two plugins that answer 'has git state moved, and must I read it again?': the ref watcher that reports every advance, and the signature-keyed memo that skips a gated recompute when a cheap probe says nothing changed.
- Sub-plugins:
  - **`git-read-cache`** — Git-state-keyed result memos: skip a gated git recompute when a cheap ungated signature is unchanged; single-flight + coalesce per worktree. createGitStateMemo takes signature/compute per call; createSignedMemo binds them at construction so a resource's revalidate and loader cannot drift.
  - **`git-watcher`** — Watches local git refs (refs/heads/main plus the current worktree's own branch) via @parcel/watcher. On every advance it notifies the refHeadResource live-state resource, runs the registered in-process ref reactions (every backend, nothing queued in between), and emits the durable git.refAdvanced trigger event (main only).
