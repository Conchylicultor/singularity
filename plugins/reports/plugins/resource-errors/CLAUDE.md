# resource-errors

The loud signal for a **live read that failed** — so a surface that ignores its
read's `error` arm still cannot hide a failure
(`research/2026-09-27-global-live-resource-skew-and-error-state.md`, Fix 2).

## Signal source

`live-state` is a primitive and must not import `reports`, so
`NotificationsClient` emits a neutral `ResourceErrorInfo` (`key`, `params`, the
typed `ResourceError`) into `resourceErrorReportSink` **once per failing
`(key, params)` tuple per episode** — it watches the query cache, not the hooks,
so N observers of one read are one emit, a retry that fails again is the same
episode, and a recovery re-arms it. `ResourceErrorCollector` (mounted via
`Core.Root`) drains the sink — the inversion `live-state-stale-drop` uses.

## Policy

The collector files a `resource-error` report only for the failures a developer
must fix: **`loader-failed`** and **`not-found`**. A `client-outdated` read is a
tab running an older bundle — expected after a deploy, and the Reload advice's
job — and a `transport` failure is the network, which the client's event-driven
retry (`online`, the tab becoming visible) heals.

Fingerprint: `sha256("resource-error" + key + errorKind)`, first 16 hex chars —
one failing resource is one bug, whichever params tuple hit it and whatever its
message says. Re-arm: `notifCooldownMs: 6h`, since a standing failure re-fails
on every retry.

## Health row

The **Live reads** row (`order: 30`, after Connection and Database) reads
`useFailingResources()` — every tuple currently in error, of any kind — and is
`attention` with "N resources failing" while any is; an out-of-date tab's
summary points at the reload. It is never `unknown`: the failing set is
page-local, known from the first render.
