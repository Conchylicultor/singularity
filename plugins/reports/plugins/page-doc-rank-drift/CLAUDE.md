# page-doc-rank-drift

The report kind for **sidebar order the page editor had to repair at boot**.

`page_blocks.doc_rank` is maintained at the editor's structural-write chokepoint
(`withPageForest` re-mints every sidebar group a write's mutators marked — see
`page/editor`'s CLAUDE.md, *The sidebar's ordering space is `docRank`*), and the
editor's `onReadyBlocking` re-checks every group before the backend serves. The
first boot of a database is the silent backfill; any later boot that still finds
a group out of order has found a writer that bypassed the marks (or an old
backend writing during a hot-swap). The editor repairs it and emits the outcome
into `docRankDriftSink`; this plugin drains the sink into a report.

## Why a sink

The editor's server barrel is loaded by drizzle-kit through the `_blocks` table
it exports, and `reports/server` pulls `config_v2`, which throws at module eval
in a process with no runtime namespace — so the editor must not import
`reports` (`./singularity check schema-files-loadable` fails on every schema file
that imports `_blocks` otherwise). The sink holds what the editor emitted before
this plugin's `onReady` registers, then replays it: the `orphanedAttemptSink`
precedent (tasks-core → conversations).

Deduped on the kind alone: one standing question ("who bypasses the marks?"),
whatever groups a given boot repaired.
