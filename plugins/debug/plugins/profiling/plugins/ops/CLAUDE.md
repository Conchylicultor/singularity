# ops

Op contention profiling for Debug > Profiling, over the op-store's live
`opsHistory` collection (`op-log/plugins/op-store/core` — the DB fold of
`op-log.jsonl`, 30-day retention). Web-only: no endpoint, no file read. Rows are
projected to op-log's read-model record in the browser
(`toOpRecord(opRowToFoldState(row), now)`), so an in-flight op's span and open
wait grow with `now` (a 5 s presentational tick in the Gantt, 1 s in the detail
— and no tick at all once every op on screen is closed).

## Surfaces

- **Profiling section** (`OpSection`): every op requested in the last 24 h —
  `useLive(opsHistory, { where: requestedAt >= cutoff, limit: 2000 })`, the
  cutoff floored to 5 min so the subscription tuple is stable.
- **Worktree Gantt** (`WorktreeOpGantt`, exported; the conversation's `/pp`
  pane): two reads. First that worktree's own ops (`where: { opSlug }`); their
  span ± 20 min, floored / ceiled to 5 min, is the window. Then every op
  overlapping the window (requested in it, or completed in it). While one of the
  worktree's ops is in flight the window is open-ended rather than re-keyed as
  it grows.
- **Op detail** (`opDetailPane`): `useLiveRow(opsHistory, opId)` — every wait
  (with its reason, requeue cycle and result), every step, the lane.

## The render model

An op is **one bar** spanning `startMs → startMs + totalMs`, colored by `kind`,
with each entry of `waits[]` painted as an overlay segment at its own true offset
*inside* that span (see `op-gantt`). Waits interleave with real work, and one op
may carry several waits of the same kind (a build re-queues for the host grant
across requeue cycles), so a renderer must handle N segments at arbitrary
offsets. That is also why an op's span is `requestedAt → requestedAt + totalMs`
and **never** `waitMs + holdMs`: that sum omits every work gap between the waits.

## Grouping

A row is keyed on the op's `opSlug` — the basename of the checkout root the
writing CLI derived — so a worktree's push, build, check, test and e2e bars land
on one row. A line with no slug (a foreign writer, or one predating the slug) is
filed under its branch, reduced to the bare id (`claude-web/att-x` → `att-x`).

Row labels come from `useConversationTitleBySlug()` (`conversations/web`, the
same lookup the op-status banner uses): the slug is the attempt id, so any
worktree with a conversation in the live lists gets its title; others fall back
to the bare id. `web/internal/op-groups.ts` holds the pure projection.

## Reconciler

The orphan reconciler lives in `op-log/plugins/op-store` (`reconcile.ts`).
