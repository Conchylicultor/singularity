# text-editor

Generic Lexical-based rich text editor primitive — an extensible shell where
plugins inject features via the `TextEditor.Plugin` slot and
`registerNodeExtension`.

The editor manages two-way markdown-to-Lexical sync, submit behavior
(Enter / Cmd+Enter), and accepts an optional `bottomSlot` prop for UI
rendered inside the LexicalComposer boundary below the text area (so
slot components can call `useLexicalComposerContext()`).

Feature-specific behaviors live in sub-plugins that contribute via the
Plugin slot.

## Node extensions

A `NodeExtension` is the one declaration that makes a token round-trip — this
editor's name for the shared `InlineTokenExtension` (see the `token-extension`
sub-plugin, which derives the (de)serialization pair from one node
declaration). The editor core applies that registry on **every** way text
enters the editor, so an extension is never wired per-entry-point:

- the `value` prop round-trip (`applyMarkdownToEditor`),
- the imperative caret insert (`insertRef` → `$insertMarkdownSnippet`),
- **paste** (`TokenPastePlugin`) — pasted text carrying an extension token
  materializes the node instead of landing as literal characters. It gates on
  `hasToken`, so a paste with no token falls through untouched to
  Lexical's default handler, and it sits at `COMMAND_PRIORITY_LOW`: below the
  image/file paste handlers, above the default insert.

### The registry is read at CALL time, and folds in lazy sources

`registerNodeExtension` takes a family; `registerNodeExtensionSource` takes a
LOOKUP, called afresh on every read. The second exists for a plugin whose token
set is itself a registry — active-data's inline chips, which fill in as the
plugin tiers load. Registering a finished list there would freeze whatever had
loaded at that instant, and the rest of the chips would render as plain
characters with nothing failing.

So `getNodeExtensions()` must never be memoized by a caller, and the editor
reads it at render / at insert time rather than holding a snapshot. (Both halves
come from `token-extension`'s `createSourcedRegistry`, sited there so the page
editor's registry can share one implementation of the call-time rule.)

This replaced a `TextEditorSlots.NodeExtensions` SLOT, whose contributions were
readable only through a React hook: that confined the extension set to render,
and the same idea could not be mirrored into the page editor at all, whose
registry readers are headless.

## The caret

- **A `value` re-apply carries the caret.** The rebuild destroys the selection
  and Lexical parks it at the *start*, so `applyMarkdownToEditor` captures it as
  raw-source offsets and restores it. With none worth carrying (a restore into
  an untouched editor) it lands at the END — where a draft is continued.
- **`useInsertMarkdown` is the only insert**, for the toolbar affordances and
  the `insertRef` handle alike. Never hand-roll `selection.insertText`: it
  leaves a literal `\n` inside a text node, which has no caret rect the browser
  can place, and skips the extension deserialization.

## Sub-plugins

- **`paste-images`** — Image paste/drop support. Registers an `ImageNode`
  extension and contributes the paste/drop Lexical command handler via
  `TextEditor.Plugin`. Also owns the attachment markdown helpers
  (`extractAttachmentIds`, `rewriteAttachmentMarkdown`, etc.).
