# dom

React hands you a tree of components; the browser has a document underneath it, with a
caret, boxes that have real sizes, a viewport that shows only part of the page, and a
clipboard. Everything here answers **how do I read or drive that real document — and
where is the one place allowed to do it?**

Reach for:

| You want | Use |
|---|---|
| The **caret or highlight** the user made | `dom-selection` |
| The **size** an element actually has on screen | `element-size` |
| Whether an element is **on screen** | `in-view` |
| To **move a scroll container** — follow the bottom, scroll a child in, auto-scroll at an edge | `auto-scroll` |
| To tell the user a gesture **scrolled nothing** | `overscroll-hint` |
| To bring an element into view **because it just became the active one** | `scroll-reveal` |
| To put on the clipboard what an element **stands for**, not what it shows | `copy-source-text` |

Five of the seven are the single sanctioned home for an idiom a lint rule bans everywhere
else, so a new need is a reason to extend the primitive, never to hand-roll a copy beside
it:

| Primitive | The rule, and what it bans |
|---|---|
| `dom-selection` | `dom-selection-safety` / `no-raw-selection-range` — bare `getRangeAt` |
| `element-size` | `resize-observer-safety` / `no-raw-resize-observer` — `new ResizeObserver` |
| `in-view` | `intersection-observer-safety` / `no-raw-intersection-observer` — `new IntersectionObserver` |
| `auto-scroll` | `scroll-safety` / `no-adhoc-scroll-write` — `scrollTop =`, `scrollTo()`, `scrollBy()` |
| `scroll-reveal` | `scroll-safety` / `no-adhoc-scroll-into-view` — `el.scrollIntoView()` |

`overscroll-hint` and `copy-source-text` have no such rule. Both install themselves once
via `Core.Root` and listen at the document, so there is nothing per-consumer to hand-roll
in the first place.

Not here: `primitives/scope/dom-scope` also deals in DOM nodes, but it answers a different
question — *which mounted instance's node is mine*, when the same surface is open in
several tabs or panes at once. That is a lifetime question, so it lives in the `scope`
umbrella beside the other per-instance primitives.
