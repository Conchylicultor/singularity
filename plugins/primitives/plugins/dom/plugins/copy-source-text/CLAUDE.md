# copy-source-text

Copy what an element **stands for**, not only what it shows.

```tsx
// I stand in for something the reader can no longer see.
<span className="contents" {...copiesAsText("`control-panel`")}>{chip}</span>

// I substitute nothing — I just don't want to be broken across lines.
<span {...copiesAsOwnText}>…</span>
```

One `Core.Root`-mounted `copy` handler does the rest.

## Why

The clipboard's plain-text flavour is built by walking the **rendered** DOM, so
it can only carry what is on screen. Two consequences, one missing fact:

1. A rendering that replaced its source text cannot give it back. An
   active-data chip minted from `` `control-panel` `` copies as a bare word that
   no longer renders as a chip when pasted.
2. A `Badge`'s label lives in a truncating `<span>` that is a **flex item**, and
   CSS blockifies every flex item — so the serializer, which breaks a line
   around every block-level box, splits a chip in running text across three
   lines. `display:inline` on that span does not help (flex blockifies it back);
   removing `overflow:hidden` does not either (it is the flex item, not the
   overflow).

Fixing (2) in CSS is possible — `Badge` as one inline-block box, ellipsis on the
shell — but it cannot fix (1), since no CSS puts text on the clipboard that is
not on screen. Given the handler exists anyway, replacing a chip with a text
node removes its boxes too, and `Badge` keeps the flex layout its truncation
depends on.

## Gates

`installCopySourceText()` acts only when all four hold. Each protects a copy
somebody else is already right about — do not loosen them:

| gate | why |
|---|---|
| `!event.defaultPrevented` | a handler nearer the selection already wrote its payload (`diff-view`, Lexical). Bubble phase, so that decision has been made. |
| non-collapsed selection | nothing to copy |
| not inside `[contenteditable]` | editors own copy there; chips already do this via the node's `getTextContent()` |
| ≥1 declaring element selected | the native copy is already right |

Both flavours are written from the rewritten fragment: after `preventDefault`
the clipboard carries **only** what is set, so writing just `text/plain` drops
the HTML a rich target reads.

## Two things that look wrong and aren't

- **The fragment is mounted off-screen to read it.** `Range.toString()` loses
  every block break; the block-aware serializer is reachable only through
  `Selection.toString()`, which only points at the live document. Off-screen and
  not `display:none`, because the serializer walks layout and a hidden stage
  serializes as `""`. (Cost: ancestor-dependent CSS doesn't reach the clone.)
- **Nesting resolves outward with no precedence list.** A chip declares its
  token, the `Badge` inside it declares "my own text", and the token wins
  because `querySelectorAll` is document-ordered: the outer element is replaced
  first and carries the inner one out of the fragment.

## Who declares

| declaration | who | text |
|---|---|---|
| `copiesAsText(token)` | `active-data`'s `renderInlineChip` | the raw token |
| ``copiesAsText(`\`${t}\``)`` | `active-data`'s code chain, claimed arm | the token **with backticks** — a code chip is reachable only from inside a backtick span |
| `copiesAsOwnText` | `Badge` | its own label, unbroken |

Those two active-data sites are where the source characters stop being on
screen, which is why they are the ones that can declare them. Block widgets
(`<task>…</task>`) declare nothing on purpose: their rendered text is more
useful than their tag source.
