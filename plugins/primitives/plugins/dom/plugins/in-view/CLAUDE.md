# in-view

The single sanctioned home for the "is this element on screen?" idiom — the
repo's only `new IntersectionObserver`, hand-rolled in four places before this
primitive.

## API

- `createInViewWatcher(onChange, { root?, rootMargin?, threshold? })` → `InViewWatcher`
  The DOM layer, no React. Builds the observer immediately (`root` may be a ref,
  an Element, or omitted for the viewport) and returns `{ observe, disconnect }`.
  `observe(el)` is **idempotent**: the watcher holds a `WeakSet` of what it
  already watches, so a surface that re-enrolls its elements as they mount pays
  only for the new ones, and a torn-out element stays collectable. That rule
  lives in the watcher precisely so no consumer can omit it.

- `useInView(target, onChange, { root?, rootMargin?, threshold?, deps? })` → `void`
  The React layer: observes one element and runs `onChange` per delivery, with
  the **most recent** entry of the batch — for a single target that is its
  current state, whereas the first entry can be a superseded observation.
  `target` is a `RefObject` or a getter (`() => Element | null`), read at effect
  time; nothing resolved means nothing is built. `onChange` is stabilised
  internally, so the observer never re-subscribes on closure churn.

There is deliberately **no** `useIsInView(): boolean`. Both single-element
consumers write to a ref rather than to state precisely so a scroll costs no
render; a boolean form would have no caller and would invite one.

## `deps` is load-bearing, not ergonomics

Because `onChange` is stabilised, the observer is built once and **never rebuilt
unless `deps` changes** — and a rebuild is a feature, not an accident.

Infinite scroll fires page N+1 only because a fresh observer re-delivers against
the still-intersecting sentinel: the sentinel never moved, so nothing else will
ever ask about it again. Stabilise the callback, forget `deps`, and pagination
silently stalls after page 1 — nothing throws, nothing logs, the list just stops
growing.

So everything the caller wants the observer rebuilt on goes in `deps`:
`rootMargin`, `root`, `threshold`, a resolved target node, and any gate flag the
callback reads. In practice that is the dependency array the bespoke effect this
replaces already had — pass it through unchanged.

## Don't hand-roll `new IntersectionObserver`

Enforced by the `intersection-observer-safety` lint rule
([`no-raw-intersection-observer`](../../../../../framework/plugins/tooling/plugins/lint/plugins/intersection-observer-safety/lint/no-raw-intersection-observer.ts)),
whose allowlist has exactly one entry: this plugin's
`web/internal/in-view.ts`. Route on-screen detection through this primitive; if
you have a genuinely different need, extend the primitive rather than
allowlisting a copy.
