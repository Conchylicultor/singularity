# hover-reveal

## Not for row-action clusters

A cluster of trailing actions on a row, card or table row is
`primitives/row-actions`, which owns the pin/mask, popup-hold, click guards and
control size as one composite. This plugin is for a *single* affordance (a tab's
`×`, a block's controls, a resize handle) and for genuinely **nested** reveal
scopes — `useHoverReveal`'s per-instance JS state is the reason it exists, since
a shared `group/hover-reveal` cross-fires when reveal regions nest (see
`FilterGroupEditor` → `NestedGroupRow`). Rows never nest: trees flatten before
render.

## The focus reveal is keyboard-only

`groupProps.onFocus` sits on the container and React's `onFocus` bubbles, so it
fires for **any** descendant — the JS twin of `group-focus-within`. It therefore
reveals only when `e.target` matches `:focus-visible`; without that, clicking a
control inside the container pins the affordance once the pointer leaves (the
same defect `row-actions` keys on `:focus-visible` to avoid).

Chromium nuance, and it is the correct outcome: a text input IS focus-visible
even when clicked, so clicking a filter rule's value box does reveal that row's
remove button — the user is editing that row. The reveal ends when focus leaves.
