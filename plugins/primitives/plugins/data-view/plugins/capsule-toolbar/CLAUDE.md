# capsule-toolbar

A **toolbar arrangement** for the `data-view` primitive: the wide toolbar drawn
as one centred pill, the shape of a phone launcher's search bar. A surface opts
in by passing the value — `<DataView toolbar={capsuleToolbar} …>` — and the host
never names it (see the data-view CLAUDE.md, "Toolbar arrangements").

## What it renders

A raised `Surface`, `min(620px, 100%)` wide and 48px tall, fully rounded,
centred in the sticky toolbar band. Its border steps up to the `input` tone while
anything inside has focus. Left to right:

1. **View chip** — `switcher.chip` (`CollapsedViewSwitcher`): the active view,
   its menu holding the other views, Add view and View settings.
2. **Search** — the bare search field, the one grow cell. `/` focuses it
   (a surface-scoped shortcut, so it only fires in the focused tab); Escape
   clears and leaves it. It is always rendered, so a query never hides.
3. A vertical divider and the **control circles** (filter / sort / fields…).
4. Consumer `actions`, then the **round filled create button**.

Below 560px of capsule width (a container query on the capsule, not the
viewport) the divider and circles are hidden and `foldedControls` — every control
behind one circle — shows instead, so filter and sort stay reachable.

The circles' glyphs rest in the faint text tier (`text-faint-foreground`) and
lift to the text colour on hover; the search icon and placeholder are faint too,
the chip's view icon muted and its chevron faint.

The arrangement declares `spaceBelow: "50px"`: with the band's own 8px and the
icons view's 12px tile padding, the first row sits ~70px under the pill, as in
the approved launcher mock.

The surface `title` is not drawn: a page using the capsule states its own
heading above it. The compact fold (`density="compact"` or a toolbar under
360px) is the host's, and replaces the capsule entirely.
