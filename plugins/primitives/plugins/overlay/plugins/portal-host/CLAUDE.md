# portal-host

**Where a popup opened inside a region is drawn.** Popups (popover, dropdown
menu, select, tooltip, dialog, sheet) portal to the end of `document.body` so
no ancestor's `overflow` or stacking clips them. That is wrong in two places:

- **Under the Fullscreen API** the browser paints only the fullscreen element's
  subtree. A popup under `body` is invisible — a tooltip never shows, a
  popover opens into nothing.
- **Over an overlay stacked above the popup layer** (a `ViewportOverlay` at
  `layer="max"`), a popup under `body` is drawn beneath it.

Wrap such a region's contents in `<PortalHost>`. It appends one empty element
after them and hands it down as React context; every ui-kit portal wrapper
passes `usePortalContainer()` as its `container`, so a popup opened anywhere
inside — including from inside another hosted popup — is drawn in the region.
Outside any host the container is `undefined` and the library's default
(`body`) applies, so nothing else changes.

```tsx
<div ref={fullscreenRef} className="relative size-full">
  <PortalHost>
    <Stage />
  </PortalHost>
</div>
```

The host region must be a positioning context without a `transform`, so the
popups' own positioning still resolves against the viewport.

**Rule: an element you hand to `requestFullscreen()` wraps its contents in a
`PortalHost`.** First consumer: the prototypes `present` plugin's presentation
overlay.

## Why it imports nothing

`ui-kit` imports this plugin, so it must import **only `react`** — same
precedent as `popup-open` and `overlay-boundary`.
