# virtual-rows

- **`scrollMargin` follows the content above the region.** It is measured once
  the scroller is found, again in the commit that changes `items` (the
  observer's synchronous measure on re-subscribe — before paint), and
  whenever a box that decides it resizes (`element-size`'s `useResizeObserver` over every
  ancestor below the scroller and every element laid out before the region
  at each of those levels, a `display: contents` one standing for its
  children; re-collected with the items). Content above the rows moves the
  region in its scroller — together with them (a paged DataView's far pages
  swapped for a height-keeping placeholder before the list, and back) or
  without them (another section's placeholders above this one) — and a
  window still reading an older offset would draw rows where they no longer are. Pinned by
  `web/__tests__/scroll-margin.test.tsx`.

- **A size learned against a stale margin scrolls nothing.** The commit that
  changes `items` draws the window against the margin measured for the old
  ones (it is re-measured in that commit's layout phase, after the rows'
  refs measured them). When content above changed with the items, that
  window is a page away from the rows' real place, and the virtualizer's
  default would "compensate" rows first measured there — from its cached
  offset, which a scroll not yet reported makes the pre-scroll one, undoing
  the reader's step. `shouldAdjustScrollPositionOnItemSizeChange` is off
  until the margin is measured for the items drawn.
- **The estimate is a real row's size.** A number `estimateSize` is only a
  first guess: the hook hands the caller a `probe` ref for one invisible
  render of `items[0]` in the first commit (the window draws nothing yet),
  measured before paint; after that, unmeasured rows are estimated at the
  first measured row's size. A wrong estimate jolts the list by the error
  for every row first drawn above the reader. `VirtualRows` and
  `data-table`'s windowed body both render the probe.
