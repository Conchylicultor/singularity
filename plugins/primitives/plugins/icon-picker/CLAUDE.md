# icon-picker

Searchable, categorized picker over the **Material Symbols** set — the same set
every code icon draws from (`ui/icons`). The `avatar` primitive, the page icon
button and the callout appearance panel compose it. Design:
[`research/2026-09-27-global-saved-icons-material-symbols.md`](../../../../research/2026-09-27-global-saved-icons-material-symbols.md).

## Components

- `<IconPicker value onSelect />` — the icon block: a header, a search box, and a
  scrollable, categorized grid. `onSelect(name)` hands back the picked
  `SavedSymbolName` (a kebab-case Material Symbols name) — that name is ALL a
  caller stores. `<Icon icon={runtimeSymbol(name)}/>` draws it anywhere, in the
  surrounding theme scope's icon style. The data loads lazily on first mount, so
  mount it only when visible (e.g. inside an open popover). It renders *only* the
  icon UI — surrounding chrome (popover, extra rows) is the caller's job.

## The grid draws through runtime symbols

The picker ships no glyphs. The grid is windowed (`virtual-rows`) and every cell
is `<Icon icon={runtimeSymbol(name)}/>`, so only the rows on screen ask
`ui/icons` for their symbols — batched per frame into one immutable
`GET /api/icons/symbols/:hash/:key?names=…` per style — in the style the picked
icon will be drawn in.

## The data: vendored Google metadata

`web/internal/symbols-metadata.json` is Google's Material Symbols metadata
(`fonts.google.com/metadata/icons`: category, tags, popularity), trimmed to the
names the installed sets draw and ordered by category then popularity. Iconify's
own `metadata.json` has categories but no tags, and tags carry search ("robot" →
`smart-toy`). It is written by
`./singularity run plugins/primitives/plugins/icon-picker/scripts/gen-symbols-metadata.ts`
(network) and guarded by `icon-picker:symbols-metadata-in-sync`, which fails
when the installed `@iconify-json/material-symbols*` versions moved (rerun the
script) or the file was edited by hand (its content hash).

## Classic Material Icons → Symbols (`core`)

`CLASSIC_SYMBOL_NAMES` / `symbolNameForClassic(key)` — the frozen table every
icon saved before the move migrated through (the
`remap_saved_icons_to_symbols` data migration and the avatar config
migrations). Total over the 2 160 classic keys: snake → kebab (1 961), suffix
stripped (`_outline` / `_outlined` / `_alt`, 33), matched by codepoint in
Google's two `.codepoints` files (126), hand-picked where the codepoint named
several symbols or none (40). Generated once, then frozen; the test pins
totality, that every value is a symbol name, and that it is a fixed point.
Nothing new is ever stored under a classic key.

## It applies NO content inset

The block used to pad itself (`px-xs` on the header and the grid, `mx-1` on the
search field) on top of whatever its host padded. Inside a `ControlPanel` that
is a second inset owner: the panel already insets its content to the icon rail,
so the picker's own label, search field and grid landed 8px right of every other
block in the panel — the exact misalignment
[`control-panel`](../css/plugins/control-panel/CLAUDE.md)'s single-owner rule
exists to delete.

So the root is a plain `<Stack gap="xs">` with no padding, and the host supplies
the inset — for all three consumers today (the avatar picker, the page icon
button, the callout appearance panel) that host is a `ControlPanel.Section`, so
the picker lands on the panel's rail by doing nothing. A caller with no such
host owns its own inset, through `className`.
