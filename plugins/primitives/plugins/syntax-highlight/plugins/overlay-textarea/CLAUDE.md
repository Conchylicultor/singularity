# overlay-textarea

`<OverlayTextarea value onChange decorate ariaLabel placeholder? className?>` —
an editable field whose text is drawn **decorated** (syntax colours, typo
underlines) while staying a plain `<textarea>` for editing, selection, IME and
undo.

Two layers in one clipped, positioned box:

- an `aria-hidden` underlay `<pre>` rendering `decorate(value)` — **in flow**, so
  it sizes the box: the field grows as the user types or a line wraps, with no
  measuring and no `rows`;
- a transparent `<textarea>` with a visible caret, a full-bleed layer over it.

Both take one metrics class (padding, the `code` text role, `pre-wrap` +
`break-words`, tab-size), so glyphs, wrapping and the caret line up by
construction. The underlay appends a space after a trailing newline (a `<pre>`
drops that empty last line; the textarea does not), and holds the placeholder
invisibly while empty so the box is as tall as the hint.

**`decorate` contract**: render exactly the characters of `text`, in order —
spans and classes only. Changing a glyph's advance (font size, padding, a bold
wider than regular) drifts the caret.

`className` is the box's chrome (border, background, radius,
`focus-within:` ring), never metrics.

Follow-up: `page/code-block` hand-rolls the same pattern (its `METRICS` /
`underlayText`); migrate it onto this primitive (its underlay is shiki HTML,
so `decorate` would return the injected markup).
