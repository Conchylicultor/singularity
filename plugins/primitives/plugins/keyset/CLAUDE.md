# keyset

Null-aware keyset predicates over one key list (declared keys + a non-null pk
tiebreaker, ordered `NULLS LAST` both ways): `seekPredicate(keys, cut)` — the
rows strictly AFTER a cut — and `atOrBeforePredicate(keys, cut)` — the rows at
or before it, written as its own positive predicate rather than `NOT seek` (a
negated NULL comparison is NULL, and would drop rows). The two split any row set
exactly; `server/internal/at-or-before.test.ts` checks both against a real
Postgres `ORDER BY` over nullable / non-null keys in both directions. A scroll
segment's `after` / `until` cuts compile through them (query-resource).
