# sortable-list

The one way into `@dnd-kit` for a sortable list: `SortableList` owns the
context, sensors (pointer; keyboard with `keyboard`) and optimistic order;
`SortableItem` owns the node, the activator (`handle` → `handleProps`, ref
included) and the transform.

The transform is `CSS.Translate`, never `CSS.Transform`. With no `DragOverlay`,
dnd-kit scales the dragged item to the rect it is over, so `CSS.Transform`
squashes an item onto a differently-sized neighbour's aspect ratio. It is the
snippet in dnd-kit's own docs and invisible with equal-size items, which is why
it kept coming back. Two lint rules (`lint/`) close it:
`sortable-list/no-scaling-transform` bans `CSS.Transform` everywhere, and
`sortable-list/no-raw-dnd-kit` bans importing `@dnd-kit/*` outside the drag
primitives (this one, rank-reorder, tree, the page editor) — extend this
primitive rather than wiring `useSortable` by hand.
