# edit-mode-signal

The page-global edit-mode flag, and nothing else. `setEditMode(v)` writes it,
`getEditMode()` reads it once, `useEditMode()` subscribes a component to it.

```ts
import {
  setEditMode,
  getEditMode,
  useEditMode,
} from "@plugins/primitives/plugins/edit-mode-signal/web";
```

It is page-global on purpose — one chrome pen button toggles one edit mode for
every reorderable slot on every mounted surface — and the store carries the
`scoped-store/no-module-mutable-store` exemption that says so. Do not "fix" it
into a scoped store.

## Why it is a leaf, and not part of `reorder`

Two different kinds of plugin read this flag:

- the ones that **do** the reordering — `reorder`'s middlewares, the pen button;
- the ones that merely **restyle themselves while it is on** — `adaptive-bar`
  stops relocating widgets (a dnd-kit handle moved out of its `SortableContext`
  silently stops working), `collapsible-wrap` force-expands so every clipped chip
  is a reachable drag target.

The second group is `primitives/`. Reading a boolean should not cost them a
dependency on the reorder feature plugin — `reorder/web` side-effect-imports
`./styles.css`, and a `.css` module resolves only under the web tsconfig, so the
edge broke `type-check` the moment `adaptive-bar` became reachable from a
`core/`-included file (the layout-harness fixtures registry). A leaf whose only
import is `react` cannot do that to anyone.

> **The rule:** nothing under `primitives/` imports `@plugins/reorder/web` to
> read edit mode. Import this leaf instead.

(`collapsible-wrap` still imports `reorder/web` for `ReorderLayoutContext` — the
reorder *layout* it injects is genuinely reorder-domain, not a signal read.)

- Description: The page-global edit-mode signal — setEditMode / getEditMode / useEditMode — as a leaf primitive whose only import is react. Everything that reorder's edit mode restyles (a bar, a wrapping chip row) reads the signal without importing the reorder feature plugin.

  - Imported by:
