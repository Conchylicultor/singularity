# shortcuts

## Who gets a key

One window `keydown` listener (`ShortcutManager`) dispatches every registered
shortcut. Before matching, it yields the key to whoever already owns it:

- **An element that handled it** — an event already `defaultPrevented` (a tree
  or list walking its rows with the arrows, a row activated by Space) fires no
  shortcut. The window listener runs after React's root-delegated handlers, so
  their `preventDefault` is visible.
- **A text field / control acting on it natively** (`targetClaimsKey`) — plain
  keys only; modifier combos still fire, and a shortcut may opt in with
  `enableInInputs`.
- **Another surface** — a shortcut registered with `useSurfaceShortcuts` is
  eligible only while its surface is the focused one.

A raw key listener that bypasses the registry (allowed only with a lint
exemption, e.g. Sonata's hold-to-scrub seek) must apply the same three rules.
