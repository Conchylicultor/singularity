# geometry

The layout harness's geometry vocabulary, as a types-only leaf (plus the one
`HOST_MARKER_ATTR` constant both sides of a mutation spell):

- `FixtureDims` / `FixtureState` — the content × metadata × state cell a
  measured exhibit pins.
- `GeometryInvariant` — what the oracle asserts against the per-width
  measurements (the ten kinds plus `falsification`).
- `FixtureMutation` — the deliberate breaks a falsification applies.
- `GeometrySpec` — `{ dims, invariants }`, the optional `geometry` of an
  `isolated` exhibit (`plugin-meta/exhibits`).

**Why a separate leaf.** The exhibit catalog carries `GeometrySpec`, and the
harness consumes the catalog. Keeping these types in `layout-harness/core`
would make catalog → harness → catalog a cycle; here both depend on a leaf
that depends on nothing.
