# switch

The on/off switch. Two exports, and the split between them is the whole design.

- **`SwitchIndicator`** — the visual only: a track with a knob, in a `<span>`
  with no handler, no `role`, no `tabIndex`. Render it inside something that is
  **already** the click target (a control-panel row with `select="switch"`, a
  clickable settings row).
- **`Switch`** — the same indicator inside its own `<button role="switch">`, for
  use outside an already-interactive host.

Reaching for `Switch` inside a row that is itself a button nests a `<button>` in
a `<button>`. That is invalid DOM whose failure is silent — the inner click is
swallowed or falls through — so the presentational half exists to make the
mistake unavailable rather than merely discouraged.

One fixed size (28×16 track, 12 knob), mirroring `selection-indicator`'s single
`size-3` box: a switch that came in sizes would eventually disagree with the
checkbox beside it.

`Switch` spreads whatever else it is handed **before** its own attributes, so
nothing from outside can take over the role, the `aria-checked` or the click that
flips it. That matters the moment a render-prop host wraps one — a tooltip
trigger clones its own props, handlers included, onto the element it wraps, and
spread last one of those would quietly replace the switch's `onClick`, leaving a
switch that stops toggling exactly while its tooltip is up. For the same reason
`id` is left to ride the spread instead of being pulled out and re-applied: such
a host assigns the trigger an id, and re-applying an absent one would erase it.

The knob is **translated, not laid out** — one position rule, so the travel
distance stays `track − knob − 2×inset` in one place instead of becoming a
padding on the track that a flex direction could reinterpret.
