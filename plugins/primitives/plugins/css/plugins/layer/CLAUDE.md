# layer

The **full-bleed layer** — one `absolute inset-0` child of a caller-owned
positioned parent. The `absolute inset-0` family (~19 call sites) expressed as a
role.

## Sibling of Overlay, not a replacement

`<Overlay>` takes its layers as **props** (`behind` / `above`) wrapped around
required in-flow `children`, so the only shape it can express is "a box with
layers painted around its content". Three shapes it cannot express, all of which
occur in the corpus:

- the layer **is** an element — a full-bleed `<img>` wallpaper, a background
  `<svg>`, a transparent `<button>` capture surface;
- the layer is a plain **sibling** in a list of layers, not a wrapper;
- the layer is itself the **positioning host** for what it contains (a backdrop
  whose children pin to it, not to the surface above it).

Nineteen disable comments say some version of *"not an Overlay wrapping
content"*. That is this primitive.

Against `<Pin>` the split is the geometry: **Pin is the point anchor** (a corner,
an edge-center, dead center), **Layer is the full-bleed one**. Neither
establishes the positioning context — the parent does (`relative` is not banned)
— and an absolutely-positioned `<Layer>` is itself the containing block for its
own children.

## The class helper is the more important half

Most of the corpus sites are a raw `<img>` / `<svg>` / `<button>` / `<textarea>`
leaf, or a third-party component exposing only a `className`. Those cannot be
wrapped without changing what renders, so **`layerClasses()` — not `<Layer>` — is
the answer there**:

```tsx
<img src={src} alt="" className={cn(layerClasses({ decorative: true }), "size-full object-cover")} />
```

The question is *do you own the element?* Own it ⇒ `<Layer>` (it also carries
`as` / `ref`); don't own it ⇒ the helper. Neither supersedes the other, and a raw
`<div className="absolute inset-0">` under an `eslint-disable` is not a third
answer.

## Defaults live in `layerClasses()`, not in `<Layer>`

`<Layer>` forwards `layer` / `decorative` straight through — it declares no
default of its own, so there is exactly one place either value is written.

This is a **deliberate divergence from `pinClasses`/`<Pin>`**, where every
default is stated twice (once in the component's destructuring, once in
`pinClasses`' required-options contract) and can therefore drift. Don't "fix"
`<Layer>` to match Pin's shape; fix Pin's when it is next touched.

## Props

- **`layer`** — `InTreeLayer` stacking level (from `z-layers/web`). Default
  `base`, because a full-bleed layer's paint order is normally its DOM order.
  Always resolved via `zLayerClass()`, never a raw z number.
- **`decorative`** — `pointer-events-none`. Default false.
- **`as`** — host element. Default `div`. **`className`** composes last.

There is deliberately **no `offset` / `mask` / `stretch`.** All 30 `inset-0` sites
in the corpus are exactly `inset-0`; none wants a partial inset. A layer that
covers only part of its parent is a point anchor — that is `<Pin>`, which already
has the vocabulary for it.
