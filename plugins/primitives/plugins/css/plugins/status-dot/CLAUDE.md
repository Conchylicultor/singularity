# status-dot

## Size: density from context (no prop)

A `StatusDot`'s diameter has **no prop** — it tracks the ambient `ControlSize`
(`useControlSize`), mapping the four density tiers to the density token group's
`--status-dot-xs|sm|md|lg` (utilities `size-status-dot-*`; defaults 4 / 6 / 8 /
10px, the old `size-1` … `size-2.5`). So a theme sets a dot's size per tier
(the agent manager's Mist makes `md` 7px). Deliberate sizing is a
`<ControlSizeProvider size>` around the region (mirroring `Badge`), never a
per-instance `size`; passing one is a compile error (`size?: never`). The
no-provider default is `md`.

## Paint: filled or hollow (`StatusDotPaint`)

The paint is a discriminated union, so a dot is exactly one of:

- `{ colorClass }` — filled; the class paints the background.
- `{ ringClass }` — hollow; a 1px ring (drawn inside the diameter, so the dot
  keeps its size) around a transparent centre, the class painting the ring
  (`border-warning`).

A status vocabulary maps to `Record<Status, StatusDotPaint>` and spreads onto
the dot (`<StatusDot {...CONV_STATUS_DOT[status]} />`). A surface that draws its
own dot element (an avatar's presence overlay takes a class string) reads the
same paint through `statusDotPaintClass(paint)`.
