# space-ramp

The spacing ramp's **one declaration**: what the steps are, and what class each
step-keyed `@utility` family gives each step. No components — `spacing` owns
`<Stack>`/`<Inset>`, `rail` owns `railClass`; both read the ramp from here, as do
`column`, `cluster`, `inline`, `sticky`, `pin`.

## The scale

Runtime-themeable (it tightens with the density preset): the steps live in the
`density` token group as `--space-{2xs…2xl}`. `none` is the constant 0, no token.

| Step  | Comfortable | Replaces (raw) |
| ----- | ----------- | -------------- |
| `none`| 0           | `*-0`          |
| `2xs` | 0.125rem    | `*-0.5`        |
| `xs`  | 0.25rem     | `*-1`          |
| `sm`  | 0.5rem      | `*-2`          |
| `md`  | 0.75rem     | `*-3`          |
| `lg`  | 1rem        | `*-4`          |
| `xl`  | 1.5rem      | `*-6`          |
| `2xl` | 2rem        | `*-8`          |

`core/`-only on purpose: `railClass()` lives in `rail/core`, and the boundary
config's `core: ["core"]` means it can only reach another `core/`. Its own plugin
rather than `spacing/core` because `rail` importing "spacing" to look up
`rail-x-md` reads wrong.

## app.css is the source

`ramp.generated.ts` is generated from the `/* @ramp … */` decls in
`primitives/css/ui-kit/web/theme/app.css` (steps declared once; each section
declares its own families beside its own utilities):

```css
/* @ramp steps: none 2xs xs sm md lg xl 2xl */
/* @ramp families: gap gap-x gap-y p px py pt pr pb pl */
/* @ramp families: rail rail-x rail-y rail-owe */
```

The classes are what actually exists; the TypeScript is derived — so a step in
the union with no `@utility` behind it is unspellable. `space-ramp-gen.ts`
requires every declared family to carry every declared step (14 × 8), and
`space-ramp-in-sync` fails otherwise. The reverse is deliberately unchecked:
`p-chip`/`p-control`/`p-row`/`p-card` are legitimate non-ramp `p-` members.

Families are declared, **never inferred from suffixes** — `control-*`,
`control-icon-*` and `control-min-*` share four suffixes with the ramp but are a
separate 4-step scale.

**To add or rename a step:** add its `@utility` to all 14 families in app.css,
add `--space-<step>` to the `density` token group, update `/* @ramp steps: */`,
then `./singularity build`. Miss a family and the build names the missing
classes; miss the token and `css-vars-supplied` fails.

## API

- **`SpaceStep`** — the step union (from `SPACE_STEPS`).
- **`rampClass(family, step)`** — the class one family gives one step; both
  arguments are checked, so anything off the ramp is a tsc error.
- **`spaceLength(step)`** — a step as a CSS length (`var(--space-md)`, `0` for
  `none`), for the two places a class cannot reach: the inline `style` offsets in
  `<Sticky>` and `<Pin>`. The ramp declares no inset utilities.
- **`SPACE_STEPS`** / **`RAMP_CLASSES`** — the raw data, to enumerate.

**Never build a class name.** Tailwind emits an `@utility` only for a literal
token its scanner finds, so `` `pl-${step}` `` compiles to nothing and "works"
only when another file happens to spell the same class. Pass the step to
`rampClass`; the literals live in the generated table.
