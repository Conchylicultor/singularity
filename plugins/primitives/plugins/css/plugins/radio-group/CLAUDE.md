# radio-group

A single-choice group of native radios: `<RadioGroup options value onChange />`.

## Why `name` is not a prop

The HTML `name` is what natively groups radios: two groups sharing one `name`
**are one group** to the browser — picking an option in the first clears the
second, and arrow-key roving focus walks across both. A controlled `checked`
prop repaints the right dots anyway, so a collision is invisible on screen and
shows up only in keyboard nav and assistive tech.

So `name` is minted from `useId()` per mount and deliberately kept off the prop
surface. **Don't add a `name` prop** — the point is that callers have no literal
to collide on.

## Scope

Native, UA-drawn `<input type="radio">` tinted with `accent-primary`.
`selection-indicator`'s `RadioIndicator` is presentational and explicitly scoped
away from native form controls, so it does not apply here. Button-based
single-select groups (`toggle-chip`'s `SegmentedControl`) have no native `name`
and are a different control.

Radio-vs-dropdown choice stays with each consumer — that's field policy, not CSS.

## Enforcement

`lint/no-adhoc-radio.ts` bans intrinsic `<input type="radio">` outside this
plugin. Syntax-only: other input types, computed `type={…}`, and a
component-named `<Input>` flow through.

```ts
// eslint-disable-next-line radio/no-adhoc-radio -- reason
```
