# flock

`flockTry(fd)` / `flockRelease(fd)` over libc's `flock(2)`, dlopen'd lazily.

**Why this is its own plugin.** The binding was hand-rolled in two places
(`packages/host-semaphore`, `infra/worktree`'s push-lock probe) before a third
consumer — the CLI's `.build.lock` — needed it. Three copies of a `dlopen` is a
smell, so the syscall lives here once and the consumers import it.

**What the kernel buys you, and why it matters here.** An flock is owned by the
open file description, so it is released when the fd closes *or when the process
dies* — SIGKILL, OOM and power loss included — and no pid is ever consulted, so
PID reuse cannot confuse it. That is the property `infra/worktree` calls "the
ONLY crash-safe, PID-reuse-proof truth for 'is a push running'", and it is why
`bin/build-lock.ts` was migrated onto it: a build killed by a caller timeout can
no longer leave a lock nobody holds. A userland scheme has to *emulate* this with
a pid probe plus a heartbeat, and both of those emulations have holes.

**Only a non-blocking acquire is offered.** A synchronous FFI `flock(LOCK_EX)`
has no yield point — the thread it runs on is frozen until the lock frees, which
is never acceptable on an event loop. Callers that must wait poll `flockTry`
(the build lock) or push the blocking wait onto a worker thread
(`host-semaphore`'s `scripts/flock-block.ts`, which deliberately keeps its own
copy of the binding so it stays a standalone, independently-runnable script with
no cross-plugin imports).

**Not a lock manager.** No file opening, no path convention, no release-on-exit
hook — callers own their fd's lifetime. `packages/host-semaphore` builds bounded
N-slot pools on top; `bin/build-lock.ts` builds a size-1 mutex.
