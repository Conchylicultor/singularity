# resource-protocol

The live-resource wire protocol's failure vocabulary, as one leaf both ends
compile against: the resource runtime (`framework/resource-runtime`, per-worktree
and central) sends these frames and bodies, the live-state client
(`primitives/live-state`) reads them. A leaf because the runtime barrel pulls
`node:crypto` (the browser cannot import it) and the runtime must not import the
live-state client.

- `SubErrorReason` — `unknown-key` / `unauthorized` / `loader-failed` /
  `contract-mismatch` / `refused`.
- `ContractVerdict` + `contractVerdict(clientBuild, serverGraph)` — whose fault a
  mismatch is: `skew` (the tab runs another bundle; a reload fixes it — absent a
  build, the bundle predates this protocol, which is skew too), `same-build` (a
  real bug), `unknown` (a dev bundle, no served graph, central).
- `SubErrorFrame`, `ResourceHttpErrorBody` (+ `parseResourceHttpErrorBody`) — the
  WS frame and the JSON body of a failed HTTP read (404 / 409 / 422 / 500).
- `BUILD_GRAPH_HEADER` — the header an HTTP read names the client's build in; a
  `sub` / `sub-batch` frame carries the same value as `build`.
- `ResourceContractError` — thrown by a params DECODE (a subscription's wire
  params do not match the declaration). Declaration-time and encode failures stay
  plain `Error`s: those are programmer errors and must crash loudly. The runtime
  refuses such a sub before registering it; see
  `plugins/framework/plugins/resource-runtime/CLAUDE.md`.
- `ResourceRefusal` — an EXPECTED, caller-caused refusal a LOADER throws (well
  formed params, but a question that cannot be answered as asked: an unknown id,
  an empty range). The runtime sends its message to the reader (`refused`: HTTP
  422 `detail`, `sub-error.message`) and never reports it as a server failure;
  the client shows the message. Anything else a loader throws is
  `loader-failed`. Subclass it per domain (`MetricQueryError`).
