# Long lists in generated plugin references → summary + per-plugin `REFERENCE.md`

## Context

Each plugin's `CLAUDE.md` ends in an autogenerated `## Plugin reference` block
(`codegen/core/docgen.ts` → `renderPluginClaudeAutogen` → `renderDocFacts`, fed by the
`plugin-meta/facets/*` `renderDoc`s). Claude Code auto-loads it whenever an agent reads a file
in the plugin, so a long list costs tokens every time and gives little: no one acts on 378
importers.

Measured across the 1,340 plugin `CLAUDE.md` autogen blocks (2.19 MB in total):

| fact | total | worst |
|---|---|---|
| Web `Uses` | 397 KB | `page/editor` 81 lines |
| Cross-plugin `Imported by` | 289 KB | `css/spacing` 374 lines / 14 KB, `css/ui-kit` 378 / 13 KB, `ui/icons` 295 / 10 KB |
| Web `Contributes` | 80 KB | `reorder`: two **single lines** of 4.3 KB (`ConfigV2.Register ×226: "…", …`) |
| Web `Slots` | 45 KB | `Pane.Register ← a, b, … (2.4 KB, one line)`, `ConfigV2.WebRegister ← …` (2.2 KB) |

Two shapes cause the bloat:
1. **Long fact lists**, one value per line: `Imported by`, `Uses`.
2. **Lists packed into one value**, so capping the number of values never reaches them: the
   contributions facet's fold (`renderValues`, `FOLD_THRESHOLD = 12`), and the slots facet's
   `` `Slot` ← `a`, `b`, … `` contributor join.

The user set three constraints: keep one value per line (no comma-joining); keep the full lists
available in a *separate* generated file, not in `docs/plugins-details.md`; summarize
`Imported by` for heavily imported plugins.

## Design

### 1. A fact says how it can be summarized (facets `core`)

Extend `DocFact` (`plugins/plugin-meta/plugins/facets/core/facets.ts`):

```ts
export interface DocFact {
  folder: string;
  key: string;
  values: string[];
  /** Present ⇒ the list may be summarized when long. One group label per value
   *  (parallel to `values`, asserted equal length at render) and the noun to count. */
  summary?: { groups: string[]; noun: string };
}
```

The facet owns the semantics: how to group and what to call the items. Docgen owns the budget
and the rendering. A fact without `summary` (Exports, Routes, Exemptions, …) is never cut.
Exports are what an agent imports, so they stay complete. Docgen keeps naming no facet, as
the facets CLAUDE.md requires.

Opt-in facts:

| facet | fact | group per value | noun |
|---|---|---|---|
| cross-refs | `Imported by` | the importer's top-level umbrella (`apps`, `conversations`, …) | `plugins` |
| cross-refs | `Uses` (per runtime) | the used plugin (`primitives/css/ui-kit`) | `symbols` |
| contributions | `Contributes` | the slot key | `contributions` |
| slots | `Slot contributors` (new, see 3) | the slot | `contributors` |

### 2. Stop packing lists into one value (facets)

- **contributions**: delete the fold in `renderValues` (`FOLD_THRESHOLD`, the sorted label join).
  Every contribution is its own value again, rendered by `fmt(c)`. The values are still
  sorted inside a label-only group, so the order stays process-independent (the reason the
  fold sorted in the first place). The summary in 3 takes over the fold's job (collapsing
  `ConfigV2.Register` ×226), and it does so generically.
- **slots**: the `Slots` fact lists slot names only. A new `Slot contributors` fact carries one
  value per (slot, contributor), `` `Pane.Register` ← `apps.agent-manager.welcome` ``, grouped
  by slot. Small plugins see the same information, one per line instead of comma-joined.

Update the contributions facet's `CLAUDE.md` prose about the fold to match.

### 3. Docgen renders long summarizable facts as group counts (codegen)

In `renderDocFacts` (`codegen/core/docgen.ts`), a fact with `summary` and more than
`LIST_CAP = 20` values (constant beside `COMPACT_DESCRIPTION_MAX` in `description-text.ts`,
renamed to a `doc-budget.ts`) renders one line per group, largest first (ties broken by name),
and points at the full list:

```
- Cross-plugin:
  - Imported by: 378 plugins — full list in [REFERENCE.md](./REFERENCE.md#cross-plugin-imported-by)
    - primitives: 100
    - apps: 67
    - conversations: 50
    - …every group, one per line
```

```
- Web:
  - Contributes: 462 contributions — full list in [REFERENCE.md](./REFERENCE.md#web-contributes)
    - `ConfigV2.WebRegister`: 227
    - `ConfigV2.Register`: 226
    - `Shell.Toolbar`: 1 → shown as the value itself, `` `Shell.Toolbar`: Reorder toggle ``
```

A group of exactly one value prints that value instead of `: 1`, so nothing small is hidden
behind the link. All groups are listed, with no "top N + other": umbrellas are about 25 and
slots per plugin are few. The summary is one value per line, so a new importer changes one
count line and not a blob.

The same `renderDocFacts` builds `docs/plugins-details.md`, so the details doc shrinks too and
links each capped list to the plugin's `REFERENCE.md` (relative path from `docs/`). That is
intended: the details doc should index, not hold every list.

### 4. New generated file: `plugins/<p>/REFERENCE.md`

- Written **only for plugins that have at least one capped fact** (about 150 today at cap 20).
  It is fully generated: a header (`# <name> — full reference lists`, "generated, do not edit,
  summarized in CLAUDE.md"), then one `## <Folder> — <Key> (N)` section per capped fact, one
  value per line, in the facet's order.
- Its name is not `CLAUDE*.md`, so Claude Code never auto-loads it. It sits next to the
  `CLAUDE.md` that links to it, so agents find it by relative path, not by searching a 2 MB doc.
- `generatePluginDocs` writes it through `writeGenerated` and **deletes** it from a plugin
  whose lists no longer overflow. It also removes the stale `docs/plugins.md` it currently
  removes best-effort; the new delete must fail loudly instead.
- `plugins-doc-in-sync` (`checks/plugins/plugins-doc-in-sync/check/index.ts`) also compares
  each expected `REFERENCE.md` and fails on an orphan (a `git ls-files 'plugins/**/REFERENCE.md'`
  entry whose plugin expects none). Export `renderPluginReferenceMd` /
  `pluginReferenceMdPath` from `codegen/core` beside `renderPluginClaudeMd`.
- `.gitattributes`: add `plugins/**/REFERENCE.md merge=regen-generated` under "Plugin docs
  (fully generated)". Confirm that the `regen-generated` normalize pass
  (`cli/plugins/normalize-generated`) rebuilds it via `generatePluginDocs`. If it keeps a
  hard-coded file list, add the glob there.
- Update the doc headers: `COMPACT_HEADER` / `DETAILS_HEADER` get one sentence ("a long list
  is summarized; its full form is in the plugin's `REFERENCE.md`"). Update the root CLAUDE.md
  bullet "Search before writing a helper…", which points at `docs/plugins-details.md` for
  reverse indexes, to name `REFERENCE.md`.

### Expected effect

At cap 20, `Imported by` + `Uses` alone save about 245 KB across 149 facts. `css/ui-kit`'s
`CLAUDE.md` goes from 40.6 KB to roughly 28 KB, and `reorder`'s from 28 KB to about 20 KB. No
generated line exceeds about 300 chars except descriptions. `docs/plugins-details.md` drops by
a similar amount (about 300 KB).

## Critical files

- `plugins/plugin-meta/plugins/facets/core/facets.ts`: the `DocFact.summary` field.
- `plugins/plugin-meta/plugins/facets/plugins/cross-refs/facet/index.ts`: groups for
  `Imported by` and `Uses`.
- `plugins/plugin-meta/plugins/facets/plugins/contributions/facet/index.ts`: drop the fold and
  add the groups (`renderValues`, `slotKeyOf`). Update its `CLAUDE.md` too.
- `plugins/plugin-meta/plugins/facets/plugins/slots/facet/index.ts`: split `Slots` /
  `Slot contributors`.
- `plugins/framework/plugins/tooling/plugins/codegen/core/docgen.ts`: the cap, the summary
  render, the `REFERENCE.md` render, write and delete. Plus `description-text.ts` (budget
  constant) and `core/index.ts` (exports).
- `plugins/framework/plugins/tooling/plugins/checks/plugins/plugins-doc-in-sync/check/index.ts`:
  check `REFERENCE.md` and orphans.
- `.gitattributes`, `cli/plugins/normalize-generated` (if it lists files), root `CLAUDE.md`
  (one bullet).

## Tests

- `codegen/core/docgen.test.ts` (new, or beside `description-text.test.ts`): a fact at
  `LIST_CAP` renders in full. At `LIST_CAP + 1` with `summary` it renders the count line plus
  groups (largest first, a singleton group shows its value). Without `summary` it renders in
  full. A groups/values length mismatch throws. The reference render lists every value.
- Contributions facet: the fold test is replaced by "a label-only group of 226 renders 226
  values in sorted order".

## Verification

1. `./singularity build` regenerates every doc. Then:
   - `git diff --stat` shows about 150 new `REFERENCE.md` files and smaller `CLAUDE.md` files.
   - `plugins/primitives/plugins/css/plugins/ui-kit/CLAUDE.md` shows `Imported by: 378 plugins`
     plus umbrella counts, and its `REFERENCE.md` lists all 378.
   - `plugins/reorder/CLAUDE.md` has no line over 300 chars, and its `REFERENCE.md` lists each
     `ConfigV2.Register` label on its own line.
   - Re-run the measurement script (line lengths over 2 KB across `plugins/**/CLAUDE.md`): it
     finds none.
2. `./singularity check plugins-doc-in-sync` passes. Hand-delete one `REFERENCE.md`, then
   create one for a plugin with no long list: the check fails on both.
3. `./singularity test plugins/framework/plugins/tooling/plugins/codegen plugins/plugin-meta/plugins/facets`.
4. Run a second `./singularity build` and confirm a zero diff (determinism).
