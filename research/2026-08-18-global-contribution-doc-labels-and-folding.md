# Contribution doc lines: give web registrations their id, fold long same-slot runs

## Context

`docs/plugins-details.md` is the reference agents open on demand to find an existing
helper before writing a new one. Inside it, the `reorder` plugin's Web section is 212
byte-identical lines:

```
  - Web:
    - Contributes:
      - `ConfigV2.WebRegister`
      - `ConfigV2.WebRegister`
      … ×212
```

They tell a reader nothing except "there are a lot of these". Twenty lines further
down, the **same plugin's server half** spells the very same set out properly —
`ConfigV2.Register "action-bar.item"`, `ConfigV2.Register "conversation.header"`, … —
because each registration does have an identity: one config directive per reorderable
slot, planted under the slot's declaring plugin.

**Root cause.** Both runtimes' contribution factories take the same optional
`docLabel` extractor, and the doc renderer prints its result in quotes:

| | definition | result |
|---|---|---|
| server | `defineServerContribution<ConfigRegistration>("ConfigV2.Register", { docLabel: (c) => c.descriptor.name })` | `` `ConfigV2.Register` "conversation.header" `` |
| web | `defineSlot<{descriptor, pluginId?}>("config-v2.web-register")` | `` `ConfigV2.WebRegister` `` |

`plugins/framework/plugins/web-sdk/core/slots.ts` already accepts
`opts.docLabel` and stamps `_doc.label` exactly like its server twin
(`plugins/framework/plugins/server-core/core/contributions.ts`), and ~130 slots across
the repo opt in. `ConfigV2.WebRegister` is simply one of the few that never did.
Nothing about the extraction, the AST parsing, or reorder's own code is at fault.

**Second problem, which labelling alone does not solve.** Once every web line names
its config id, reorder's entry becomes 212 informative web lines *plus* 212 informative
server lines carrying the same ids — and `config_v2`'s own `registrations-paired` check
guarantees the two sets are always 1:1. That is ~430 lines of a 30,098-line doc spent
restating one list twice.

**Intended outcome.** No contribution line is information-free, and a long run of
same-slot registrations costs one line instead of hundreds — with every id still
present and greppable.

## Approach

Two changes, both small.

### 1. Give `ConfigV2.WebRegister` its label

`plugins/config_v2/web/internal/slots.ts` — pass the same extractor its server twin
uses:

```ts
WebRegister: defineSlot<{ descriptor: ConfigDescriptor; pluginId?: PluginId }>(
  "config-v2.web-register",
  { docLabel: (c) => c.descriptor.name },
),
```

Mirrors `plugins/config_v2/server/internal/contribution.ts` byte for byte. Safe for
runtime consumers: `useConfigRegistrations` and `storePathOf`
(`web/internal/store-path.ts`) read named fields (`descriptor`, `pluginId`,
`_pluginId`) and never enumerate keys, so an added `_doc.label` is inert. The facet's
`contributionsToComparable` reads `data.static` only, so no diff/catalog surface shifts.

### 2. Fold a long same-slot run onto one line

`plugins/plugin-meta/plugins/facets/plugins/contributions/facet/index.ts`, in
`renderDoc`. Today it maps every runtime contribution through `fmt` one-per-line. Add a
grouping pass over each of the `web` / `server` arrays:

- Group entries by their rendered slot key (`slotDisplayName ?? slotId`), keeping each
  group at the position of its first member — no re-sorting, so the regenerated diff
  stays honest.
- **Fold only when the fold is lossless**: the group has more than `FOLD_THRESHOLD`
  (12) members *and* every member renders as slot + label only — i.e. each has
  `doc.label`, and none has `doc.detail` or `componentName`. Any group failing either
  test renders per-line exactly as today.
- A folded group emits one value:

  ```
  - `ConfigV2.WebRegister` ×212: "action-bar.item", "agents.list", "conversation.header", …
  ```

  **Every** id is listed — no truncation, no "N more" — so `grep conversation.header`
  still finds it.

`renderDoc` returns opaque strings that `renderDocFacts`
(`plugins/framework/plugins/tooling/plugins/codegen/core/docgen.ts`) prints one per
markdown list item, so the folded value needs no renderer change. Long single lines are
already the norm there (the `Slots: X ← a, b, c, …` reverse index renders the same way),
and generated docs are not prose-wrapped.

Keep the threshold in the contributions facet, not in `renderDocFacts` — only this
facet knows whether a value is label-only, which is what makes folding lossless.

Document the rule in the hand-written prose of
`plugins/plugin-meta/plugins/facets/plugins/contributions/CLAUDE.md` (above the
`AUTOGENERATED:BEGIN` marker).

### What today's data does

Measured against the current `docs/plugins-details.md` (threshold > 12): **639 lines
saved**, four slot kinds affected —

| slot | where | entries |
|---|---|---|
| `ConfigV2.WebRegister` | `reorder` web (+1 other block) | 212 |
| `ConfigV2.Register` | `reorder` server (+1 other block) | 212 |
| `SonataAudio.Instrument` | sonata soundfont | ~100 |
| `Shortcuts.Shortcut` | apps-core floating | ~15 |

All four already render as slot + quoted label with no component name, so all four fold
losslessly.

Explicitly **not** doing (decided with the user): no new check guarding against future
slots defined without a `docLabel`.

## Files

- `plugins/config_v2/web/internal/slots.ts` — add `docLabel`.
- `plugins/plugin-meta/plugins/facets/plugins/contributions/facet/index.ts` — group +
  fold inside `renderDoc`.
- `plugins/plugin-meta/plugins/facets/plugins/contributions/CLAUDE.md` — prose note.
- Regenerated by the build, not hand-edited: `docs/plugins-details.md`, and the
  `AUTOGENERATED` block of every affected `plugins/**/CLAUDE.md` (notably
  `plugins/reorder/CLAUDE.md`, which drops ~420 lines).

## Verification

1. `./singularity build` (background — it regenerates the docs, then runs
   `plugins-doc-in-sync`, which fails on any drift between the facet output and the
   committed files).
2. Read the generated diff deliberately — it is the real deliverable:
   - `git diff $(git merge-base HEAD main) -- docs/plugins-details.md | head -200`
   - `git diff --stat $(git merge-base HEAD main)` — confirm the only non-source files
     touched are `docs/plugins-details.md` and `CLAUDE.md` AUTOGEN blocks.
3. Confirm reorder's block is now two folded lines carrying real ids:
   `rg -A3 '^- \*\*`reorder`\*\*' docs/plugins-details.md`
4. Confirm no id was lost in the fold — every server id still appears in the doc:
   `grep -c 'conversation.header' docs/plugins-details.md` (and spot-check a few from
   `plugins/reorder/shared/reorderable-slots.generated.ts`).
5. Confirm zero information-free lines remain:
   `grep -c '`ConfigV2.WebRegister`$' docs/plugins-details.md` → **0**.
6. `./singularity check` — `plugins-doc-in-sync`, `type-check`, and config_v2's
   `registrations-paired` all clean.
7. Sanity-check the app still reads config: open
   `http://att-1787004352-y9l7.localhost:9000`, enter reorder edit mode (pen button)
   and reorder a slot — proving `useConfigRegistrations` / `useSetConfig` are unaffected
   by the added `_doc` field.
