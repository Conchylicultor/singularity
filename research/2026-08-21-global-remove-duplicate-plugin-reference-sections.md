# Remove duplicate hand-written `## Plugin reference` sections from plugin CLAUDE.md files

## Context

When the autogenerated CLAUDE.md system was introduced, `renderPluginClaudeMd()` appended a `BEGIN…END` block to each plugin's CLAUDE.md. That block always opens with `## Plugin reference`. Files that already had a hand-written `## Plugin reference` section ended up with two copies: the stale hand-written one immediately above the `<!-- AUTOGENERATED:BEGIN … -->` marker, and the fresh autogenerated one inside the block.

The `plugins-doc-in-sync` check only validates the content inside the autogenerated block and leaves the prose prefix untouched, so the duplicates silently persist and drift.

**Scope:** 53 plugin CLAUDE.md files have this duplicate. One special case (`conflict-agent/CLAUDE.md`) also has a dangling `<!-- AUTOGENERATED:END -->` with no matching BEGIN above it, left behind from a manual edit that removed the original BEGIN.

The autogenerated block is already the authoritative, more complete source of truth for plugin references. The hand-written copies predate the autogen system and can be safely removed.

## Approach: structural fix in the codegen

Rather than manually editing 53 files, fix `renderPluginClaudeMd()` to strip any hand-written `## Plugin reference` section (and any dangling `AUTOGENERATED:END` marker) from the prose prefix when it regenerates a file. Running `./singularity build` then cleans all 53 files in one pass.

This is the structural fix: the root that generated the duplicate also removes it, so future files can never accumulate the stale section.

## Implementation

**File:** `plugins/framework/plugins/tooling/plugins/codegen/core/docgen.ts`

**Function:** `renderPluginClaudeMd()` (around line 252)

### What the function currently does

```typescript
// (simplified)
const beginIdx = existing.indexOf(BEGIN)
if (beginIdx === -1) {
  // No existing block — append
  return existing.trimEnd() + '\n\n' + BEGIN + '\n\n' + body + '\n\n' + END + '\n'
}
const endIdx = existing.indexOf(END, beginIdx)
const prosePart = existing.slice(0, beginIdx)  // everything before BEGIN
const suffix = existing.slice(endIdx + END.length)  // everything after END
return prosePart + BEGIN + '\n\n' + body + '\n\n' + END + suffix
```

### Changes needed

After computing `prosePart`, strip:
1. Any hand-written `## Plugin reference` section (the last such section in the prose, and all its content)
2. Any dangling `<!-- AUTOGENERATED:END -->` line left from malformed files

```typescript
// Strip any hand-written ## Plugin reference section from the prose prefix.
// The autogenerated block is the authoritative source; a hand-written copy
// that predates it has no value and drifts silently.
const refIdx = prosePart.lastIndexOf('\n## Plugin reference\n')
let cleanProse = refIdx !== -1
  ? prosePart.slice(0, refIdx) + '\n'
  : prosePart

// Strip any dangling AUTOGENERATED:END marker (conflict-agent anomaly:
// a prior manual edit removed the matching BEGIN, leaving a lone END).
cleanProse = cleanProse.replace(/<!--\s*AUTOGENERATED:END\s*-->\n?/g, '')

return cleanProse + BEGIN + '\n\n' + body + '\n\n' + END + suffix
```

The `lastIndexOf` picks only the last `## Plugin reference` in the prose prefix, which is always the stale duplicate (all 53 files have it as the final prose section, immediately above `BEGIN`). Content earlier in the prose — genuine hand-written prose sections — is untouched.

### "Append" path (new file, no existing BEGIN)

The append path is unaffected. New files won't have a stale hand-written section.

### Special case: conflict-agent

`plugins/config_v2/plugins/settings/plugins/conflict-agent/CLAUDE.md` has:
- Hand-written `## Plugin reference` at line 36
- A dangling `<!-- AUTOGENERATED:END -->` at line 51 (no matching BEGIN)
- A proper `BEGIN…END` block at lines 53–66

With the fix:
- `BEGIN` is found at line 53
- `prosePart` = lines 1–52 (includes the dangling END at line 51)
- `lastIndexOf('\n## Plugin reference\n')` finds line 36 → stripped
- The dangling END regex also strips the stray marker at line 51
- Result is clean prose, then the updated autogenerated block

## Verification

1. Run `./singularity build` — this runs `renderPluginClaudeMd()` on every CLAUDE.md, which cleans up all 53 files.
2. Run `./singularity check plugins-doc-in-sync` — should pass since the autogen blocks are unmodified; only the stale prose was removed.
3. Spot-check a few files to confirm: `plugins/primitives/plugins/collapsible/CLAUDE.md`, `plugins/debug/plugins/memory/CLAUDE.md`, `plugins/config_v2/plugins/settings/plugins/conflict-agent/CLAUDE.md`.

## Files to modify

Only one source file changes:

- `plugins/framework/plugins/tooling/plugins/codegen/core/docgen.ts` — the `renderPluginClaudeMd()` function

The 53 CLAUDE.md files are then regenerated automatically by `./singularity build`.

## Non-goals

- The 10 files with hand-written `## Public API` or `## Exports` headings (different names, no duplication) are **fine** — leave them alone.
- No new check is needed: the codegen fix is self-healing, so there is nothing left to enforce.
