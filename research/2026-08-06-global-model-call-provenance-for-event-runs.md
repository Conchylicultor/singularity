# Model-call provenance: seeing the prompt & output behind an Events run

## Context

The Events app's `url` source type turns a web page into structured events with a
one-shot Sonnet call (`runClaudePrint` in
`plugins/apps/plugins/events/plugins/sources/plugins/url-extract/server/internal/extract.ts`).
When a run extracts nothing, extracts the wrong thing, or dies on
`NonRetryableError: could not parse the extraction response`, the run row in the
source side-pane's **Runs** section reports the outcome and the counts — but not
*what the model was asked* or *what it said back*. That is the one artifact that
actually explains the outcome, and today it is unreachable from the Events app.

The text is not lost: every `claude --print` call is already recorded durably in
`claude_cli_calls` (prompt, system, output, error, model, duration) and rendered
by **Debug → Claude CLI Calls**. What is missing is a *link* — nothing ties a
recorded call back to the domain record it was made for. Six callers across the
repo (story generation, workflow steps, conversation category, turn summary, task
title, url-extract) all stuff domain ids into an untyped `sourceContext` blob, and
no feature plugin reads them back.

So this change is two things:

1. **A reusable primitive** — `infra/claude-cli` gains a first-class correlation
   id, so any plugin can ask "which model calls produced *this* record?" and get a
   typed answer, including an honest "the log no longer retains it".
2. **Its first consumer** — a run row in the Events Runs section gets a row action
   that opens a side pane whose **Model call** section renders that run's prompt
   and output.

Naming: this is a **model call**, not a conversation. `runClaudePrint` is a
one-shot, tool-less, non-persisted `claude --print` invocation — there is no
session to resume and no turn history. The UI should say "Model call" everywhere
so nobody goes looking for a transcript that does not exist.

Two decisions taken up front (confirmed with the user):

- **Link, don't copy.** The call log stays the single copy of the text. It is
  trimmed to the 1000 most recent calls globally, so a run older than that horizon
  says so explicitly rather than rendering blank. No prompt/output duplication into
  the events schema, and no "there is an LLM here" leaking into the generic ledger.
- **Row action → side pane**, not an inline expander or a dialog. A run drills into
  its own pane, exactly the shape `deploy/deployments` uses (`dep/:deploymentId`
  under `server/:serverId`, with `DeploymentDetail.Section` contributions).

## Design

### 1. `infra/claude-cli` — correlation as a typed primitive

**The end-user experience**, written first:

```ts
// producer — stamp a call with the record it was made for
await runClaudePrint({
  tier: "sonnet",
  prompt,
  source: { name: "events.url-extract", correlationId: ctx.runId, context: { sourceId, url } },
});

// consumer — ask what the model was asked, for this record
const calls = useClaudeCliCalls({ correlationId: run.id, occurredAt: run.startedAt });
//   → { status: "calls", calls: [...] }   render them
//   → { status: "none" }                  this record never made a model call
//   → { status: "not-retained" }          it did, but the log has since trimmed it
```

Changes:

- `core/resources.ts` — append `correlationId: nullable(textField())` to
  `claudeCliCallFields` (append, not insert: the record is documented as "keys in
  column order"). Both the table and `ClaudeCliCallSchema` derive from it, so no
  drift is possible.
- `server/internal/tables.ts` — add
  `index("claude_cli_calls_correlation_id_idx").on(t.correlationId)`. The migration
  is generated by `./singularity build`; never by hand.
- `server/internal/run-claude-print.ts` — `RunClaudePrintInput["source"]` gains
  `correlationId?: string`, threaded into `recordClaudeCliCall`. Document that it
  must be a globally unique row id (a UUID), since the column is not namespaced by
  `sourceName`.
- `core/` — a new endpoint, with a **discriminated response** rather than a bare
  array, because "no calls" has three genuinely different meanings and a `[]` would
  collapse them (`no-absorbed-failure`; same shape as `RefreshSourceResultSchema`
  in `events-core/core/internal/endpoints.ts`):

  ```ts
  export const ClaudeCliCallsResultSchema = z.discriminatedUnion("status", [
    z.object({ status: z.literal("calls"), calls: z.array(ClaudeCliCallSchema) }),
    z.object({ status: z.literal("none") }),
    z.object({ status: z.literal("not-retained") }),
  ]);

  export const listClaudeCliCallsFor = defineEndpoint({
    route: "GET /api/claude-cli/calls",
    query: z.object({ correlationId: z.string(), occurredAt: z.coerce.date().optional() }),
    response: ClaudeCliCallsResultSchema,
  });
  ```

- `server/internal/list-calls.ts` (new) — the reader. `not-retained` is reported
  **only** when the log is genuinely at capacity *and* the record predates the
  oldest surviving call: `count(*) >= RECENT_CALLS_LIMIT && occurredAt <
  min(created_at)`. Without the capacity check, a fresh install would libel every
  record as trimmed.
- `web/` (new barrel — the plugin has only `core/` + `server/` today):
  - `useClaudeCliCalls({ correlationId, occurredAt })` over `useEndpoint`.
  - `<ClaudeCliCallDetail call={…} />` — the presentational system / prompt /
    output / error / meta block. Lifted verbatim from the expanded half of
    `plugins/debug/plugins/claude-cli-calls/web/components/call-row.tsx`, which then
    **composes it** instead of owning it. The primitive owns how a call is
    displayed; the Debug pane keeps only its collapsed header + preview line.

  No cycle: `claude-cli/core` already imports `conversations/model-provider/core`
  one-way, and `model-provider` does not import `claude-cli`.

### 2. `events-core` — the run's identity, available *during* the run

`ProbeContext<TConfig>` gains `runId: string`, documented as: *the run this phase
belongs to — stamp any durable side effect (a model call, a fetched artifact) with
it so the ledger row can find it afterwards.* Generic by construction; it names no
LLM, and a future source type that caches a fetched artifact uses the same id.

Also add a single-run read so the pane can resolve a deep link without depending on
whatever window the list happens to have loaded:

- `core/internal/endpoints.ts` — `getEventSourceRun`,
  `GET /api/events/runs/:runId`, response `EventSourceRunSchema`.
- `server/internal/sources-repo.ts` — `requireRun(runId)`, 404 on absent (mirror
  `requireSource`), wired in `handlers.ts` beside `handleListRuns`.

### 3. `events/refresh` — mint the run id at the start, still write the row at the end

`run-source.ts` mints `const runId = randomUUID()` before `markSourceRunning` and
passes it through `probeContext(source, runId)` and into every `finish*` call.
`run-ledger.ts`'s `completeRun` takes the id instead of minting its own.

This is a **nuance worth documenting, not a reversal**: the ledger's stated
invariant is that the *row* is written only at the end, so every row is complete by
construction. That still holds — only the *identity* moves earlier, which is what
lets in-flight work name the run it belongs to. Update the header comment in
`run-ledger.ts` and the "The ledger is written at the end, not the start" section of
`plugins/apps/plugins/events/plugins/refresh/CLAUDE.md` to say exactly that.

### 4. `url-extract` — stamp the call

One line in `server/internal/extract.ts`: add `correlationId: ctx.runId` to the
`source` object. The existing `context: { sourceId, url }` stays — it is what makes
the Debug pane row readable.

### 5. `runs` — a run-detail pane with contributed sections

`plugins/apps/plugins/events/plugins/sources/plugins/source-detail/plugins/runs/`
mirrors its own parent (`sources/web/{slots.ts,panes.tsx}`) byte-for-byte in shape:

- `web/slots.ts` (new):
  - `RunActions = defineItemActions<EventSourceRun>("events.source-runs.item-actions")`
  - `EventSourceRunDetail = defineDetailSections<{ runId: string }>("event-source-run-detail")`
- `web/panes.tsx` (new):
  ```ts
  export const eventSourceRunPane = Pane.define({
    id: "event-source-run",
    defaultAncestors: [eventSourceDetailPane],
    segment: "run/:runId",          // globally unique after param erasure
    component: EventSourceRunPaneView,
    resolve: useResolveRun,          // over GET /api/events/runs/:runId
    useTitle: …,                     // e.g. the outcome + relative start
    width: 460,
  });
  ```
  The pane body is a run summary header (outcome chip, counts, duration,
  fingerprint, error verbatim) plus `<EventSourceRunDetail.Host runId={runId} />`.
  Pane params are **own-only** (`pane.ts` design decision 6), which is precisely
  why the run is fetched by its own id rather than reached through the parent's
  `sourceId`.
- `web/components/open-run-action.tsx` (new) — a `RowActionButton` contributed by
  `runs` itself into its own slot, exactly as `sources` contributes
  `SourceDeleteAction` into `EventSourceActions`. `onClick` → `openPane`, with
  `e.stopPropagation()`.
- `web/components/runs-section.tsx` — add `itemActions={RunActions}` to the
  `<DataView>`. It composes cleanly with the existing
  `viewOptions.list.renderRow`: `renderRow` replaces only the row *body*, while
  item actions render in the `Row` primitive's hover-revealed trailing region
  regardless.
- `web/index.ts` — export the slots + pane, register the pane, contribute the
  action.

`runs` still names no LLM anywhere.

### 6. `runs/plugins/model-call` — the section (new sub-plugin)

Contributes `EventSourceRunDetail.Section({ id: "model-call", label: "Model call",
icon: MdAutoAwesome, component: ModelCallSection })` — `MdSmartToy` is banned
repo-wide by `icon-safety/no-robot-icon`; `MdAutoAwesome` is the codebase's
canonical AI glyph. It fetches the run (same
endpoint, same query key) for `startedAt`, then calls
`useClaudeCliCalls({ correlationId: runId, occurredAt: startedAt })` and renders
each arm of the union — no `??`, no collapsing:

| arm | what the user sees |
| --- | --- |
| `calls` | one `<ClaudeCliCallDetail>` per call (system, prompt, output or error, model, duration) |
| `none` | "No model call was recorded for this run." — the honest and *expected* answer for a cheap `unchanged` run, where the fingerprint matched and extraction was deliberately skipped |
| `not-retained` | "The call log no longer retains this run's model call." |

The section declares `useAvailable` returning `true` while pending — loading is not
emptiness (the `source-detail` house rule).

Its `CLAUDE.md` must say why the section lives here rather than in `runs`: the
ledger is generic over source types, and only *some* source types pay for a model
call. It reaches the calls through `infra/claude-cli`'s generic correlation API and
names no source type either — a future non-LLM source type simply produces runs
whose section reports `none`.

## Verification

1. `./singularity build` — generates the `claude_cli_calls.correlation_id`
   migration, regenerates the plugin registries + docs, and seeds the reorder config
   for the two new slots. Confirm `~/.singularity/worktrees/<wt>/build-status.json`
   reports `status: ok`.
2. `./singularity check` — `migrations-in-sync`, `plugins-registry-in-sync`,
   `plugins-doc-in-sync`, `plugin-boundaries`, `type-check`.
3. In the app at `http://<worktree>.localhost:9000/events/sources`: open a `url`
   source, **Schedule → Refresh now**, wait for the run to land.
   - Hover the newest run row → the action appears → it opens the run pane as a
     third Miller column, with a **Model call** card showing the system prompt, the
     full extraction prompt (URL + hint + page text) and the model's raw JSON.
   - Refresh again without the page changing → an `unchanged` run whose pane says
     "No model call was recorded for this run."
   - Reload the deep link `…/events/sources/source/<id>/run/<runId>` directly — it
     must resolve from the URL alone.
4. `query_db`: `SELECT correlation_id, source_name, length(prompt), length(output)
   FROM claude_cli_calls WHERE source_name = 'events.url-extract' ORDER BY created_at
   DESC LIMIT 5;` — `correlation_id` must equal the `event_source_runs.id` of the
   corresponding run.
5. Debug → Claude CLI Calls still renders identically after the `CallRow` refactor.
6. `./singularity test plugins/infra/plugins/claude-cli` — add a unit test for the
   `not-retained` rule (capacity + horizon), the one piece of real logic that is
   easy to get subtly wrong.

## Follow-ups (not in this change)

- The other five `runClaudePrint` callers can adopt `correlationId` (a task's
  generated title, a conversation's category, a turn summary) and get the same
  "why did it say that" affordance for free. Deliberately out of scope here.
- `apps/workflows/steps/llm-prompt` keeps its own prompt/output copy on the
  execution-step record. That is not redundant with this — the step's prompt is
  *authored config*, not a recorded side effect — but it is worth revisiting once
  correlation exists.
