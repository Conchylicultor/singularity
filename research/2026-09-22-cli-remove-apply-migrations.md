# Remove `./singularity apply-migrations`

## Context

`./singularity apply-migrations` crashes whenever it has anything to log. The
migration code logs through a channel that saves to a file in a per-instance
folder. Finding that folder means asking the process which app instance it is,
and a command-line process has no answer, so the command dies on its first log
line. The crash started with `92d4d7ee9` (2026-09-15), which removed the
environment variable that command-line processes used to inherit by accident.

The command is not needed:

- It was added in `75c0b0a7d` (2026-06-29) so that `mise run setup` could apply
  the schema to the base database on a fresh clone.
- `1a7bfdf45` (2026-09-20) took it out of `mise.toml`. Now the cluster creates
  the base database when it starts, and the first backend to boot applies the
  schema to it.
- Every database gets its schema from the backend when it starts. Nothing in the
  repo calls the command, and its own doc says reaching for it means the boot
  path is being worked around.

Decision (user, 2026-09-22): delete the command; don't fix it.

With the command gone, no command-line process reaches a durable log channel.
The sweep traced all ~25 `defineLogSink` channels. The only other candidate is
`./singularity check`'s `migration-applies-clean`, and it returns before logging
anything, because a CLI loads no plugins and so sees no views. So the log-channel
change ("log lines go to the terminal when the process doesn't know its
instance") is not needed for this fix. A future command-line path that reaches
one would still crash, but on its first line, visibly. That is the loud failure
the repo prefers to a silent one.

1. Delete `plugins/framework/plugins/cli/plugins/apply-migrations/` (CLAUDE.md,
   `cli/`, `package.json`, its `node_modules`).
2. Drop its path from `EXEMPT_PATHS` in
   `plugins/database/plugins/connection/lint/no-raw-pg-connection.test.ts`.
3. Fix the comment in `plugins/database/plugins/migrations/drizzle.config.ts:26`
   so it no longer names the command.
4. Hand-written doc: remove the `apply-migrations` row from the command table in
   `plugins/framework/plugins/cli/CLAUDE.md:59`.
5. Regenerated by `./singularity build` (do not hand-edit):
   `cli/core/cli.generated.ts`, the autogen block of `cli/CLAUDE.md`,
   `docs/plugins-*.md`, and the `bun.lock` workspace entry.

Leave `sidequests/clean-install/steps.sh` as is. Its harness rule is that a
recorded step is never edited. Step 15 is already `EXPECT_FAIL=1`, and its
`createdb` half now fails anyway, because the database already exists.
